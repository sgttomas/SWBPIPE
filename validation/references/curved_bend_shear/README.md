# Curved-bend transverse shear: independent reference (candidate)

Independent expectations for the proposed `timoshenko_annulus_energy_curved_v2`
curved-bend shear term (RT-K1, RT-A1), designed in
[DEL-04-01 Work, curved-bend-transverse-shear.md](../../../execution/PKG-04/DEL-04-01/Work/curved-bend-transverse-shear.md).
Every input is invented, no value comes from a vendor or a project, and nothing
here has been accepted. The generator uses only the Python standard library. It
imports, reads and runs no SWBPIPE product code. The curved-bend kernel
regressions consume its values through a mechanical Rust-constant translation.

## Files

| File | Role |
|---|---|
| `generators/curved_bend_shear_reference.py` | the generator: decimal arithmetic at 70 digits with its own π (Machin), sin/cos (Taylor with halving) and atan; Gauss–Legendre rules (40 nodes, Newton on the Legendre recurrence); the arc built through an explicit centre; section actions from free bodies; the closed forms |
| `element_cases.json` | the invented inputs: one section, one uniform load, five stiffness cases and fourteen angle-sweep cases |
| `expected.json` | the expectations: 34 significant digits, decimal strings |
| `generators/emit_rust.py` | mechanical translation of the JSON oracle into Rust test constants; no mechanics or product-code reads |
| `kernel_cases.rs` | generated constants consumed by `curved_bend/src/transverse_shear_tests.rs` |
| `SHA256SUMS` | hashes of the other files above (`shasum -a 256 -c SHA256SUMS` in this directory) |

Regenerate with `python3 -I generators/curved_bend_shear_reference.py`, run from
this directory. Add `--check` to compare the regenerated bytes with the files
instead of writing them. The run takes a few seconds. It refuses to write if two
methods disagree by more than 1e-28. Translate the JSON to the Rust test
constants with `python3 -I generators/emit_rust.py`; its `--check` verifies
that translation without rerunning the independent integration.

## Source

The formulation is EDF Code_Aster, *Éléments "exacts" de poutres (droites et
courbes)*, key R3.08.01, revision 13337, dated 9 July 2015, §8 "Poutre courbe",
pp. 45–52. It was read from the mirror
<https://ericca.uqtr.ca/fr12.4/man_r/r3/r3.08.01.pdf>, a 67-page PDF with
SHA-256 `57a9fa3f43bc3d665211b9eb11c446bc0bafb52b02f2cd3ecefc432a1482ebc7`.
The shear-coefficient definition is R3.08.03, revision 10726, dated 25 March
2013, §2.1.3, p. 10, eqs. [4]–[5], from the same mirror (`r3.08.03.pdf`, a
35-page PDF with SHA-256
`9fb4e49b2251c9169a3c98f148e606915e38ba4bb735e6d8c4719a2b90a147f5`). Both are
published under the GNU FDL. Neither PDF is kept in Git. The design note gives
the translation, the axis map and the printed typographical errors, which are
not used.

What is taken from the source: the end flexibility is
C = R ∫₀^φ Jᵀ diag(1/ES, 1/(k₁SG), 1/(k₂SG), 1/GC, 1/EI₁, 1/EI₂) J dθ, where J
transports end actions by equilibrium alone. The shear terms are V²/(kSG), with
k defined by shear energy. The pipe flexibility coefficients divide only the
bending inertias (p. 52). What is not taken: the source's printed closed forms
and any of its shear-coefficient values. Here k₁S = k₂S = A_s is an input
(`shear_area`). SWBPIPE's κ_E, which would supply it, is inherited unchanged
from `frame_kernel::shear` and is not re-derived here.

## What the expectations cover

Conventions: local rows x (radial outward at node i), y (tangent at node i
toward j), z = x × y. Global DOF order [ux, uy, uz, rx, ry, rz] at node i, then
node j. The flexibility is node j's with node i clamped. Loads are equivalent
nodal loads p, and true end forces are K d − p.

- **Stiffness cases.** `Q1` is a quarter arc, φ = π/2 exactly. `Q1K` is Q1 with
  k_in = 2.5 and k_out = 1.75. `S1` is a skew arc of about 1.72 rad. `S1T` is S1
  translated exactly. `S1P` is S1 under a cyclic axis permutation. Each case
  gives the local end flexibility with shear (`_v2`) and without
  (`_euler_bernoulli`), the closed-form shear block, both global 12×12
  stiffnesses, the free-tip deflection under the uniform load, and both
  consistent load vectors.
- **Sweep cases.** The chord lies along x, with R = 1. They run from φ ≈ 2e-8 to
  π − 6.3e-4, on both sides of the product's series switch s = 1/2 (φ = π/3),
  plus a straight-limit family (chord 1, R = 50 to 5e7). Each gives φ, the
  stable quantities φ − SC and φ² − S², the dimensionless shear block
  ΔF·GA_s/R and the shear-only uniform-load translation δ·GA_s/R² per unit
  local w.
- **Independent checks**, recorded per case in `checks` and `invariance`:
  - closed form against quadrature, for the shear block and the shear
    uniform-load deflection;
  - shear contributes no tip rotation under the uniform load;
  - Betti reciprocity, by double quadrature over interior displacement fields,
    for the total deflection and the shear part;
  - equilibrium transport, where K_ii from integrating the other end equals
    H K_g Hᵀ;
  - annihilation of the rigid motions;
  - the pointwise force split N² + V_r² + V_b² = |F|², which shows that no
    action is counted twice;
  - exact translation and permutation invariance;
  - the k_in/k_out separation, where the shear block is unchanged and
    F_v2 − F_EB equals the shear block.

  The stiffness-case residuals are at most 2.5e-67 relative. The sweep
  cases' closed-form-against-quadrature residuals are at most 4.1e-54, the
  largest at φ ≈ 2e-8. The k-separation residual is formed from the 34-digit
  outputs and is 7.4e-34.
- **Straight limit.** As φ → 0 at a fixed arc length L, the relative deviations
  of ΔF_xx and δ_xx from the straight Timoshenko values L/GA_s and wL²/(2GA_s)
  are −φ²/3 and −φ²/6, and ΔF_yy/L → φ²/3.

## Limits

These are element-level expectations for the kernel and the certificate tests.
There are no product requests: the option is not admitted by any schema yet.
They do not establish the accuracy of a curved-beam shear energy that uses the
straight-annulus κ_E, of stresses, or of modal behaviour. Binary64 comparison
tolerances are the consumer's choice.
