## The two readouts

Both solve the same model exactly. They differ only in the member leaves.

**Annular readout: the engine, unchanged.** `kd5t_engine.Reference` with its
own element, which is SHEAR_REFERENCE's Timoshenko or Euler–Bernoulli frame
member. κ_E is formed exactly in its cancellation-free form from the authored
OD, nominal wall and ν. The D-5 bases use t_r = fl(fl(t − c_m) − c_a), the
fixed binary64 order. A, I, J = 2I and Z = I/r_o of each basis are exact, and
G = E/(2(1+ν)) is exact. Stiffness and the shear area use the nominal wall.
The generator asserts that its unmutated annular leaves equal the engine's
element bit for bit.

**Admitted readout: added by the generator.** The engine is not edited. A
subclass replaces each member's leaves before the engine's own assembly,
solve and recovery run:
- prepared A, I, J and Z per basis: each the correctly rounded binary64 of the
  exact annulus value. The generator refuses a value within working precision
  of a binary64 midpoint;
- κ̂ in U8 §3.1's fixed binary64 order, with no FMA, from the leaves
  r_o = D/2 and r_i = fl(D/2 − t). It is asserted equal to the engine's
  `kappa_energy` evaluated on binary64;
- Â_s,prep = RN(κ̂·Â_nominal) and Ĝ = RN64(E/RN64(2·RN64(1+ν)));
- EA, EI, GJ and K_s are the exact products of binary64 leaves. φ is
  12EI/(K_s L²) at the exact member length.

On stress rows the admitted readout uses Â and Ĵ. For bending it uses the
represented interval hull(Ẑ, Î/r_o). Its bending rows and circular maxima are
written as that interval's two endpoints (`lower`, `upper`), so a judge
compares against the whole interval and cannot report a false breach. The
interval is written even where it is degenerate (r_o a power of two).

Model inputs are taken as the exact values of their binary64 numbers. The
working precision is 110 decimal digits, the engine's default. π comes from the
engine (Machin). The engine is rerun at 150 digits by setting its module
precision and recomputing its π; its source is not changed.

## Rows

Every row is per case and per readout. Units are SI: m, rad, N, N·m and Pa.

| Group | Key | Content |
|---|---|---|
| `nodal` | node, then `ux uy uz rx ry rz` | global displacements and rotations; Timoshenko rotations are section rotations |
| `member_end_force` | member, `end_i`/`end_j`, then `Fx Fy Fz Mx My Mz` | node-on-element end actions, f = K d, in the member's local frame |
| `section_action` | member, station, then `N Vy Vz T My Mz` | the j-side (+x face) section action at `end_i`, `quarter_1`, `midspan`, `quarter_3` and `end_j`, by statics from the i-end action |
| `stress` | member, station, basis, then `axial bending_y bending_z torsion` | N/A_b, M_y/Z_b, M_z/Z_b and T·r_o/J_b on `nominal_section` and `reduced_section` |
| `circular_maximum` | member, basis | max over the two ends of \|N\|/A_b + hypot(M_y, M_z)/Z_b. With nodal loads only, N is constant and ‖M‖ is convex along the member, so the maximum is at an end |
| `support_reaction` | support, then `Fx Fy Fz Mx My Mz` | support-on-pipe, in global components. Rigid restraints carry Σf − P on restrained DOFs. A spring's reaction is −k·u on its DOF; other components are exact zeros |

The local frame is x along the chord, y the `y_reference` projected normal to
x, and z = x × y. The bending planes follow the engine: v = u_y with θ = r_z,
and v = u_z with θ = −r_y.

Per case, `derived` records for each member: L; κ_E and κ̂ (with hex); exact
and prepared A_s; G and Ĝ; φ and φ − 2 for each readout (the value it would
have where the document is Euler–Bernoulli); the φ used; t_r; both bases'
exact A, I, J and Z and the prepared leaves (with hex); the admitted Z hull;
and the governing end of each maximum.

## Value format and exact zeros

Every value is `[decimal with 40 significant digits, binary64]`. The binary64
is a JSON number written in shortest round-trip form. It is the correctly
rounded value of the exact quantity, and the precision recheck confirms it.

A value within working precision of a binary64 midpoint is taken as an exact
tie and rounded half to even, as the exact value is. Such ties are real:
statically determinate rows are sums of binary64 inputs, as in the source
twins' 0.0006 + 0.5·0.002. The rational re-solve compares every rational
value's binary64 with `Fraction`'s correctly rounded conversion, so it checks
this rule independently. Adding the rule changed no frozen value of the
judged set.

**Exact zeros**, written `["0", 0.0]`, follow t4_u4b's two rules:
- **Known exactly.** A value computed as exactly zero. Examples are the
  out-of-plane components of planar designs and the components a spring does
  not act on.
- **Residue snap.** Any other value below 1e-60 in SI units is an arithmetic
  residue of the 110-digit working precision, and it is written as `"0"`.
  Snapping happens before any comparison, so residues never reach a
  discriminator or a gap.

The generator asserts both sides of the snap:
- no written nonzero value is below 1e-30;
- at 150 digits every snapped residue is below 1e-80. The largest is 4.5e-94
  at 110 digits and 5.1e-134 at 150 digits.

Wherever the rational re-solve reaches a snapped value, that value is exactly
zero. In the four `PHI2-EXACT` Timoshenko documents, the annular near-end
bending rows are exact zeros because φ = 2 exactly. The admitted rows there
are nonzero.

## Source-control twins (`o4_source_twins.py`)

Section 5 asks for Timoshenko and nonzero-allowance re-authorings, in memory,
of J2's twelve source requests and of RF's PIN-OFF-345 r1e-08 and r1e-12
cases. The first freeze could not source their inputs independently, and the
refuting TASK recorded that gap as its one MINOR finding. A later steer allowed
the input-only files named under "Independence", and this section closes the
gap.

**Re-authoring.**
- Each source load case is mapped into this unit's request-agnostic document
  form. The map converts units exactly, to SI, and refuses any conversion that
  is not exactly a binary64 number. It takes base E and ν, and requires an
  authored `shear_modulus` to equal E/(2(1+ν)) exactly, because both readouts
  derive G from E and ν.
- A load/reference-state group is in scope only when it resolves to plain nodal
  loads:
  - explicit base properties;
  - unchanged-reference thermal states;
  - no boundary motion;
  - a reference configuration with `fit: none`;
  - factors that keep each magnitude exactly a binary64 number.

  It then becomes its factored nodal loads.
- The RF census requests (model 0.3.0, contract without a shear model,
  sections without allowances) are re-authored, as the census does, to an
  explicit shear model and explicit mill tolerance and allowance. Despite its
  name, RF-SKEW-T-PIN-OFF-345 is one (3,4,0) member: translations are pinned at
  both ends, a soft RX spring sits at N0 (0.00864 and 8.64e-7 N·m/rad), and the
  two moments act at N1. This unit's invented `RFLIKE` tee designs read "T" as
  a tee and stay in the judged set as a separate design.
- For each in-scope load case there are eight documents:

## Discriminators

Each mutant is formed in each applicable readout. Stiffness mutants are full
re-solves; stress mutants are post-processing. Every row is then compared with
that readout's correct row.

The table's "How it is formed" column gives the annular form, which uses exact
quantities. In the admitted readout each stiffness mutant is formed from the
prepared binary64 leaves, with Ĝ, E and every other leaf unchanged:
- `phi_with_metal_area`: K_s = Ĝ·Â, with Â the prepared nominal area.
- `kappa_on_reduced_section`: κ̂_r in U8 §3.1's fixed binary64 order from
  r_i = fl(D/2 − t_r), then A_s = RN(κ̂_r·Â_r).
- `stiffness_on_t_minus_cm`: correctly rounded A, I and J of the annulus on the
  wall fl(t − c_m). κ̂ comes from fl(D/2 − fl(t − c_m)), then A_s = RN(κ̂·Â′).
- `euler_bernoulli_member_in_timoshenko_document`: the same leaves, with φ = 0
  on the target member.
- `kappa_cowper`: Cowper's κ evaluated in binary64, as the left-to-right
  expression 6(1+ν)(1+m²)²/((7+6ν)(1+m²)² + (20+12ν)m²), from m̂ = fl(r_i/r_o).
  Then A_s = RN(κ_C·Â).
- `kappa_five_sixths`: κ = RN(5/6), then A_s = RN(κ·Â).

The stress mutants copy the admitted readout's own nominal rows and intervals.
`annular_lane_reuses_kappa_hat` is formed in the annular readout only.

No zero scales are supplied. Exact-zero rows are not given a relative
tolerance; a product judge holds them to its absolute bounds.

**Separation.** The separation of a row is |wrong − correct| / (1e-9·|correct|),
REQ-001's relative_limit. For an admitted interval it is measured from the
nearest endpoint. A row is listed only when its separation is at least 1e3.
For each (case, mutant, readout), up to three listed rows are kept, the most
separated first. Each record also counts:
- rows moved by at least 1e3 tolerances, in total and per row group
  (`moved_1e3_by_group`);
- rows moved by less;
- exact-zero rows moved. These are counted, not listed: a relative tolerance on
  zero is zero.

A row within 1e-50 tolerances of the correct value counts as unmoved. Each
listed row's separation of at least 1e3 is asserted, and every mutant is
asserted discriminable in at least one case on every readout it applies to.

`annular_lane_reuses_kappa_hat` changes κ by about 1e-16 relative, so it can move
a row by 1e3 tolerances only where the row is that sensitive to φ:
- **Discriminable** only in the four `PROP-PHI2-NEAR` Timoshenko documents. There
  the near-end bending is M(2 − φ)/(4 + φ) with |φ − 2| between 1.4e-16 and 3.3e-11.
- **Exact-zero rows moved** in the four `PHI2-EXACT` Timoshenko documents: it
  moves the annular near-end bending rows, which are exact zeros (8 rows each).
- **Below 1e3 tolerances** everywhere else, including every source twin.

This is round 1's open MINOR finding. The rows this mutant moves are exactly
the rows where the two readouts already disagree ("Readout gaps"). There no
relative-verified publication can match both readouts, so the product can kill
the mutant only through absolute bounds. Product-side it is covered by the
kernel test `annular_timoshenko_lane_uses_the_exact_kappa`.

## Readout gaps (a finding for the binder)

Per case, `readout_gap` counts rows where the admitted readout lies more than
one tolerance (1e-9·|annular|) from the annular readout.
- **Gaps above one tolerance** occur in 8 documents, all Timoshenko `PROP-PHI2`
  documents, on their near-end bending rows (end actions, station actions and
  stresses at `end_i`):
  - `PHI2-EXACT`: the annular rows are exact zeros and the admitted rows are
    nonzero (8 rows);
  - `PHI2-NEAR-X`: up to 6.2e9 tolerances;
  - `PHI2-NEAR-345-OFF`: up to 5.7e3 tolerances.
- **Elsewhere** the worst gap is 2.8e-6 tolerances.

A published row cannot lie within 1e-9 of both readouts where they differ by
more than 2e-9 relative. So REQ-001's relative bound cannot hold for both
readouts on those rows, and a sound W1-E publication must use its absolute or
fail-closed path there. Whether it does is for the product test to judge.

## Binary64 proxy

`binary64_proxy` is a plain binary64 formation: coefficients rounded
separately, a binary64 transformation, assembly and partial-pivot elimination.
It is judged against the exact annular readout. The figure is the worst error
on displacement, rotation and end-action rows, each scaled by the largest value
of its group.

The proxy shows which designs defeat an ordinary binary64 solve:
- 51 of the 54 `sensitive_design` documents exceed 1e-9. The other three are
  the Timoshenko `SHORT-MEMBER` twins: at φ ≈ 2.9e5 their short member is
  shear-flexible, so the proxy reaches only 1.8e-12;
- no other document exceeds 1e-9.

Where a plain binary64 elimination meets an exactly zero pivot, the proxy is
recorded as "singular in binary64". This occurs only in the source twins.

The proxy is not the product's Passed/Sensitive gate. That gate is product-side
and is not computed here.

## Euler–Bernoulli zero-allowance harness-validation twins

Every design has an Euler–Bernoulli document with zero mill tolerance and zero
allowance (33 documents, variant `zero`, theory `eb`). These are the documents
today's product already publishes: ordinary exact recovery, the source route
with coincident bases, and W1-E as admitted before O4. Section 5's acceptance
requires that they reproduce today's numbers.

The binding test runs them first, against both readouts. Zero judged breaches
on them validates the harness: the builder, unit conversion, row mapping and
interval judging. The source twins add 13 such documents, the
Euler–Bernoulli zero-allowance re-authorings of the J2 and RF load cases. A breach there is a harness or reference fault, not an O4
fault. On these documents the reduced rows equal the nominal rows (asserted).

## Binding

The product binds these request-agnostic cases; nothing here names product
rows, kinds, ids or request fields beyond the case documents.

1. **Requests.** A builder in a later product test authors one request per case
   from `cases.json` `document`, in the then-current model format:
   - the `pressure_contract` {3.0.0, `exact_pressure_v3`, `shear_model`};
   - nodes, and straight pipe segments with explicit length-valued
     `outside_diameter`, `wall_thickness`, `mill_tolerance` and
     `corrosion_allowance` and the `y_reference`;
   - one homogeneous-isotropic E/ν material;
   - supports: `rigid` becomes an anchor restraining exactly the listed DOFs,
     and `spring` a grounded linear spring on its DOF;
   - one load case with the nodal concentrated forces and moments and explicitly
     empty `pressure_regions`.

   `engine_request()` shows the 0.5.0-shaped input the reference engine reads.
   It is not a product request.
2. **Rows.** The product test maps the agnostic keys to its row kinds,
   locations and bases, and converts its units exactly: mm to m, MPa to Pa.
3. **Judging.** This unit supplies the exact rows of both readouts. Section 5's
   acceptance states how they are used. An admitted interval row is met within
   1e-9 of any point of the interval. The source route's declared-problem
   containment needs the later oracle unit. Both solver modes and both typed
   and captured entries are product-side repetitions of the same documents.
4. **Source twins.** A twin document is the in-memory re-authoring of its
   pinned source request's load case (`source` names the file, its SHA-256 and
   the load case). The binding test re-authors J2's and RF's requests the same
   way and judges them against these rows.
5. **Stability.** Oracle values never move to match a product. Request SHA-256
   values may be added once requests exist; that changes only the bindings and
   the files' hashes.

## Not covered

- Member loads, self-weight, thermal or explicit strains, prescribed motions,
  load/reference-state groups, combinations and multi-case documents. These are
  outside W1-E's D1 nodal-load domain, or not needed for the readouts.
- Pressure regions and the D-5 pressure bore. Neither route admits a present
  pressure region.
- Arcs, connectors and nonlinear supports, which are declined by name on both
  routes.
- U4b's derived rows (σ⁺/σ⁻, τ_v,max) and DEF-E's sharper allowance.
- The source route's declared-problem oracle (a later unit), the premise census
  and the product's Passed/Sensitive classification.

## Reproduce and change

```
./run.sh                                               # check: about 2 s on 12 workers
python3 -I -B generators/o4_reference.py --workers 1   # the same check in one process
python3 -I -B generators/o4_reference.py --write       # intentional re-freeze only
python3 -I -B generators/o4_source_twins.py            # check the source twins alone
python3 -I -B generators/o4_source_twins.py --write    # intentional re-freeze of the twins only
```

Check mode fails on any byte difference, on any unexpected or missing file, on
an engine or source input whose SHA-256 differs, and on any failed
cross-check.

**Re-freeze rules.**
- No value changes to match a product output. A disagreement goes back to this
  unit's owner and its refuter.
- Changing a readout definition, the D-5 order, the fixed κ order, the hull or
  the judged set is a re-freeze with a recorded reason and a new refutation.
- Changing a row convention (key, unit, sign, frame or station) re-derives the
  rows. Physical values stay unless the convention changes their meaning.
