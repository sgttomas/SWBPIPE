# After-worker family table

Generated by `tools/after_worker_family/family_table.py` from the web source; do not edit by hand. `README.md` beside it says what the check is for and how to regenerate it. Each source is found by text: a declaration by its name, a passage by its start and end.

What the check establishes, and what it does not:

- The first three columns are checked against the source. Each row's source is found by its text in the named file. An imported row's name is exported there and the judge imports it from that module; the check does not compare the arguments the judge passes with those the web passes. A restated row's name is not imported, the judge's text names it (a textual reference, comments included, not proof that the judge applies it), its export claim holds, and its cited text, with each passage listed after "with", has its recorded digest. A run-inside row's name is called by the imported function it names.
- The fourth column, "equal, or the difference", is the exact route performance lane's reading of those sources. No check establishes it; the import checks passing do not make it so.
- That reading rests on one premise: the judge takes the session model from the standing request's model text, so each equality that involves the session model holds for a session model equal to the parse of its own JSON text (one with no undefined, non-finite or non-JSON member).
