The 2026-09-05 workspace implementation exposed an ordering and test-quality gap. Recommended next steps:

1. For structural UI changes, inventory all affected existing browser workflows during planning. Before accepting the final source freeze, run the complete source-browser and production-dist preflight through current visible paths. Adapt intentional navigation changes while preserving the same model operations, explicit units/payloads, validation errors, application/undo, save/reopen and solve/result boundaries.
2. Prefer ordinary pointer and keyboard actions when proving user reachability. A synthetic DOM click or forced action must not stand in for actionability evidence. Preserve diagnostic selection and drawer scrolling/Close checks, including the declared minimum window target. Keep independent review of the complete resulting test/product diff.
3. Define a diagnostic trace approach explicitly for iterative runs: retain bounded errors, screenshots, command/results and source bindings; collect detailed traces when needed for diagnosis without repeatedly packaging very large archives. Agent 0 authorized the iterative preflight trace-off setting after preserving the failure. The final registered clean DEC-025 command and configuration remain unchanged and must still pass in full. Any future canonical trace-policy change belongs to its owning workflow process.

Acceptance for a future workflow improvement: the same complete browser workflows pass without skips, weakened engineering assertions, inflated tolerances or synthetic interaction bypasses; ordinary diagnostic selection, linked result units, required-input scrolling and Close work at the declared size; final source review binds the exact passing candidate; the clean committed final gate remains independently required. A proposed method update should preserve failed-attempt evidence and clearly distinguish exploratory preflight from final acceptance.
