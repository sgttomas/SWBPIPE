## 2. Locked design frame (DO NOT relitigate)

1. **Workspace IA inversion.** The model canvas is the hero. ONE navigation = a ribbon (`Model → Loads → Analyze → Results → Rules → Report`) that doubles as the workflow spine (replaces the three competing navs). Structured data entry splits into two purpose-built surfaces with a clear contract: a **Layout grid** (CAEPIPE-style tabular bulk editing) and an **Inspector** (deep single-entity detail incl. user factors, provenance, dual units). A command/selection bar gives the authoring feedback loop (AutoCAD-style). Canvas reads as real 3D (axis triad, view cube, reference grid, scale, selection handles, distinct support/load glyphs). All telemetry/compliance is demoted to a status-bar `Audit & boundaries` control + an `issues` diagnostics home. Dual-unit display (`DEC-018`). Code-neutral entry done right = user value + provenance + inline `required` flag, NOT machine strings.
2. **The embedded agent acts through the SAME structured-operation seam the human uses, as PROPOSALS.** It can only propose; the human judges (accept/edit/reject) via diff preview; only then does it apply through the validated seam, audit, and stay reversible. Three tool classes: **Read** (model/results/diagnostics — unrestricted), **Query** (domain research — read-only), **Propose** (mutations — never direct).
3. **Bounded autonomy = the harness tool-permission / `humanGate` model (tunable), not bespoke machinery.** Two layers: (a) tunable permissions — each `propose_*` verb is `auto` or `ask` (default: reversible/cosmetic auto; engineering-significant — section/support/component/load/factor — ask); (b) fixed invariants — code-neutral, no certification/compliance/reliance claims (`FR-AGENT-005`), the status vocabulary, local-first. The invariants are maintained by **agent instructions + tests/linters** (and seam validation), NOT hard structural locks — except that the dangerous verbs simply don't exist (`approve_for_project`, `mark_rule_passed`).
4. **Human judgment is the telos, not overhead.** It is invoked through interaction in three shapes the UI must carry: a **proposal** (approve/edit/reject), a **framed choice** ("two support strategies, here's the trade-off"), an **interpretation flag** ("borderline rule result — your call; I won't decide"). Instruction+interaction is primary; permissions are the floor; tests/linters are verification.
5. **The agent surface COMPOSES the harness's agent-orchestration UI — does not reinvent it.** The v3 "Agent" panel splits into: the **live-loop** (consume the new `harness:event` stream — tool calls, subagent fan-out, permissions, cost) reused from the harness, plus the **piping proposal/judge surface** (canvas+grid diff, accept/edit/reject, provenance, boundary banner) which is ours.

UI mockups v1→v3 were rendered via `mcp__visualize__show_widget` (ephemeral — not files). v3 = workspace with the agent as collaborator, one proposal (add support S-5 at N-110) flowing through the human-judge gate with research evidence + boundary banner. Rebuild mockups as needed; the frame above is what matters.
