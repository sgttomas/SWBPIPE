1The territory map — one repo, three governed spaces

Everything lives in one git repository (/Users/ryan/ai-env/projects/chirality, single main branch). Inside it there are three governed spaces. "Convergence" means the piping app will consume the app-dev agent harness as versioned packages — it does not merge the codebases.

2The governance stack — how authority is layered

Each layer answers a different question and is corrected by the layer above it. The golden rule: when a lower layer and a higher authority disagree, the lower layer is corrected — never the authority. Humans rule at every gate marked ⬤.

Takeaway: if you ever want to know "is X really true / approved?", read DOWN from the top. _COORDINATION.md is the single source of truth for which milestone is current; docs/PLAN.md is just a readable summary that routes to the authorities.

3The decision workflow — agents propose, the human rules, CHANGE publishes

Nothing becomes policy because an agent says so. Every governance change runs this loop. This is why your role (the human project authority) sits at the only ruling step.

Takeaway: a draft packet (D-xx) is a question for you; a DEC-xxx record is your answer, published. An agent that edited a governed doc and committed it before you ruled would be skipping step 2 — that's the line the workflow protects.

5The convergence gate chain — three gates to land the agent harness

This is the heart of "convergence." To put a live embedded agent into the piping app, three gates must clear in order. Two downstream prerequisites are already done, and a whole lane of prep can run in parallel right now.

Takeaway & one correction to the common shorthand: people say "clear the R4 hold (the sparse residual)" — but the sparse residual is already repaired. Gate 1 is now purely your exit ruling on the refreshed packet (ideally after two small readiness items), not more build work. Gates run 1 → 2 → 3; the DEC-042 lane needs none of them.

6How the embedded agent will behave — propose-only, through the human's own seam

When R7 lands, the agent is deliberately constrained. It uses the same structured-operation seam the human uses, and it can only propose — it never writes to the model directly. This is what keeps the professional boundary intact.

Takeaway: the agent is a fast assistant that drafts schema-valid proposals; you remain the engineer-of-record. It can read and research freely, but every change to the model passes through your accept/reject diff — same as the decision workflow in §3, applied to the modeling surface.
