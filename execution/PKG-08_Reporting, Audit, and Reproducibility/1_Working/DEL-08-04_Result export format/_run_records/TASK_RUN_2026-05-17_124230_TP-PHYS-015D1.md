## Fit Findings

The existing DEL-08-04 result export contract can represent the main TP-PHYS-015 canonical solve-result envelope categories without public runtime expansion:

- Envelope traceability: `ResultEnvelope` carries `model_ref`, `run_ref`, `solver_version`, `unit_system_ref`, `load_basis_refs`, `provenance`, `reproducibility`, `analysis_status`, and `professional_boundary`.
- Displacements and rotations: `QuantityResult` can carry node displacement and rotation values with explicit `object_ref`, `basis_ref`, finite `magnitude`, `unit`, `dimension`, and `provenance`. For schema compatibility, displacement values should use dimension `length` and rotation values should use dimension `angle`.
- Reactions: `ResultFamily` includes `reaction`; reaction evidence can be represented as unit-aware `QuantityResult` records with force dimension.
- Station resultants: station shear and bending can be represented as `force` and `moment` `QuantityResult` records with `station_ref` and `ResultMetadata` such as component `shear_force_y` or `bending_moment_z`, coordinate system `element_local`, location `midspan`, and a nonempty sign convention.
- Diagnostics: `Diagnostic` carries explicit code, class, severity, source, affected object, message, remediation, and provenance. The Rust crate emits blocking export diagnostics instead of silent defaults for missing IDs, references, units, dimensions, provenance, reproducibility, human-review-required status, rule-pack metadata, and professional-boundary violations.
- Source and provenance evidence: `Reference`, `Provenance`, `Checksum`, and `Reproducibility` can carry source locations, model/run hashes, audit-manifest refs, and redistribution/review status without copying private or protected payloads.

## Gaps Recorded

No schema or runtime behavior was changed. The following fit gaps remain for a future explicitly approved schema/result-export tranche if TP-PHYS-015 parent review wants stronger evidence:

- Load-vector evidence has no first-class result-set type or metadata vocabulary for assembled nodal vector entries, global DOF names, or nodal equivalent force/moment components. It can be approximated as `force`/`moment` quantities, but that would rely on generic metadata rather than a dedicated load-vector boundary.
- `ResultSet.set_type` has `mechanics` and `stress_recovery`, but no explicit `station_resultants` or `load_vector_evidence` values. Station resultants still fit as mechanics quantities with `station_ref`.
- `QuantityResult` does not include an explicit multi-hop source-link field. The current schema can carry `object_ref`, `basis_ref`, `station_ref`, `provenance`, and envelope-level model/load/run references, but it cannot directly encode a full physical source -> analytical model -> adapter DTO -> solver input -> result evidence chain per result value.
- `schemas/results.schema.yaml` includes optional per-value diagnostics, but `core/reporting/result_export::QuantityResult` does not. Crate-side validation produces envelope-level diagnostics only.
- The Rust crate validates in-memory `ResultEnvelope` values and deterministic ordering, but it does not mirror the root schema wrapper fields `deliverable_id`, `package_id`, `scope_item`, `objectives`, `export_format_status`, or schema-required `downstream_use`.
- The TP-PHYS-014 mechanics benchmark labels expected displacement and rotation dimensions as `displacement` and `rotation`; the existing result export schema accepts `length` and `angle` instead. This is a mapping requirement or schema vocabulary gap, not a blocker for read-only fit.
