# D-65 ruling — CI-produced surface-4 evidence accepted with binding

## Verbatim owner ruling

<!-- BEGIN OWNER RULING VERBATIM D-65 -->
Ruling — CI-produced surface-4 evidence accepted, with binding.
DEC-025 five-surface sweeps may satisfy surface 4 with evidence produced by the .github/workflows/piping-desktop-e2e.yml workflow, as follows.

	1.	The sweep summary must bind, for the CI path: the workflow path; the Actions run ID and run attempt; the run’s exact head SHA; and the run conclusion. The run’s head SHA must equal the sweep’s commit_hash; a run on any other commit — parent, child, or nearby — is not surface-4 evidence for that sweep. The run must have concluded success with the registered e2e specs executed across both registered viewport projects.
	2.	execution_capability: ci is added as a recorded value alongside the existing host. Host execution remains a permitted alternative with unchanged semantics. Neither path is deprecated by this ruling.
	3.	CI checkout of the exact SHA satisfies the clean-tree intent of working_tree_dirty=false for the CI path by construction; the summary still records the field.
	4.	A run that fails for infrastructure reasons (runner outage, queue, cache-cold timeout) permits a rerun of the same workflow on the same SHA; the summary binds the run that succeeded. A run that fails on a spec is a genuine surface-4 failure and blocks the sweep as today.
	5.	Scope: this acceptance covers the registered desktop e2e surface as it exists. Any future surface that asserts macOS-specific behavior of the packaged desktop application may be designated host-mandatory when it is registered; this ruling does not pre-authorize CI substitution for such surfaces.
	6.	Out of scope: exploratory or agent-as-user testing findings are not sweep evidence under any surface. That evidence lane, when it exists, will be established by its own instrument, not by amendment to DEC-025.

Follow-up engineering opened, not executed here: one bounded node to teach the sweep tooling (run_evidence_sweep.py and its summary schema/validator, as applicable) to record and validate the CI binding in point 1, including rejecting a summary whose bound head SHA differs from commit_hash. Register it as a Remaining item on the owning deliverable; it is selectable from the next iteration under the standing development-pressure direction. Until it lands, sweeps continue on the host path.

Sequencing: this recording tranche is one iteration on its own — one branch, one commit, one receipt, one PR under the usual token, no merge. Do not begin the sweep-tooling node in this tranche.
