## Proposed workspace and interaction target

Use one compact command band with visible **Build, Supports, Properties, Loads, Edit, Select and View, Review** groups, preserving the accepted catalog identities and selection-dependent explanations. Pin commonly used commands; retain search as an alternative access path. All normative commands must be discoverable in this one organization, with bounded capability descriptions. Node renumbering, snubbers and cold spring remain ROADMAP help entries, never active tools or implied obligations.

Keep the model tree on the left, spatial canvas central, and one contextual task/properties rail on the right. A lower dock handles analysis tables, pending changes and diagnostics. Provide Model/Results workspace emphasis, not separate model stores. Show project/units, active tool, selection type/identity and pending-change count persistently; place verbose source/hash details behind a clearly labelled evidence disclosure. Use neutral panels, consistent spacing/type/icon treatment, strong selected/hover/focus states and purposeful warning colors. The prototype should compare two density treatments on the same task rather than a collection of cosmetic themes.

Default interaction is Select/Navigate. Build mode makes Route or Place Component explicit; its rail shows required inputs in task order, with optional detail disclosed. Route shows From, endpoint mode, plane, applicable axis, coordinates/units, pipe properties and provenance; spatial feedback mirrors these exact fields. An endpoint pick identifies an existing node; a plane pick proposes coordinates only. No “near enough” silent connection. Typed coordinates remain authoritative, with no rounding into a different authored point. Cancel discards the draft, never reverses an applied operation.

Component mode distinguishes placing a symbol at explicit incident pipes from inserting finite geometry into a run. Show candidate orientation and selected pipe roles; require explicit material/section/stiffness/source data. Future drag handles edit a draft vector, angle or insertion location and feed the same typed operation preview. They must not directly stretch a connected engineering network until attachment/reconnection semantics exist. Selection expands later to type filters and multiple entities; the first slice retains current `EntityRef` identity and exact current picking behavior.

Industry conventions inform this proposal, not new engineering authority: Autodesk Plant 3D's current documentation describes continuation grips, explicit routing planes, object snaps and direct distance entry; these support discoverable continuation and precise coordinate feedback [Autodesk, Compass and Snaps](https://help.autodesk.com/cloudhelp/2026/ENU/Plant3D-UserGuide/files/GUID-80606EFD-7D5C-43CD-8F90-DBFEF07EE34D.htm). SST describes synchronized text/graphics selection, contextual commands and load-case visual review; these support linked result/tree/canvas selection [SST, CAEPIPE Graphics](https://www.sstusa.com/caepipe-graphics.php). No layout/assets are copied, no vendor performance claims adopted, and no CAEPIPE execution is proposed.

## Human action to contract mapping

| Human action | Existing typed intent/query | Validation, history and busy contract |
|---|---|---|
| Pick/search entity; orbit/pan/zoom; choose view | `EntityRef` selection or transient camera state | No mutation/checkpoint; preserve camera across selection; distinguish drag from authoring click |
| Enter coordinates or place new route endpoint | `create_node` plus `connect_pipe_run` atomic batch; existing endpoint uses connect | Preserve 4 CSS-pixel same-pointer gate, strict three-axis unit conversion, generation invalidation and unavailable-WebGL fallback to typed entry |
| Add → review → Apply → continue | Frozen draft plus `validateModelOperation`/`validateOperationBatch`, then corresponding apply service | Exact members, hash/revision, deterministic before/after, explicit Apply; one successful checkpoint; continue only after matching own commit |
| Edit selected property; place support/component | `set_field`, `update_support`, `insert_component_symbol` through current forms | Engine validates types, units, references, before-state, provenance; leave missing values visible; avoid auto-apply on blur |
| Split/copy/rotate/mirror | `split_pipe_run`/`transform_pipe_run` batch | Display exact source set and scope blockers; no partial publication; preserve local-frame and attached-entity restrictions |
| Change units | Existing display-quantity query | Stored/entered values unchanged; unsupported conversion retains entered value plus reason |
| Undo/redo; reopen history | Existing session checkpoint handlers; historical review queries | Restore current session checkpoints only; reopened proposed metadata has acceptance UNKNOWN and requires requeue/fresh validation |
| Run/cancel solve; select result | Existing solve job service; explicit result/entity selection | Preserve job/model/input bindings, stale/late suppression and cancelling state; current vs historical vs blocked/unavailable visible; historical rows cannot drive current overlays/rule checks |

Retain the shared Rust engine via native/Wasm services and PR 785 semantics. Busy state gates conflicting application/history actions while keeping readable diagnostics and the existing cancellation/withdrawal path. Never let palette navigation reset work, stale responses resurrect withdrawn drafts, or validation itself count as acceptance. Present results by producer quantity/kind/dimension, coordinate frame, location, units and run basis; IDs are identifiers, not semantic parsers. Do not invent adapters that flatten intentionally distinct library/CLI/native serialization. Rotation rows and energy residuals need their own truthful display; absent rule ratios remain unavailable. Overlay scale is explicit, and deformation stays illustrative rather than authored geometry.

## Concrete next tranche and first implementation slice

**Next design tranche deliverables:** (1) editable vector wireframes for 1024×768, 1280×800 and 1440×920 covering Select, Route, Component, Properties, Pending Changes and Results; (2) one small offline interactive prototype of select → route → review → apply → continue → property edit → result invalidation, with conspicuous simulated-engine status and injected busy/blocked/stale/cancelled/historical states; (3) three task walkthroughs and an annotated state/intent map; (4) updated backfill/ownership table and frozen review record. HELPS_HUMANS owns design, WORKING_ITEMS owns feasibility/future production planning, and fresh read-only review checks semantic mapping. Prototype execution and product work require the next adopted scope; neither occurred here.

The three walkthroughs are: **A**, create and continue a mixed-unit route, then cancel a draft and undo/redo the accepted route; **B**, select a pipe/node, place a component or support with explicit pipe roles/DOFs, inspect a blocked attached transform, and correct a property; **C**, inspect current results, change a model property, observe invalidation, then reopen historical results without current overlays. Walkthrough B may simulate pending contracts, visibly labelled.

Completion means an independent reviewer can execute all three walkthroughs, find every normative command, inspect every mutation's exact typed intent and failure state, and identify every simulated/backfill control. Freeze the prototype/wireframe revision, record findings and incorporate them before parent presents the design for owner preference/alignment. This is an actual inspectable design package, not another promise to design later. It need not wait for complete pressure/connectors or results implementation; uncertain contracts appear explicitly simulated or unavailable.

**First production slice after design review:** persistent grouped Build/Select/Edit access, one focused Route rail over the existing node/route draft and review functions, preserved tree/inspector access, truthful command availability, and no new operation kinds. Deliver one end-to-end blank-model authoring journey using explicit invented material/section/provenance. Acceptance cases: new endpoint creates exactly one atomic route checkpoint; existing endpoint does not duplicate a node; own-commit continuation is correct; plane/axis/mixed units work; drag/cancel/stale conversion/model replacement apply nothing; stale/busy Apply and undo remain blocked; undo/redo invalidate current results correctly; save/reopen restores model while historical acceptance stays unknown. Verify pointer and keyboard journeys at all three dimensions, including reached Apply/Cancel, bounded scrolling and preserved canvas interaction. Existing H4/DEC-025 and fresh full-diff review apply to production execution; later packaged witness proves only its exercised behavior.

The native minimum is 1024×768 (`src-tauri/tauri.conf.json`); `styles.css:3264` calls this an initial checked layout target, not usability acceptance. Larger existing browser targets are 1280×800 and 1440×920. Preserve labelled controls, visible focus, keyboard tree→properties→diagnostics navigation, focus return on dismissal, and typed alternatives to spatial input. Exact new shortcuts and density treatment are prototype choices for review.
