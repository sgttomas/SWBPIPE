# Work-graph and change workflow update

Owner-authorized Root tranche `ROOT-WORKFLOW-WAVE2A-EXECUTION-20260926` retires the bundled `software-bounded-implementation` workflow without a successor package. Implementation is commissioned as a bounded TASK assignment whose brief carries the objective, accepted basis, write fence, exclusions, acceptance criteria and authorized checks. `construct-local-work-graph` now states those implementation-node requirements, including that an executor never silently changes scope, public contracts, migrations, shared ownership or acceptance criteria, and never weakens or removes adopted tests, oracles or tolerances. The legacy-method ledger lists the retired name as historical only, and `workflows/README.md` records its last revision. `project-setup` loads its software-activation guidance from its own resources.

`construct-local-work-graph` also:
- names loops that adopt the method (currently App, Piping and PEC) instead of only App/Piping;
- keeps MEMORY and closeout writes subject to project write fences;
- replaces superseded graph state in place, with one designated current graph ref;
- carries open deferrals and follow-ups when adopting a predecessor graph;
- marks a node awaiting a human decision as BLOCKED, naming the decision.

The `change` workflow drops an approval gate and an undefined "closeout gate", permits fetching during state collection, and states that agents act within existing authorization. The Root loop now names the `chirality-change` skill for Git closeout. The agent manual v3 and its HTML edition are updated accordingly.

Historical graphs, briefs and run records are not rewritten. This loop decides its own adoption; this source tranche grants no release.
