## 2. Four-Lens Analysis

- **Ontology.** The proposed object is an internal candidate execution brief
  for a code-binding slice inside two existing deliverables. The producer
  path, the DEL-08-04 envelope vocabulary, its validators, and the
  solve outputs all already exist as distinct governed entities; the tranche
  connects them without collapsing producer, validator, evidence, or
  acceptance into one thing. No new project entity, scope node, or authority
  class is created.
- **Epistemology.** The gap is warranted by the live tree, not by derivative
  tasking: no non-test `ResultEnvelope` constructor exists; the
  `assumptions`/`limitations` vectors have no consumer; the payload
  validator has no producer. The brief's acceptance predicates are
  checkable (validators, tests, byte-diffs, containment JSON), and its
  claims stay inside that warrant — no run-quality, review, or reliance
  claim is made.
- **Praxeology.** The selected shape gives the executor a bounded,
  executable, fail-closed path: one integration owner, serialized; additive
  library surfaces; blocking diagnostics on production failure; explicit
  stop conditions; witness byte-stability preventing silent downstream
  drift; deliverable-state writes only on success. Rerun triggers and
  failure dispositions are recorded.
- **Axiology.** The binding advances the adopted PRD purpose (governed,
  reproducible analysis-run evidence) and evidence-over-plausibility while
  preserving prohibition integrity (no thresholds, no lifecycle act, no
  external action), truthful attribution (owner standing approval vs agent
  classification kept distinct), reversibility (local commits on a wave
  branch), and the DEC-081 claim fence.

All four lenses support the same bounded outcome: author and advance this
tranche brief now, through the governed verify→execute→verify chain.

## 3. Materially Important Rejected Alternatives

1. **Expose the envelope through the runner CLI in the same tranche
   (stdout/`export-results`).** Rejected: changes the committed witness
   surfaces and immediately re-stales the just-refreshed DEL-09-04
   validation manual (R13); `export-results` is DEL-10-05's recorded open
   scope, not PKG-04's; the library-level binding discharges both PKG-04
   Remaining items without either collateral.
2. **Put the producer in `core/reporting/result_export` (DEL-08-04
   crate).** Rejected: writes another package's deliverable surface and
   inverts the dependency (the envelope crate would depend on the solver
   crates); the headless crate already owns the analysis-run producer path
   and the payload-validation contract, so the binding belongs there.
3. **Bind through the Python DEL-14-02 preview builder
   (`core/analysis_runs`).** Rejected: that surface is fixture-driven
   preview tooling for DEL-14-02; the Remaining items name the governed
   producer path whose live implementation is the Rust runner; a
   Python-side binding would not create the solver-to-envelope integration
   the items describe.
4. **Extend `MechanicsEnvelope` with new serialized solver-context
   fields.** Rejected: `MechanicsEnvelope` serializes into the runner CLI
   stdout, so any always-present field breaks witness byte-stability;
   additive public accessors plus envelope-document diagnostics carry the
   same information without changing committed bytes.
5. **Split into two tranches (one per deliverable).** Rejected: both items
   bind the same producer surface; two writers on one surface would force
   serialization anyway and double the verification overhead; the campaign
   plan records the combined tranche with one integration owner.
6. **Defer despite no defect.** Rejected: the campaign queue is
   owner-directed for this lane, all upstream evidence is present, and no
   risk/evidence record supports deferral; deferral has no positive support
   in the accepted record.
7. **(v3) Park the tranche on the executor BLOCK.** Rejected: the blocking
   condition is a predicate-design defect in the v1/v2 brief, not a missing
   prerequisite — the named Remaining items (straight-pipe element
   results/diagnostics; nonlinear solver metadata) are fully representable
   in the accepted vocabulary; only auxiliary review-echo/count rows are
   not, and truthful per-row disclosure covers them.
8. **(v3) Extend the DEL-08-04 vocabulary in this tranche.** Rejected:
   `core/reporting/result_export/**` and `schemas/results.schema.yaml` are
   another package's governed surfaces, expressly fence-external; a
   dimension-vocabulary extension (stiffness/energy/count) is new shared
   schema content that belongs to a separate lawful selection with its own
   review, reported to HELP_HUMAN.
9. **(v3) Coerce out-of-vocabulary rows into nearest existing dimensions
   (e.g. `N*m` work residual as `moment`).** Rejected: assigns semantically
   false classifications, contradicting the accepted D-01 unit taxonomy and
   the evidence-over-plausibility value; a disclosed boundary is truthful,
   a coerced row is not.
