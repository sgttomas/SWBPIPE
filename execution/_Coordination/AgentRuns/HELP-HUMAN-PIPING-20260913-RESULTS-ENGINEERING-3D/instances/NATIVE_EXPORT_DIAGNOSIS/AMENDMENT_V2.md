# Additive static backcheck — Downloads guard and isolated bootstrap

Original diagnosis and proposed expectations remain frozen. This amendment is a derivative recommendation under the parent's follow-up, not source adoption or runtime evidence. No source/runtime/build/test effects occurred.

**Disposition:** agree with all three parent corrections. Default Wry destination handling cannot be accepted without a Downloads guard. Prefer the resolved-context bootstrap below; it is smaller than modifying both base configuration and isolated overlay.

1. **Bootstrap after overlay resolution, before app startup.** Locked Tauri `src/lib.rs:411` exposes `Context::config_mut()`. Build the context using `generate_context!()`; on macOS only, find the resolved existing main window and set its `create` field false **before** passing the context to `.run(context)`. In the user setup hook, create that same resolved WindowConfig once with `WebviewWindowBuilder::from_config` and attach `on_download`. Do not recreate or edit identifier/store/title/dimensions/URL fields. Tauri `src/app.rs:2516–2523` creates automatic windows before the user setup hook, so suppressing automatic creation inside setup is too late. Non-macOS code keeps its original automatic creation and no new callback. Fail explicitly if the expected main configuration is absent or ambiguous; do not silently create a differently configured fallback.

   This handles `instances/NATIVE_VERIFY/tauri-isolated-overlay.json`, whose replacement `app.windows` array omits `create`. No overlay change is then required. If the writer instead uses the original base-config approach, the isolated overlay needs an immutable successor with `create:false`, and both merged production and isolated configuration must be checked before build. Never overwrite the frozen original overlay. Minimal preferred production fence becomes the native shell source plus a bounded helper/tests; `tauri.conf.json` can remain unchanged.

2. **Use the platform resolver, never the Wry fallback.** Locked Tauri `src/path/desktop.rs:119–120` returns `dirs::download_dir().ok_or(Error::UnknownPath)` through `app.path().download_dir()`, requiring no dependency addition. Resolve/check Downloads at each Requested event. Return false if resolution fails, the returned path is relative, unavailable, or not a directory. Do not create it, substitute current_dir, choose another directory or rewrite destination. This closes the concrete Wry fallback at `wry-0.55.1/src/wkwebview/download.rs:60–64` and applies the existing no-repository-default-write boundary (project `docs/PLAN.md:244–247`; parent identifies F-PIP-1).

3. **Constrain destination to an immediate child of that directory.** Require absolute destination, one normal filename, no parent/current-directory components, and canonical destination parent equal to canonical resolved Downloads. Compare paths/components, not string prefixes; sibling `Downloads-other`, nested subdirectories and traversal are not accepted. A non-existent destination is normal, so canonicalize the existing parent, not the final file. Reject any existing final filesystem entry using `symlink_metadata`, including dangling symlinks, and reject unexpected metadata errors. This preserves Wry's preselected collision suffix and prevents following a static final symlink or overwriting a raced-in file at the preflight check. Do not introduce repository scanning or a new configured filesystem root.

   Canonical parent equality prevents a symlinked parent escape relative to the resolved Downloads root. It does not prove Downloads itself lies outside every repository if a user has deliberately redirected it. If F-PIP-1 is interpreted to forbid that additional case, use the existing report-save convention of rejecting a symlink at the platform-returned root rather than claiming the basic canonical-parent check proves more; parent should record that local destination rule explicitly. Neither option is a wire/schema/privacy-classification change. Static checks remain best effort: WebKit owns the later open/write, so this callback cannot prove resistance to malicious concurrent filesystem replacement. No new atomic/durability guarantee is justified.

4. **Exact small route predicate.** On macOS Requested events, allow only the existing exact producer prefix `data:application/json;charset=utf-8,` with a nonempty body and the existing basename family `openpipestress-preview-results-<token>.json`, with optional Wry collision suffix ` (<N>)` immediately before `.json`. Token is the existing safeFileToken output for the generated run reference: lowercase ASCII alphanumeric groups separated by single hyphens; N is a positive decimal counter without a leading zero. Accept ordinary names and ` (1).json`, ` (12).json`, etc. Reject other prefixes/media types, network/blob/file URLs, other export filename families, separators, traversal, uppercase/other extensions, malformed suffixes and empty generated run tokens. Match using a small parser; no regex crate is needed. The filename and URL predicate scopes this transport hook only; it does not attest payload truth or replace existing frontend screening. Do not decode/re-encode the body, parse/rebuild canonical JSON, insert metadata or compare against a regenerated document. Return the original destination and original download unchanged. Treat Finished separately; its return value does not authorize a new download, and macOS `path=None` is not file evidence.

**Freeze these additional checks before effects:**

- Production resolved config and isolated overlay each produce one main window; identifier, title, size, minimum size, URL and app-data identity remain those of their own input configuration. Overlay omission of `create` must not create a duplicate. Non-macOS resolved `create` behavior remains unchanged.
- Accept exact canonical prefix + base filename and positive numbered suffixes within a real existing Downloads directory. Native witness must confirm WebKit's actual suggested filename agrees with this predicate; do not silently broaden matching after an unexplained failure.
- Resolver error, missing directory, file-as-Downloads, relative root and unresolvable parent each deny without any directory creation or write. A candidate in a repository/current working directory is denied when Downloads is unavailable; no fallback is accepted.
- Deny sibling prefix, outside absolute path, nested directory, `..`/`.` path, empty filename, path separator, existing file/directory/symlink/dangling symlink, and filesystem-check errors. If adopting the explicit no-symlink-root convention, freeze its positive/negative tests too. No invented adversarial containment claim.
- Deny unrelated URL/MIME/filename and malformed collision suffix; preserve all original policy/own-intent/Current/Historical tests unchanged. The route predicate must not independently create download authority.
- A real first native download and a repeated download both produce actual exact canonical bytes; the second uses Wry's collision suffix and leaves the first unchanged. No success inferred from callback, raw href capture or path prediction. Re-run the original native responsiveness/lifecycle and source/schema/hash/row expectations.
