## Smallest justified repair candidate

Wire the existing canonical HTML download into the **locked Tauri download hook**, preserving the approved frontend control and payload path. Tauri `src/webview/webview_window.rs:384` exposes `on_download`; its [versioned public documentation](https://docs.rs/tauri/2.11.1/tauri/webview/struct.WebviewWindowBuilder.html#method.on_download) confirms that returning false prevents a requested download.

Because the existing window is automatic, create that same window once from its existing configuration in `setup`, with automatic creation disabled, attaching a bounded macOS download hook. Preserve label, title, sizes, URL, isolation overrides, menus and other configured attributes. Register the existing local canonical result route; do not broadly enable network or unrelated export routes as incidental work. A transport-level predicate can use the existing exact data MIME/prefix and safe download filename family, but the implementer must prove WebKit preserves that filename in the actual app before relying on it. Such a predicate is routing, not replacement semantic/privacy authorization. It must not add document metadata requirements or invent schema fields. Preserve non-macOS behavior.

Wry `src/wkwebview/download.rs:60–105` already chooses the user's Downloads folder (falling back to current directory when unavailable), avoids an existing filename by appending a counter, and delegates the original download to WebKit. Allowing that native path requires no new IPC command, model operation, serialization, JSON format, or project persistence. The current HTML-download UI does not promise a native save picker. No blocking native dialog belongs inside the synchronous download callback. Wry completion on macOS supplies `path=None` (`download.rs:113–118`); a successful callback is not a captured file and must not be reported as such.

Initial production scope: `apps/desktop/src-tauri/src/lib.rs`, `apps/desktop/src-tauri/tauri.conf.json`, a tightly bounded local routing helper/test if useful, and selected native acceptance evidence. No dependency update is justified. No frontend change is intrinsically needed.
