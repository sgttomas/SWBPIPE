Control availability vocabulary: `LIVE_LEGACY`, `DESIGN_BACKFILL`, `SUPPORTED_INCOMPLETE` (edit/save allowed, solve blocked), `SUPPORTED_READY`, `UNSUPPORTED_COMPOSITION`. These are handoff design terms, not new canonical model state enums. Busy/stale/cancelled/blocked editing remains a distinct state axis. Root/UI owner maps them onto accepted capability labels rather than silently creating a new registry.

In the offline prototype, every solver/pressure/joint value is clearly simulated. Mutation intents must show the same explicit fields/units/roles as the eventual shared typed operation; preview cannot infer E/nu, triads, closures, load transfer or engineering values. Exact model-hash equivalence is demonstrated later through shared Rust source-bound production witnesses, not established by the prototype.

Versioned edits preserve original model/attachment bytes until controlled apply/save. Reauthoring legacy to exact changes model hash and invalidates Current results; reopening authentic untouched old attachment yields Historical. Display reclassification never rewrites old witness/dimension/serializer hashes. Connector with legacy pressure has no E/nu dependency; pressure-joint composition is explicitly unsupported until its separate load-path proof.

No user choice is needed to continue navigation/routing design or normal contract preparation. Retained public activation/migration consequences, personal visual alignment and specific formal dependency rulings remain scoped owning acts. All model edits route through existing typed Rust operations/batches, schema/constraint preview, controlled apply and audit/history; no new operation kind is implied here. If a proposed field is not yet accepted by that route, show a backfill block rather than fall back to direct JSON mutation.
