## Executive summary

1. The owner's verdict holds: the UI works end to end (every persona task is reachable, undoable and auditable) but it presents like an instrumented test harness, not an engineering tool.
2. All three June-2026 defects survive in mutated form: the "wall of evidence strings" is now a `key=value` dialect (391 template-literal fact lines, about 2,200 machine-term hits in renderable text, a nine-field hash proof in the status bar); the "three competing navigations" are now five (toolbar, menu, Toolkit palette, viewport command bar, dock tabs) plus two drawers; the "postage stamp" canvas gets 20-26% of a 1024×768 window whenever any dock section is open and never more than ~47% closed.
3. New defects since June: a ten-section dock that mounts 51 panels (14 in Exports alone, 7 Evidence panels rendered twice), two different support-creation forms, a queue/validate/apply gate applied to single-field edits, pending work counted in five places, solve failures that never reach the screen, an Issues badge that shows 5 on an empty model, 10-px viewport chrome, three generations of CSS in one file.
4. The 3D viewport is a schematic: fixed-radius pipes, one cone glyph for every support family, unit-length load arrows, truncated `UI-…` labels, hard-coded camera presets with no fit-to-model, a static scale bar, and a deformation overlay that mixes load cases at a normalized offset.
5. Feedback is located when it comes from diagnostics (row click selects the entity) but not when it matters most: no inline numeric validation, project-scoped missing-data blockers, and a solve `error_message` that only exists inside a JSON packet.
6. Visual language has no system: 131-151 color literals, no tokens, orange doing five jobs, green (plus a shield icon) marking readiness in a product that must never look like it approves anything.
7. Governance content that must exist (maturity line, acceptance boundary, analysis status, missing-data classes, units, provenance, historical designation, agent standing) fits in a footer, a status pill and per-result labels; today it is stamped on every panel as negative-claim litany, the very pattern the claims registry lints against.
8. What is genuinely good and must survive any redesign: atomic batch apply with rollback and stale-basis detection, 25-deep undo checkpoints that invalidate results, one selection identity across tree/viewport/inspector/results/diagnostics, entered-units preservation with explicit unavailability, Current vs Historical run separation, a gated searchable palette, and disciplined generation gates behind async work.
9. The people who built this optimized for what they could see and test (829 test ids, 36 JSON download links, machine-readable status everywhere); the target users (PRD §9) see none of that as value and all of it as noise.
10. Ranked owner reaction, best inference: (1) machine text everywhere, (2) the model is not the hero, (3) every edit is a bureaucratic transaction, (4) no single spine, (5) web-admin styling rather than CAD/CAE visual language.

## 1. Information architecture

**How many systems.** Five command/navigation systems coexist, plus two drawers and the status pills:

1. `WorkspaceToolbar` — six stops (Model, Loads, Analyze, Results, Rules, Report) and five edit actions (Select, Toolkit, Undo, Redo, Review) — `WorkspaceToolbar.tsx:23-38`.
2. Menu bar — native on Tauri, in-DOM otherwise (`App.tsx:2038`); 31 commands across File / Edit / View / Insert / Analyze; the View menu lists all ten dock sections plus Issues, Audit & Boundaries and "Close Panel (show viewport)" (`App.tsx:345-367`, `2660-2805`).
3. Toolkit palette — a modal catalog of 31 capabilities in seven groups, routed to surfaces by `focusTestId` / `elementId` (`ToolkitPalette.tsx`, `capabilityCatalog.ts`).
4. Viewport command bar — Node / Pipe / Support / Component / Load, where Support and Load are themselves redirects to the inspector and the Loads section (`PipeViewport.tsx:1220-1282`; `App.tsx:1856-1866`).
5. Dock tabs inside the Review section — Review changes / Geometry / Supports / Self weight / Agent / Details (`App.tsx:2237`), reachable from the toolbar, the View menu and the Toolkit (`App.tsx:1868-1891`).
