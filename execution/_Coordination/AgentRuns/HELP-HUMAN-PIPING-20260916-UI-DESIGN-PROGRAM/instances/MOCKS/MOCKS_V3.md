## 1. The count, the two retirements and the two additions

Eighteen frames: the sixteen design frames of the second pass regenerated, and two new ones.

- **Retired: `d71_item1_status_bar_light` and `d71_item2_results_caption_light`**, with their screenshots. Reason: they were decision aids, each drawing one option of a question put to the owner (where the maturity sentence would live; whether the results header carried a caption with the acceptance sentence). Both questions are ruled: both sentences are removed from the product (rulings 2 and 3 as superseded by the addenda; rows 51, 52, 77), so neither option exists to be drawn, and a frame that draws a removed string would fail this pass's own search. `tools/build.mjs` removes any frame file and screenshot that is not in the frame list, so the inventory, the index and the shots agree (`report.json` `_summary.inventory.agree`).
- **Added: `s7_both_light_historical`.** The brief made it optional; it is added because the historical band, its popover with the run's recorded statuses, the note card in the legend's place, the neutral canvas and the rail caption are five pieces of ruling 6 that no other frame can show, and the Stale frame alone would leave a reader to infer them.
- **Added: `s4_both_light_slideover`.** The brief's list of states to draw names Q-15, and DS §8 asks for "a new frame, the agent column reopened with the inspector as the slide-over". It could not be folded into an existing state-4 frame without losing the docked frame or the collapsing-column frame, which are both still the rule.

## 2. Common to every frame

**Name and removed sentences (rulings 1, 2, 3; rows 50, 51, 52).** The wordmark and the caption bar read SWBPIPE alone. No frame carries the maturity sentence or the acceptance sentence, in any variant, visible or in an attribute. The status bar's information control at its right end is titled "About SWBPIPE…" and hangs no popover: a click opens About directly (`report.json` `pointer.aboutOpensDirectly`).

**Labels (ruling 4; rows 53, 54).** Every status and evidence chip is generated by one function from the `labels` table of `tokens.json` 1.2: the authority domain, a middle dot, the label, with the raw token as the tooltip ("Solver · Mechanics solved", "Rule pack · User-rule checked", "Human · Human review required", "Evidence · Internally verified"). The render lint reads every chip back and compares it with the table (`lint.labelChips`, `lint.labelProblems`: none). Chip policy: none on a complete unsolved model (state 4), none after a failed run (state 6; Q-21, row 73), two on a Current run, the rule-pack chip and Human on the Review page (spec §7.1), none under a Stale or Historical run, and the evidence chip only for a Current run whose record carries evidence.

**Run standing (ruling 6; row 57; correction row 88).** Current, Stale and Historical are drawn as three different things: state 7 (Current), `s8_table_light` (Stale) and `s7_both_light_historical` (Historical). The measured facts for each are in `report.json` under `standing`.

**The pointer rule (rows 61 to 66).** The toolbar carries Undo and Redo after the save state, and the Inspector toggle beside the Agent toggle after Issues; the Inspector toggle is disabled with its reason in Table and Model views and latched while the Both-view inspector is open. The HUD is one group of ten with Fit first. Table footers carry the clear-selection control and the selection group of five icon buttons whenever a row is selected, and the edit chip with Commit and Cancel while a cell is edited. Expansions open from a chevron in the owning cell and close from the block's chevron or its close control. "Add row", "Add case", "Add restraint…" and "Add load…" lines end their tables. Close controls: the docked and slide-over inspector, the pinned probe, toasts, the issues drawer, joined rows and editors; collapse controls: the table drawer and the agent column; Send beside the agent's field. Buttons in bands and editors read their names with keys in their tooltips (row 66). `report.json` `pointer` records each of these per frame, and the lint fails a frame whose visible text asks the reader to press a key.

**Agent cards (ruling 8; row 59).** Every agent-authored card carries exactly one of the five class words from `agentCardClasses` (Check, Open issue, Draft, Proposal, Evidence summary); the engineer's own card is a Note. The lint compares each card's class chip with the token list (`lint.kindProblems`: none).

**Checked (ruling 7, option A; row 58).** Control "Check" (or "Clear check" / "Check again"), mark "Checked", filter "Unchecked rows"; never in a status, a results row or the report.

**Export naming (ruling 9; row 60).** No frame draws the model export command or its sheet, in this pass or the earlier ones, so the ruling applies to the frames by absence; the one place the generator named another vendor's product, a source comment in `tools/model.mjs`, now says "the model batch file grammar".

**Tokens and stylesheet.** `frames/tokens.css` is regenerated from `tokens.json` 1.2: 99 colour tokens (1.1 had 98; the addition is `canvas.edgeAlt`), plus the HUD, toast and run-log layout values. `frames/mocks.css` is revised: the third-pass block replaces the second pass's (label chips, icon-button variants, the selection group, the edit chip, expansion chevrons, add-row lines, the boundary line, the historical popover, the legend's note card, the probe's close control, the compass's button row, the toast, the run log, the Send row, the receipt line, the iteration and Kind menus), and the decision-aid rules are removed.

**The edge line (R-6; row 83).** `tools/canvas.mjs` computes, for every result-coloured element and each theme, the fill the scale gives it and picks whichever of `canvas.edge` and `canvas.edgeAlt` has the higher contrast on that fill. Because one static SVG serves both themes through the theme switch, the choice is carried as a class and a custom property (`--mock-edge-ee`, `-aa`, `-ea`, `-ae`, defined per theme in `mocks.css`); that is the mocks' mechanism, not a token (G-16). Measured in `report.json` `edges`: in light the pale steps keep the dark edge and the darker teal steps take the light line; in dark the brighter steps take the dark line.

## 10. How the frames were composed and checked

As in the earlier passes the frames are generated (`tools/build.mjs` from `model.mjs`, `canvas.mjs`, `ui.mjs`, `frames.mjs`), self-contained, and rendered by `tools/render.mjs` with Playwright, whose location is given at run time (`--playwright-from <dir>` or the `PLAYWRIGHT_FROM` environment variable) and is written into no file. This pass added to the render lint: the retired-string search over every shipped file, the label-chip and card-class comparisons with the tokens, the pointer facts, the standing facts, the HUD, toast, run-log and canvas-minimum measurements, the edge-line record, and a check that no child of a bar runs past the bar's right edge, which is the check that found the results header's and would have found the Review header's overflow.

Standard claim fence applies (F-PIP-2; claims taxonomy per DEC-081).
