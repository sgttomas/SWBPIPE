## 4. Uncertainties

1. **Frames.** Fourteen of the fifteen frames were read through their generator sources and `MOCKS_V1.md`, with text extractions of the index and four frames; the frames were not each rendered and inspected. A drawn moment that exists only in a rendered frame and not in the generator's strings or the mock record could be missing from the state tables.
2. **RESEARCH-B's line numbers.** B cites `App.tsx` menu lines (2691–2756) that no longer match the source; the menus are now at line 3344. The map cites the current lines; other B citations were re-derived from the source rather than trusted.
3. **Evidence labels.** No emission of `INTERNALLY_VERIFIED` or `PROVER_CORRELATED` was found in `apps/desktop/src`; the search did not extend to `core/`. G-13 may be smaller than stated if a core component emits them.
4. **Reference fields through `set_field`.** Whether the applier's `set_field` accepts `start_node_ref` and `material_ref` as targets was not established; rows 47 and 59 cite it with a composed fallback (delete and reconnect; create and assign).
5. **Stress type.** No stress-category field was found on `LoadCase` or `Combination`; G-05 assumes none exists. If a category lives in the rule-pack binding, G-05 shrinks.
6. **Per-case progress.** `SolveJobEvent` carries a message per event; whether events are emitted per load case was not established (row 188).
7. **The chip after a failed run.** The mocks show "Model incomplete" after a non-convergence; the specification shows whatever the run record emits (§5.4 item 5) and asks the engine what a stopped run emits (§11 Q11). If the record emits nothing, the mock's chip is a departure from the specification.
8. **M-04's trigger.** The trigger and wording source were aligned to RESEARCH-C §4 (design-authoring records, handoff packages, export metadata, external-prover references) rather than to the earlier phrasing used during design (export metadata, hanger selection records, handoff data). Hanger selection records are treated as design-authoring records.
9. **Design system V1.1.** Not read; if V1.1 renames a component or token or restates a keyboard binding, the specification still uses V1's names with §11's decisions applied over them.
10. **The export correspondence.** The renderer's element-code table (`CaepipeMbfExportPanel.tsx:450`) was not read for behaviour; §8.3 states the projection as behaviour and puts the correspondence and its loss entry under G-26.
11. **Interpretations where the basis was silent**, made so the specification is complete and offered for ROOT's decision: several row expansions open at once (the frames show one); the insert-between numbering rule (integer midpoint, else the next increment above the highest number); the delete-heal rule (the downstream element re-anchors to the deleted row's From, offsets re-derived so nothing moves); the edit-or-fork default (Edit when the set has one reader, else Fork); the envelope definitions per results table; the hanger candidate filter (hot load within the working range, variation within the row's limit); the deformation factor default (one tenth of the model's extent); the Both-view pane floors and the slide-over fallback at the minimum window; "Engine unavailable" as a Run reason; Draft comments as the agent's route to report text; "Restore as current" for iterations; the M-15 caption placed once in the Loads header band; the probe's readings on the Model and Loads stages.
12. **Element kinds.** Design system V1 §5.1 lists the target file's kinds (slip joint, ball joint, hinge, tie rod, elastic element, beam, cut pipe, jacketed pipe, miter bend) in the Type column; the specification offers only the engine's kinds with a footer line to Scope and limitations and names the rest under G-24 and §11 Q21. This is a deliberate departure from V1 for ROOT to accept or reverse.
13. **Placement of the acceptance sentence.** The specification places M-02 in three homes, one per surface class (results header disclosure, Review page top, the report), following the design system's disclosure homes and decision-packet item 8. The brief's rule "no boundary sentence repeated across product surfaces" is read as one placement per surface class; ROOT should confirm that reading.
14. **Rendering dependencies.** The canvas gaps under G-16 (probe, result colour, legend, deformation controls, label budget, presets, section plane, proposal ghost) may overlap the rendering brief's scope; that brief was not in the basis and the overlap was not reconciled.
15. **Zero imposed displacement.** The tooltip in §3.3 states the target file's zero-as-absent rule from RESEARCH-E; how the engine treats a zero imposed displacement is §11 Q24 and not established.

2. 3. "Every mandatory disclosure has its trigger and wording source": satisfied with file and line for each; the wording of M-03 and M-04 is cited and not reproduced, because the notice text contains words the copy rules forbid in strings this document specifies.
4. No implementation plan, technology choice, code or estimate was written; the gap list is classed (engine, typed interface, host, rendering, interface) so the implementers can estimate from it, and the classes are not estimates.
5. The specification uses the spelling "Analyse" for the menu the product spells "Analyze" (`App.tsx:3403`); a copy decision for ROOT, not a functional difference.
6. The record identifier `contributor_certification` appears once in the specification (§8.1), in code font, as the name of an existing provenance field of the library record; it is an identifier, not a string the specification specifies, and a word-level scan will find it.
