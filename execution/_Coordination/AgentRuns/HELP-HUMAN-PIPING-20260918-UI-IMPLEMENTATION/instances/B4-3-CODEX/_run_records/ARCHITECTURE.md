# Materials editor stability decision

The real delayed-conversion journey retained the input DOM identity, focus and caret through row reorder but lost native text Undo. The isolated Chromium probe reproduced Undo loss by moving the same input node, compared with successful Undo without that move. Restoring focus/selection alone is therefore insufficient for this host behavior.

Deferring reorder until editing ends is a plausible smaller alternative for pure conversion completion. It is not impossible, and resize alone does not require a stable host. It would, however, introduce a new view policy: draft changes immediately invalidate the sort basis, and the current requirement uses stable input order while the projection is unavailable and complete physical ordering when it resolves. Holding a previous sorted order needs distinct deferred-sort wording/semantics. A viable alternative is to reset to stable input order at editor start, label the requested sort deferred, and apply the latest complete projection after Keep/Cancel/Apply. That avoids movement while typing, but changes edit-start/live-sort presentation and needs explicit copy and equivalent filter/pinned-navigation proof. Filtering and retained out-of-filter edits also change displayed membership/pinned placement; deferring only conversion completion does not generally keep the inline input's ancestor stationary through those changes. Virtualization by itself is not proof of DOM movement; the observed failure is movement during reorder, including cases that may cross a virtual window.

Chosen bounded mechanism: Materials opts into one persistent editor host inside the owning EngineeringTable, outside the reordered VirtualList subtree. Rows still follow the current filter/pin and complete-or-unavailable projection policy. Only the editor's visual box changes. Captured row/column/token/generation and existing apply/keep/cancel/blur guards retain semantic ownership. A unique aria-owned input connects the stable DOM editor to its grid cell. Position/clip derives from current anchor, body slot and grid client bounds; it must not intercept chrome or other cells. Initial focus occurs only after measured visible placement with captured focus/surface/selection ownership, and initial selection still runs once per edit token. Hidden/inert surfaces keep retained state without stealing focus. Node retains its existing inline rendering and behavior; shared VirtualList is unchanged.

This adds real obligations rather than claiming free correctness: actual browser input identity/caret/text-Undo, initial character focus, Enter/double-click selection, virtual/filter-threshold/pin transitions, resize, clipping, pointer hitability and hidden-family behavior are targeted checks. Early failures and subsequent proof remain separately bound. Native observation is still required after reviewed freeze. Reversal within the adapter increment is to restore the legacy Materials renderer, preserving model/history/evidence; replacing the stable host with deferred reordering would first need a named view-policy decision and equivalent interaction proof, not a silent timing workaround.
