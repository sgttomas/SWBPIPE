## Rules of the move (all stages)

1. **Byte for byte.** A moved statement keeps its text and the comments that lead it: no rename, no reformat, no reordering inside it, no tidying, no "while I am here". Keep its indentation too: the new hooks are top-level functions, so their bodies sit at two spaces exactly as `AppSession`'s does, and `git diff --color-moved` and the audit tool then see the statement as identical.
2. **No consolidation.** The handlers repeat long runs of setter calls, and the runs differ: for example `handleOpenProject` does not clear `operationOutcomes` or `operationMessage`, while `handleCreateBlankProject` and `adoptNormalizedPersistenceModel` do. Those differences are today's behaviour. Do not factor the runs into shared helpers, do not reorder setter calls, do not "fix" an asymmetry. If one looks like a defect, say so in your return.
3. **No dead-code removal.** `r3JourneyState` is set and never read; `modelPublicationGenerationRef` is written and never read; `restoredSolveJob`, `operationIntentDisplayRef`, `isBlankAuthoringModel` and `countStatus` are never called. They move or stay as the inventories below say. List anything else of the kind that you notice.
4. **All effects in one function, in base order.** The 13 `useEffect` / `useLayoutEffect` statements stay together and keep their relative order: in `AppSession` through stage 2, in `useWorkspaceSession` from stage 3. The state hooks declare no effect. The stale-response guards depend on this order (the layout effect on `[model]` increments `modelRevision` and invalidates the solve gate; the mount effect's closure is the first render's on purpose); none of it is re-derived or "modernized".
5. **All handlers in one function.** Every function declared inside `AppSession` today moves to `useWorkspaceSession` in stage 3, in base order, including the ones that touch a single domain. One closure today, one closure after; a reader follows the solve path or the apply path in one file.
6. **Inside a state hook, keep the base order** of the statements assigned to it. Several read earlier ones (`currentSolvedResult` reads `result`; the two `…BasisRef` bumps read their cells; `orderedSelectionRef` is initialised from `orderedSelection`; the two render-time assignments to `currentSolvedResultRef.current` and `currentInputManifestRef.current` follow their refs).
7. **Same local names.** Each function that needs a cell gets it by destructuring the hook's return into the same local name it has today. That is what lets a handler body and the JSX move without an edit.
8. **Module singletons stay singletons.** `nextUiModelPublicationGeneration` is a module-level `let`; it moves with `commitModel` into the same module and stays a module-level `let`.
9. **`App.tsx` keeps its exports.** `App`, `SolveRunGenerationGate`, `RuleRevisionGenerationGate`, `commitModelAfterSolveInvalidation`, `isSupportedChangedModelPersistenceResponse`, `solveProofStatus` and the type `SolveProofEvidence` are imported from `./App` by tests. Re-export the moved ones from `App.tsx` (`isolatedModules` is on: a type is re-exported with `export type { … } from`).
10. **Imports.** Each new module imports what it uses, types with `import type`. Remove from `App.tsx` the imports it no longer uses. Add no runtime import cycle: nothing under `src/features/workspace/` imports `../../App`.
11. **If a statement cannot move unchanged**, make the smallest edit that compiles, and list it in your return with the reason. The audit tool will show it as CHANGED; an unexplained CHANGED is a defect.
