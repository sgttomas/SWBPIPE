# Slice C2: selection and hover as halos over the element's own colour (G-31)

By the lane manager B-CANVAS (Claude Fable 5.1), 2026-09-19. Children: C2-HALO (product; return `../returns/C2-HALO_RETURN.md`) and C2-PROBE (the probe; `../returns/C2-PROBE_RETURN.md`), both Claude Fable 5.1 by their own statement; both were cut off once by the owner's session limit and resumed by message. The manager ran every timed series and pair count: `../probes/C2/MANAGER_SERIES.md`. Placeholders as in the lane brief.

## What changed

- New `viewportHalo.ts` (with `viewportHalo.test.ts`, 24 tests): a selected element keeps its own colour and edge line and gains a 2 CSS px outline in `canvas.selection` outside its silhouette; an unselected, visible hovered element gains 1 CSS px in `canvas.hover`. Per base geometry and kind of halo: one depth mask of the element's own geometry written at the near plane with colour off, and one shell (edge quads from the geometry's crease and border edges, or a sphere grown along its normals) drawn just behind it with the depth test on, all after the figure. So the halo shows over nearer geometry and never inside a haloed outline. Halo meshes carry only the haloed instances, are created on first need, account to the ownership ledger, and are no pick input. Width is read where the renderer is sized, never per frame.
- `viewportResource.ts`: the selection recolour is removed (`applyInstancedSelection`'s selected branch and the non-instanced material recolour); `setHoverPresentation` is added; the halo follows selection, visibility, theme, layer replacement, resize and disposal. **The renderer's construction is unchanged.** `PipeViewport.tsx`: one effect passes the hovered key.
- `viewportSelectionPresentation.ts` and `viewportSelection.ts` are byte-identical; the first profile's diamond cue keeps drawing; nothing under `e2e/**` changed.
- Tests moved, not weakened: six assertions that pinned the recolour as display now assert the element's own colour (listed one by one in C2-HALO's return).
- The probe (`../tools/orbit_probe.mjs`, README beside it) gains `run --select`, a `hover` subcommand and a `pairs` subcommand, with self-test cases.

## Semantic changes, named

1. A selected element keeps its own colour and edge line and gains an outline. Before: its colour was overwritten with `canvas.selection`.
2. Hover gains a canvas cue (1 px, `canvas.hover`), including hover that arrives from a label. Before: hover showed only as a label. A selected or hidden element shows none.
3. The halo shows through nearer geometry. Before: a recoloured tube inside its node spheres was hidden there.
4. Overlapping haloed elements are outlined as their union: no halo line crosses another haloed element's body.
5. Load arrows and the deformed overlay no longer change colour when their owner is selected, and get no halo (they are not the element, and are not selectable).
6. A hidden selected element has no halo (the first profile's cue already behaved so).

## For the instrument's second profile

The halo spans 0 to 2 CSS px outside the drawn outline (a 10-gon prism, a 12 × 8 sphere: the drawn polygon, not the ideal circle), so only its outer pixel lies in P1 §4.3's band of 1 to 3 px: about one device pixel at ratio 1, part of it antialiased. Halo pixels appear over nearer geometry. A selected neighbour removes band pixels inside its own outline. The diamond cue still draws, so Selection-coloured pixels also appear at the winner's centre and along a selected pipe's axis. The sample files' expected winners are for a nominal camera 5.90 m from the camera the product fits at this canvas size. A hovered entity is not on the diagnostics surface (C2-PROBE's proposal: `hover: { ref, changeSequence }` in `uiDiagnostics.ts`, the shell lane's file).

## Carried forward

- `applySelectionPresentation` still repaints every instance's base colour on every selection change, which the halo makes needless; it costs what it cost before. A candidate for C3, which reworks that path for dimming.
- Hover at 10,000 pipes costs about 4.3 ms of main thread per pointer move **in today's product**, before and after this slice: a pick and a full redraw per move.
- The review's three residual risks (edge width captured once; any torus arc accepted; the orthographic branch untested) stand; the halo reads its width in `resize()`.
- C3's dimming: a dimmed figure needs `transparent` with opacity and sorts before render order 9,000; a dimmed element can be hovered and then gets a full-strength hover halo.
