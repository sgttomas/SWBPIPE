**Arc members** (`curved_bend_macro_element` spans): end force rows (`element_local_*_force|moment` at `end_i`/`end_j`) change `coordinate_system` to `arc_chord_frame` (values and other metadata unchanged). ## 5. `contract_evidence` (closed; exact key sets)

```
{"preview_cases": [<case>, ...],              // one per load case, model order
 "combination_gates": [<gate>, ...]}          // one per model combination, model order
<case> = {"load_case_id", "pipe_stress_extrema", "stress_maximum_coverage",
          "support_attribution", "intensified_measures"}
```

### 5.1 `pipe_stress_extrema`
List of the exact route's 13-field objects: `pipe_id, result_id, station_fraction, span_index, local_fraction, value_lower_pa, value_upper_pa, global_upper_bound_pa, certified_gap_pa, subdivisions, approximation ("piecewise_quadratic_straight_section_statics"), coefficient_basis ("j_side_section_equilibrium_binary64"), enclosure_scope ("supplied_binary64_polynomial_coefficients; solution and coefficient formation error are separate")`. One per maximum row; `result_id` is that row's id.

### 5.2 `stress_maximum_coverage`
`{"complete": bool, "unavailable_pipe_ids": [...], "outside_domain_pipe_ids": [...]}`. Members of a case = the pipes that publish `element_local_axial_force` rows in that case. Each member is in exactly one of: `pipe_stress_extrema`, `unavailable_pipe_ids` (straight, enclosure failed), `outside_domain_pipe_ids` (arc). `complete` ⇔ both lists empty.

### 5.3 `support_attribution`
`{"attributed_support_ids": [...], "withheld": [{"support_id", "reason"}]}`, model support order; every model support appears exactly once. Reasons:
- `SUPPORT_ACTION_ATTRIBUTION_WITHHELD` — the support is residual-determined (rigid or nonlinear) and shares a node-DOF with another residual-determined device (rigid + nonlinear, or nonlinear + nonlinear, across records). Springs and constant effort are law-determined and never cause withholding.
- `CONSTANT_EFFORT_NOT_CONSUMED` — a constant-effort support that the solve does not consume.
Attributed ⇒ exactly the 8 rows of §3 in that case. Withheld ⇒ no support-action rows and no `nonlinear_support_final_reaction` row for it. Nothing is zero-filled.

### 5.4 `intensified_measures`
List of `{"result_id", "component_id", "pipe_id", "location" (end_i|end_j), "factor_role" (bend|branch_header|branch_branch), "sif", "sif_source_reference", "section_modulus_m3", "bending_moment_y_n_m", "bending_moment_z_n_m"}`, one per intensified row. Empty before S2b lands.

### 5.5 `combination_gates`
`{"combination_id", "withheld": bool, "reason": string|null}`. `withheld` only for `basis == "mechanics"`; `reason` is the first holding gate of §7, else null.

## 6. Headlines and summary

- `summary.max_open_formula_stress` = `{value (Pa), unit "Pa", location_ref pipe, result_ref maximum-row id}` = maximum over all cases' maximum rows; null when any case's coverage is incomplete, or no member has a maximum.
- `summary.max_displacement` = `{value (mm), unit "mm", location_ref node, result_ref}` over all cases' `displacement_magnitude` rows (qualified id for non-first cases).
- **Ties** (both headlines): larger value wins; on equal value, the smaller `load_case_id`, then the smaller `location_ref`, wins (byte/code-point order; TS must not use UTF-16 order for non-BMP text). Within a case, the smaller member or node id wins.
- `HIGH_DISPLACEMENT_REVIEW` refs the all-case headline.
- `summary.component_stress_modifier_count` per §4.

## 7. Combinations

Gate for `mechanics` combinations, evaluated in this order; the first that holds withholds **all** that combination's rows, with one diagnostic, and case states are kept:
1. `NONLINEAR_COMBINATION_REQUIRES_SOLVE` — the model has any nonlinear support record;
2. `CONSTANT_EFFORT_COMBINATION_REQUIRES_SOLVE` — a consuming constant-effort support exists and `|Σf − 1| > 64·ε·max(1, Σ|f|)`;
3. `COMBINATION_MODULUS_BASIS_MIXED` — operands have different modulus-basis keys (`None` counts as one key).

Admitted combinations (ungated `mechanics`, every `result_state_subtraction`, every `range_envelope`):
- scalar algebra (or mode selection for ranges) over the table's `combination_policy.linear_state_kinds` only; rows grouped by base id for ordinary rows and by `(kind, entity_ref, metadata.component)` for `support_reaction_component_v2`;
- `displacement_magnitude` and the two support magnitudes are recomputed from the combined components for mechanics and subtraction, and mode-selected for ranges;
- combined support ids `result:combination:{stable(comb)}:support-action:{L(support)}:{support}:{c}`; other ids as today;
- subtraction rows' `sign_convention`: `positive value follows explicit user result-state subtraction (minuend minus subtrahend) of matching source result sign conventions; a signed difference of solved states, not an equilibrium state`;
- never combined: maxima, intensified rows, nonlinear kinds, reviews, records, counts, codes, residuals.

## 9. Reader checks (Rust, Python, TS identical in meaning)

For a `preview-physics-1` source:
1. header per §1; `contract_evidence` key sets per §5 exactly; finite numbers;
2. every row's kind has a signature in the table; no retired kind; no retired code;
3. **completeness (F-1):** every diagnostic `affected_refs` entry that begins with `result:`, and each non-null summary `result_ref`, resolves to an emitted row id. Other references (entity ids, field tokens, decision ids such as `DEC-046`, `hanger`, user source-reference strings) are allowed and not resolved;
4. `preview_cases` load-case ids = the `numerical_quality.cases` load-case ids (when solved);
5. each maximum row has exactly one extrema object with the same `result_id`, pipe and case; `value_lower_pa ≤ value ≤ value_upper_pa` and `value == lower + 0.5*(upper − lower)`; coverage partitions the case members (§5.2);
6. headlines per §6 (presence ⇔ complete coverage in every case; value, ref and tie rule);
7. supports per §5.3; magnitudes consistent with components within `64·ε·max(|m|, tiny)` relative (representation guard, not an engineering tolerance);
8. intensified rows ⇔ `intensified_measures` entries; `value` equals `sif*(hypot(My,Mz)/Z)` within the same 64·ε guard; its `source_result_refs` resolve in the same case;
9. combination rows (`basis_ref.ref_type == "combination"`) only for combinations whose gate has `withheld: false`; their `source_result_refs` resolve; no maximum or intensified row for a combination; mechanics/subtraction magnitude rows consistent with that combination's component rows (guard as 7).

A failure makes the source unsupported (Rust/Python error code prefix `SOURCE_PREVIEW_PHYSICS_`; TS equivalent).

### A2 — 2026-09-26: one strict reader list (ROOT ruling on R2 SF-1)
