## Blocking

- **B-1: the combination allowlist certifies linear superposition of nonlinear-support states.** The governing RESULTS_AND_COMBINATIONS design already forbids this (`NONLINEAR_COMBINATION_REQUIRES_SOLVE`). The reviewer ran the invented preview model, which has a one-way support and a friction support, through the desktop entrypoint. The `mechanics` combination 1.0·L-100 + 0.5·L-200 published superposed contact and friction reactions (NL-140 −361.38 N, NL-130-FRIC 0.79 N) as Current-eligible. **This is live on main today.**
  - Repair: when any operand has nonlinear supports, withhold every `mechanics` combination row with that code and keep the case states. Keep subtraction only as a labelled signed difference, and add a lift-off reference and mutation control.
- **B-2: the interaction with source-blocks-1 is undefined.** A source-blocks-1 envelope can mix source-selected cases with ordinary or failed cases. Those cases must publish precision-1-shaped rows, because the Rust and Python readers and the producer's own `validate_summary` require them, and `source_row_bindings` would see duplicate reaction rows. The design's claim that source-blocks-1 reactions "are already correct" is false for its ordinary cases, which publish norm-only reactions: M05 stays Current-eligible there.
  - Repair: specify the rule, correct §2.1(4), and add mixed-envelope tests.
