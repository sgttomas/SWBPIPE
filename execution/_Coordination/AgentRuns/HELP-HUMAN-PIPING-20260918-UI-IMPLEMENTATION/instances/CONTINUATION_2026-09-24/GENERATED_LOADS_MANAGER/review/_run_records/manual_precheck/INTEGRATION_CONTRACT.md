## Behavior

Pure solve validates recognized generated self-weight on the original typed model. It never refreshes or mutates the accepted model. A managed generated load with changed consumed mass dependencies blocks with load-specific SELF_WEIGHT_INPUTS_STALE. Invalid source quantities/units/shared-section bindings produce input diagnostics, not a misleading claim of ordinary dependency drift. A changed generated primitive is SELF_WEIGHT_GENERATED_LOAD_MODIFIED and also held until explicitly reconciled. Ordinary manually authored loads are unchanged.

Refresh is an explicit review/apply operation, not a side effect of solve or Save. The existing generation JSON/native/WASM route accepts a strict second request shape: {mode:"refresh", case_id, source_model_hash, manual_overrides:"block"|"preserve"}. Existing create requests and their strict unknown-field rejection remain unchanged. It uses the complete original model hash and returns the existing plan envelope and supported selected_pipe_mass_only scope.

The refresh preserves all primitive IDs, order, count, unselected/manual records, case metadata, explicit gravity and exclusions. It updates only magnitude and generated provenance of managed stale primitives, and only provenance of explicitly preserved modified records. It never appends a second weight, resurrects removed generated primitives, selects newly added pipes or replaces the case. A second refresh on an already reconciled case reports no refresh needed rather than queueing an empty operation. Invalid/unresolvable source or ambiguous lineage blocks the complete refresh plan; no partial overwrite occurs.

## Dependency and provenance rules

New generation retains the same physical mass inputs/basis but uses the ROOT-authorized stable-algebra successor in STABLE_MASS_SUCCESSOR.md, with mandatory mass_method source_od_effective_wall_areas/v1 and versioned provenance method pipe_mass_per_length_times_explicit_axis_acceleration/v2. Its self-contained record retains user provenance/gravity and original source hash, pipe and shared-section identity, an exact normalized consumed dependency projection, and the exact generated primitive payload excluding provenance. Existing v1 records remain identifiable and inspectable. Their old mass_inputs/referenced_section/gravity/mass fields are evaluated with the historical v1 formula for exact lineage recognition, followed by explicit numerical-method refresh to stable v2; they are not silently rewritten at open or solve. Ambiguous original payloads require explicit manual preservation.

Consumed dependency projection is resolved OD/wall, mill deduction, explicit section material_density, contents_density and the exterior insulation thickness/density pair, with compatible unit conversion and source section_ref identity. No all-model hash comparison after application. Node length/orientation and project length scaling are handled by the existing whole-span distributed load integration, so they do not stale intensity. Pipe material stiffness/name/provenance, unselected entities, support settings and arbitrary unrelated metadata are not mass dependencies. Current code has no implicit model.materials density fallback; no new material/layer/curvature theory is introduced.

Current payload is compared to its generated snapshot before any refresh replacement. New v2 snapshots allow exact preserved-value comparison after transport. Legacy v1 lacks a full generated payload snapshot; if its declared original intensity cannot be established consistently, classify it as modified/unverifiable and require explicit reconciliation, never overwrite an ambiguous value. No newly introduced numerical tolerance can turn a possible manual override into an automatic replacement. Known malformed generation records are input/lineage errors; source checks must not infer valid managed status from a string prefix alone.

manual_overrides:"block" is the default UI choice and refuses a plan that would reconcile modified generated records. With explicit preserve selected, each modified record keeps every physical field and receives a distinct manual_override_of_generated_self_weight/v1 provenance record retaining the original generation provenance and explicit preservation decision/source model hash. Subsequent solve treats it as a fixed manually owned primitive, emits a clear manual-override warning, and does not recompute it on mass edits. Further manual edits stay manual. No global/manual load is silently overwritten. Malformed original records cannot be laundered into a valid generated claim by this action; all ordinary primitive/solver validation still applies.

## Shared core API

self_weight.rs owns a typed inspection result with case_id, primitive_index, state (fresh/stale/modified/manual_override/invalid), optional current generated payload/provenance for explicit refresh, and structured diagnostics. inspect_applied_self_weight(&PreviewModel) is read-only. validate_applied_self_weight(&PreviewModel,&mut Vec<Diagnostic>) appends the same source-specific findings. Shared product lib.rs calls it after basic model validation has passed and before section resolution/unit normalization; invalid base inputs are not relabeled stale.

The normalized mass-input calculation is reused by creation/current inspection/refresh, using the sole shared PHYSICS area helper. Historical v1 evaluation deliberately retains the original formula, as the explicitly separate compatibility branch. Inspection must use cloned shared-section resolution and preserve its cache-validation semantics; it must not hash or trust a stale inline cache. No products outside this checkout are written.

## Operation and facade proposal

Use existing update_load taxonomy with a bounded rich field_path "generated_self_weight". Its before/after are checked canonical primitive-load arrays. The applier requires a complete current hash, equal IDs/order/count, exact unchanged unrelated records and physical-field preservation for manual detach; managed refresh changes only magnitude/provenance. It uses normal finite compatible force-per-length validation and preserves all other object bytes. The compound write is atomic through the existing operation/batch path. No delete/recreate index churn is needed.

An optional source_model_hash on OperationBatch binds generated create/refresh batches to the plan's complete initial document, checked before any batch simulation. Other batches without it retain their existing contract. This keeps a queued plan from rebinding itself to a later current-model claim after dependencies change. It is intentionally a full pre-apply plan guard; post-apply stale classification remains dependency-specific.

The native generate_self_weight_operation_plan command already forwards generic Value request/model to generate_plan and needs no new command or persistence schema. Proposed additional application edits are limited to services/selfWeightPlanService.ts (strict refresh request type/route), services/operationBatchService.ts (optional batch source hash type), and existing load-specific authoring tests. No native store/type or broad workspace changes are planned. UI adds an existing-case refresh action and an explicit preserve-modified-loads choice, retains usePreparation/hash/generation guards, and explains stale/modified inputs through the returned diagnostics.
