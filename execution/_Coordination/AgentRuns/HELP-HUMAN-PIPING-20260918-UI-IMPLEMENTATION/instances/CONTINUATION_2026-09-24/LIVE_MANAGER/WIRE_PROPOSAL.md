# Live-control wire v1 — current source implementation proposal

Prepared by /root/live_manager, WORKING_ITEMS Type 1. Owner activation is granted in ../OWNER_DECISIONS.md. This exact-byte proposal is ready for native and frontend writer acknowledgement; neither writer has yet acknowledged it. ROOT records their acknowledgements against its SHA-256 before product work. It concretizes, rather than replaces, activation revision 2, domain contract revision 3 and the historical wire draft. No implementation or connected-path qualification is claimed.

## Transport and limits

Development opt-in `SWBPIPE_LIVE_CONTROL=1` enables a private macOS Unix socket. Default startup remains unchanged. Other hosts return `unsupported_host` without breaking their builds. No network listener, account/provider configuration, MCP or embedded Runtime. Native startup creates a random short private directory under a suitable short temp root, mode 0700, then an exclusive descriptor mode 0600 and owner-private socket. Refuse symlink/existing unsafe objects; cleanup only process-owned objects. CLI verifies descriptor shape, file kind/permissions, frame limits and explicit identity. Native prints only the descriptor path on opt-in startup, never capability contents. Secrets are absent from responses, logs, examples and evidence.

CLI syntax: `swbpipe-control --attachment <descriptor-path> inspect|preview|submit|status`; one params JSON object on stdin, one response JSON object on stdout, nonzero exit for error. `help` and `describe` need no app. CLI does not accept Apply. Descriptor exact keys: `protocol_version:1`, `app_instance_id:string`, `socket_path:string`, `capability:string`. Native creates app identity and a random capability; these are local attachment authorization, not verified Codex identity. CLI supplies a fresh random request ID per process invocation.

Limits: 1,048,576 UTF-8 bytes per newline-delimited frame including delimiter; descriptor <=16,384 bytes; maximum 16 native in-flight requests; 30-second request deadline; maximum 128 explicit node IDs per inspection and 64 ordered changes per preview; 256 previews and 1,024 idempotency associations per controller lifetime. Refuse capacity without evicting promised recovery records. No silent truncation. No preview wall-clock TTL in v1. Preview invalidity on workspace replacement/revision change is explicit; key/ticket associations survive project replacement. Admission constants are new transport limits, not protected product-performance limits.

Request exact keys:
```json
{"protocol_version":1,"request_id":"req-example","app_instance_id":"app-example","capability":"LOCAL_SECRET_NOT_AN_EXAMPLE_VALUE","method":"inspect","params":{"scope":"workspace"}}
```
Success envelope exact keys: `protocol_version`, `request_id`, `app_instance_id`, `result`.
Error envelope exact keys: `protocol_version`, `request_id`, `app_instance_id`, `error:{code,message,retryable,next_action}`. Before trustworthy correlation can be parsed, `request_id` may be null; never echo unauthenticated caller app identity as the native authority. Unknown envelope/params fields reject. Native parses framing, identity, authorization and method only; domain validation stays in the frontend/engine. No capability is forwarded to the frontend. A transport error cannot assert that an earlier submit did not happen.

## Domain shapes

Opaque references are strings minted by the running controller, resolved against its registry, never caller-constructed authority. JSON object keys shown here are exact. Non-secret identity diagnostics use `identity:{app_instance_id,controller_session_id,workspace_id,project_generation,project_id}`; the opaque workspace references bind these values. Basis diagnostics add `model_revision` (published UI revision) and `model_hash` (the existing complete ModelHashEvidence object). Keep the internal modelRevision guard separate from this externally published UI revision; never mix the counters.

| Method | Params | Result |
|---|---|---|
| inspect workspace | `{scope:"workspace"}` | `{workspace,identity,readiness:"ready",selection:[{object_type,ref}],supported:{object_type:"Node",field_path:"position.x",operation_kind:"modify",change_kind:"set_field",dimension:"length",length_unit},limits:{max_node_ids:128,max_changes:64}}` |
| inspect nodes | `{scope:"nodes",workspace,node_ids:[string]}` | `{workspace,identity,basis,basis_identity,nodes:[{id,label,position:{x,y,z}}],length_unit}` |
| preview | `{workspace,basis,changes:[{target:{object_type:"Node",ref},field_path:"position.x",before:string,after:string,unit:string,dimension:"length"}]}` | `{workspace,preview_ref:string|null,basis,basis_identity,validation:"passed"|"blocked",outcome}`; outcome is existing validate-only OperationBatchOutcome, not a new result wrapper |
| submit | `{workspace,preview_ref,idempotency_key}` | `{workspace,ticket,state,reason,receipt}` |
| status | `{workspace,ticket}` | `{workspace,ticket,state,reason,receipt}` |

`basis` is an opaque reference. `basis_identity` contains identity fields plus published revision and full canonical model-hash evidence. Node positions are returned in current model representation, with explicit project length unit; inputs retain decimal strings and entered source unit. All model-sensitive calls name workspace. A workspace inspection is explicit app discovery, not a remembered default. Missing/unready coherent snapshot yields `not_ready` with no basis. Unknown nodes reject rather than omit silently. Workspace selection is a copied typed-identity snapshot; later selection changes do not retarget proposals. Non-Node selections may be returned for inspection, but preview supports only explicit Node position.x changes.

One-change previews use the same atomic batch route with one member. Multi-change order is immutable, including repeated targets; engine temporary-state before-value checks govern ordered changes. Inputs never carry operation IDs, validation/acceptance flags, author, source or rationale fields. The controller creates invocation-scoped operation/change/batch IDs, `author_type=agent`, truthful `source_channel=local_json_cli`, `source_role=external_agent_proposal`, and a neutral generated rationale with no professional claim. Never inherit `author_type=user` from a GUI builder. Reuse the maintained intent structure and engine, not its GUI attribution defaults. Explicit unit must equal the inspected source length unit in this first narrow projection; do not convert through display preferences. Engine retains finite numeric, before-value, dimension, reference and constraint checks. Failed preview returns diagnostics and no submittable reference, with no model/history mutation.

External states: `queued`, `committed`, `rejected`, `withdrawn`, `expired`, `outcome_unknown`. `reason` is null or a stable string; `receipt` is null except for committed. Pre-publication cancellation is an error `cancelled_before_publication` only once absence is confirmed and no ticket was published; UI Clear after publication produces `withdrawn`. Stale pending work is `expired` with `stale_basis` or `workspace_replaced`. Validation rejection is `rejected`. A receipt being hashed is a transient `not_ready` error, not a fabricated queued/committed response. Lost controller outcome returns `outcome_unknown` or an `expired` error for an old handle and requires reconciliation.

Receipt keys: `ticket`, `workspace`, `identity`, `batch_id`, `operation_ids`, `origin:{actor_type:"agent",source_channel:"local_json_cli",request_id}`, `acceptance:{route:"local_review_apply",identity_verification:"not_performed",professional_approval:false}`, `before:{model_revision,model_hash}`, `after:{model_revision,model_hash}`, `publication:{undo_checkpoint_id,applied_receipt_id,batch_receipt_id,queue_entry_removed:true,computed_results_invalidated:true}`, `persistence_status:"session_state_only_not_yet_saved"`. These are controller-observed facts, not claims of authenticated person identity. The actual human or controlled test-driver attribution belongs in the witness evidence; automated UI clicks cannot establish the real human witness. Raw engine acceptance metadata remains raw engine evidence and cannot by itself fill this receipt.

Error codes cover `invalid_request`, `unsupported_protocol`, `unauthorized`, `wrong_app`, `unsupported_host`, `unsupported_method`, `unsupported_change`, `frame_too_large`, `capacity`, `not_ready`, `controller_unavailable`, `busy`, `stale_basis`, `wrong_workspace`, `unknown_preview`, `unknown_ticket`, `idempotency_conflict`, `cancelled_before_publication`, `expired`, `outcome_unknown`, and `internal_error`. Replies redact arbitrary internal exception payloads. Each has concrete retry/reconcile/inspect guidance; uncertain submit guidance always says retry the original workspace/preview/key, never invent a new key.

## Native/frontend binding

Frontend installs request/cancellation listeners before registering. Commands are `live_control_register({controllerSessionId})`, `live_control_reply({registrationId,dispatchId,response})`, and `live_control_unregister({registrationId})`. Register returns `{enabled,app_instance_id,registration_id,controller_session_id}`. Disabled normal startup returns enabled=false and installs no socket readiness. Native commands receive the actual invoking WebviewWindow and accept only the configured main webview (`main`, checked against generated configuration), not a caller-supplied label. Only one active controller registration is accepted; StrictMode dispose/register ordering must be covered. Registration replacement expires prior pending dispatches. A stale session cannot unregister or reply for its successor.

Native event `piping-live-control-request`: `{registration_id,controller_session_id,dispatch_id,request_id,app_instance_id,method,params}`. `dispatch_id` is native-minted per accepted dispatch and cannot be forged by reusing a caller request_id. Frontend reply `response` is exactly `{result}` or `{error}`; native restores outer correlation and never trusts frontend replacement app/request IDs. Reject duplicate/stale replies. Frontend event `piping-live-control-cancel`: `{registration_id,controller_session_id,dispatch_id,request_id,reason:"disconnect"|"timeout"|"shutdown"}`. A disconnected socket does not delete controller idempotency history.

The native registry synchronizes readiness/admission/pending resolution and targets events to the registered main webview. The frontend listener dispatches through a current controller ref, not a stale first-render closure. Browser mode is inert. Unmount synchronously retires frontend readiness and settles outstanding handlers; asynchronous native unregister cannot clear a successor. Neither side waits forever for the other. Runtime/App consumes none of these commands in this tranche.

## Publication acknowledgement and recovery algorithm

1. Install one controller registry owned by the workspace hook lifetime, distinct from project generation. Never clear completed key/ticket outcomes on `advanceProjectSession` or Save/Open/Create. Reserve a NEW idempotency key and exact workspace/preview association synchronously before the first await. Identical in-flight calls join its promise. Different preview/payload association rejects. Authenticate app/controller first, then resolve an existing association before current-workspace/revision/freshness checks. New work still needs the exact current basis and free owner.
2. Preview freezes copied model, canonical ordered operations, complete basis and engine outcome. After every await, check request epoch, project generation, model/revision identity and cancellation. Do not substitute the model current at submit arrival for the inspected model. Canonical model hashing uses hashService's existing Rust/Wasm canonicalizer.
3. Queue publication uses a controller transaction token carried on the actual queued entry. `useLayoutEffect` in workspaceSession observes the committed render containing that exact token/key/frozen batch/basis. Only this observation records queued and resolves submit. `setQueuedBatches`, promise completion and an engine result alone are insufficient. Preserve existing GUI queue callers with an optional owned-live admission parameter or wrapper inside the same hook; expose no model/history setters.
4. A cancellation flag can prevent an unscheduled entry. For scheduled state, token-aware queue update/removal and a committed observer must establish absence before reporting cancelled-before-publication. Never promise cancellation merely because a setter was invoked. If the observer already witnessed publication, retain the ticket and report/recover its actual state; disconnection cannot withdraw or undo. Reconcile cancellation racing render and unmount conservatively, with outcome uncertainty where absence cannot be proved.
5. Human Apply remains the existing handleRunOperationBatch and DEC-020 engine. Live entries additionally validate exact workspace generation and basis. Prepare an expected transaction descriptor tying ticket, batch, before snapshot, new immutable model, checkpoint ID, applied receipt and batch receipt, expected next UI revision and result invalidation. Schedule existing controlled updates once. A layout observer must see the exact committed model plus queue removal, matching Undo checkpoint/receipts, cleared redo and invalidated result/analysis/manifest/rule state before acknowledging application. The existing `modelAssignment.status="committed"` is set before React publication and is insufficient by itself.
6. At that committed render, retain an immutable publication snapshot synchronously, including the before/after model snapshots and actual history/result facts. Compute/verify canonical after hash against that frozen after snapshot. Historical receipt hashing is owned by the observed transition, not the current project/hash effect: an immediate later edit, Undo or project switch must not erase or rewrite the commit. On hash failure retain an explicit observed-but-unresolved record and outcome uncertainty; never fabricate hashes or replay. Future retries can rehash the same immutable snapshot while that controller lives. Before actual observation, interruption cannot claim committed.
7. Clear maps observed queued tickets to withdrawn, stale model revisions to expired, project replacement to expired for pending work, while retaining already observed commits. Status and same-key submit recovery for a prior workspace generation run historical lookup first. Undo advances revision even when canonical content returns to the old hash; no old preview revival. Remount/restart creates a fresh controller identity and invalidates handles. No registry is persisted and no durable restart recovery is promised.

## Substantive delta assessment

No approved semantic obligation is removed. This proposal specifies concrete snake_case public wire fields, opaque basis references, Tauri registration/correlation, explicit limits, one-member atomic batches, and an observer with immutable historical hash ownership. Historical contract `cancelled` becomes the precise pre-publication error above; post-publication UI clearing is `withdrawn`, preserving the approved boundary. Those details require both writer ACKs, not another owner activation. Any proposed loss of publication proof, same-session recovery, source units, actor distinction, atomic Undo or actual human witness is a substantive contract change and must return to ROOT.

Current engine `atomic_batch.rs` still emits `agent_runtime_binding:"held_D58"` and `source_identity_verification:"not_performed_asserted_metadata_only"`. Preserve these as engine-local historical/raw metadata; the controller envelope reports the actual local CLI binding without asserting Runtime qualification. Their presence is not a reason to infer no owner activation, and they are not trusted live-origin evidence. Altering core output is outside both proposed writers and requires ROOT's named scope, if needed.
