## SSLL106 variants and assumptions

[The current family index](https://codeaster.gitlab.io/doc/docaster/manuals/man_v/v3/v3.01.106/index.html) and pinned scripts distinguish A/C/E linear workflows from B/D/F elastic `STAT_NON_LINE` workflows. A/B use TUYAU_3M with SEG3, C/D use TUYAU_6M with SEG3, E uses eight SEG4 members converted from an ASTER SEG3 mesh, and F one SEG4 member. A/C/E also contain modal checks, which are outside this static scope. B/D/F contain seven nodal/pressure cases; declared high-yield material parameters do not establish a plasticity validation because their selected law is ELAS. Do not interpret every file as an independent theory or every family statement as every variant's exercised load set.

[Problem §1](https://codeaster.gitlab.io/doc/docaster/manuals/man_v/v3/v3.01.106/Probl_me_de_r_f_rence.html) defines a5m member oriented along(4,3,0), outer radius0.04m and wall0.004m, elastic E/nu, density and constant expansion data. The fixed/free geometry and explicit rotated load components are useful for frame-convention testing. They are source-prescribed fixture inputs, not a library selection. The acquired MED input and node/group mapping still need a decoded, independently checked model interpretation before use.

[Reference §2](https://codeaster.gitlab.io/doc/docaster/manuals/man_v/v3/v3.01.106/Solution_de_r_f_rence.html) explicitly includes Timoshenko shear with reduced shear areas equal to section area. Transverse tip-force and distributed/self-weight displacement targets therefore cannot be used as exact EB checks merely because the pipe is slender. Equilibrium/actions can be separately selected with their own mapping, while deflection targets wait for formulation matching. Its modal bending values are numerical roots, distinct from elementary static formulas and pure axial/torsion modal expressions; no dynamic target is selected here.

[Model A §3.3](https://codeaster.gitlab.io/doc/docaster/manuals/man_v/v3/v3.01.106/Mod_lisation_A.html) defines beam actions `N,VY,VZ,MT,MFY,MFZ`, but stress coordinates are axial/circumferential/radial and indexed by longitudinal point plus thickness/circumferential subpoint. It sets radial stress/associated shear to zero. `WO` is an enriched radial quantity, not a centerline translation. Model A's transverse generalized strains have interpolation error; [model E](https://codeaster.gitlab.io/doc/docaster/manuals/man_v/v3/v3.01.106/Mod_lisation_E.html) changes interpolation order, not the basic target into an EB result. Do not borrow tabulated error percentages as project acceptance criteria.

The pressure load uses `FORCE_TUYAU/PRES`. [The element command notice §3.4.2](https://codeaster.gitlab.io/doc/docaster/manuals/man_u/u2/u2.02.02/Description_du_jeux_de_commandes.html) locates that pressure at the internal radius. The inspected deck tests `WO`, hoop stress and hoop strain; it does not supply the explicit closure-transfer field or wall/effective axial reference ledger required by current Piping. No closed-end-equivalence claim is inferred. A full pressure target needs its own free body and matched radial stress/strain approximation; keep existing independently checked Piping annulus references for current closure/thermal interactions.

## SSLL101 Hovgaard and reference lineage

[Problem §1](https://codeaster.gitlab.io/doc/docaster/manuals/man_v/v3/v3.01.101/Probl_me_de_r_f_rence.html) describes a noncoplanar, two-bend, end-fixed line with separate gravity, nodal-load and uniform thermal states. It says water-filled, but the inspected decks use a supplied effective density and no pressure load; this is not a hydrostatic validation. Do not add a separate full-fluid mass on top of the supplied equivalent density. Constant alpha and a472.22 temperature field with reference0 are explicit command inputs, not temperature-dependent material interpolation or installation-history evidence.

Model A uses92 straight POU_D_T segments,40 per bend. Its general sections retain area and torsion properties while assigning smaller bending inertias in bend regions; AY/AZ are2. [The section command definition](https://codeaster.gitlab.io/doc/docaster/manuals/man_u/u4/u4.42.01/Mot_cle_POUTRE.html) identifies these as inverse shear factors, not areas. Match the explicit effective properties; do not regenerate them from a code rule or reduce pipe wall to mimic a bend. Aster source A's density/nodal rounding differs slightly from C/D/E; preserve the selected variant exactly.

[Reference §2](https://codeaster.gitlab.io/doc/docaster/manuals/man_v/v3/v3.01.101/Solution_de_r_f_rence.html) assigns beam comparisons to POUX/ADL/TITUS and enriched-pipe comparisons to ABAQUS with the corresponding Fourier order. It reports2% reference uncertainty. The equivalent-moment scalar at T1 instead descends from model A as AUTRE_ASTER; it is neither another external solver nor an independent analytical oracle. C/D use28 SEG3 members with3/6 Fourier modes; E uses28 SEG4 members with3 modes. Their restrained Fourier DOFs and local deformation mechanisms cannot be hidden behind a six-DOF beam mapping. Preserve individual displacement components, not just a norm; source publications report materially different Y-component agreement.

No underlying POUX/ADL/TITUS/ABAQUS run deck, version or raw external result was acquired. The public document's bibliography points to the1956 Kellogg piping text but does not resolve all modern reference-run details. Treat the values as **published numerical references of reported lineage**, not reproduced external runs, measurements or independent physical validation. The Code_Aster command's VALE_CALC fields add regression observations; they do not improve the external reference's independence.

## Freshness and engine feedback

The official switcher labels v17 stable and v18 development. The six inspected problem/reference/model-A article bodies are identical across those versions; no newer correction was observed there. This is a bounded comparison, not a claim every page/version is unchanged. [Current theory R3.08.06](https://codeaster.gitlab.io/doc/docaster/manuals/man_r/r3/r3.08.06/index.html) still describes small rotations/strains with mixed beam/shell behavior, ovalization, swelling and warping. More Fourier modes or SEG4 interpolation add a different approximation space; they do not invalidate current straight EB/Lamé identities or prove that a richer benchmark must be passed by a narrower beam solver.

Necessary mapping fields are actual frame/cut convention, centerline versus radial DOF, Gauss location/surface, total/elastic/thermal strain meaning, signed support action versus element nodal/internal force, pressure closure/effective-force identity, exact per-region stiffness/mass basis, and reference class per assertion. In particular, thermal `FORC_NODA` near zero at a free end is not automatically a six-component support reaction measurement. Do not claim unavailable outputs as zeros. These distinctions feed the validation adapter and later mechanics work; no new solver formulation is implemented by this research.
