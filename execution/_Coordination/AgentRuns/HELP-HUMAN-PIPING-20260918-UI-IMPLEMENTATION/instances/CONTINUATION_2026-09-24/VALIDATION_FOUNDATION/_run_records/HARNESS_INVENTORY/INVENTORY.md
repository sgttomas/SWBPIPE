## Why PKG-14 comparison cannot be the qualification gate

`core/comparison/analysis_run/engine.py:1–5` explicitly describes a diagnostic comparison of already-available records. Its API at `:163–221` accepts left/right runs, result envelopes, mappings, optional tolerance profile and explicit unit conversions, and returns deltas, settings deltas, diagnostics and professional boundaries. It does not ingest external solver files or establish acceptance.

- Exact-ID mapping is an **intersection** of unique result IDs with compatible family/object/basis/dimension (`:230–308, 499–520`). Missing/unmatched/duplicate IDs may produce no automatic mapping. Empty mappings can therefore produce zero deltas and no blocking diagnostic; that is not a passing qualification denominator.
- Direct comparison indexes duplicate result IDs with a dict comprehension (`:471–475`), so a later occurrence replaces an earlier one. It does not make a complete quantity inventory claim. Explicit mapped missing data and nonfinite input magnitudes do block (`:331–349, 391–408, 658–666`); noncomparable/unsupported mappings can be warnings with no delta (`:314–329, 351–368`).
- `_classify_delta` returns `not_classified` when the profile/rule/unit basis is absent and `exceeds_tolerance_profile` for a numerical excess; `has_blocking_findings` counts diagnostic severity only (`:137–139, 542–576`). Neither that property nor “no diagnostics” proves every numerical assertion passed.
- Current paired classification is `max(absolute, relative * max(abs(left), abs(right)))`, not the external documents' proposed reference-sided `atol + rtol*abs(reference)` (`:557–569`). The wrapper must cite the actual adopted criterion; it must not silently rewrite this function or import the example formula as policy.
- Source values and conversion factors are checked finite, but multiplication/subtraction results are not rechecked before classification (`:409–450`). Finite inputs can overflow during normalization/delta calculation. This is a source-level hazard to cover in a required-output adapter's arithmetic tests, not a newly executed product defect reproduction.
- The raw CLI mechanics envelope uses `results[]` with `id/value`; this diagnostic comparator expects envelope `result_sets[].quantity_results` (or `.results`) with `result_id/magnitude` (`:480–496`). Passing raw CLI JSON to it without a deliberate existing-contract projection would silently yield no rows.

Keep PKG-14 behavior and schema roles intact. A qualification gate may consume diagnostic comparison findings as supplementary evidence, but owns its independently declared denominator and fails closed for unclassified required assertions.

## Smallest concrete extension proposal

1. **Read the manager-owned qualification inventory.** For one explicitly selected case set, lock exact case IDs/revisions, required quantity selectors and semantic definitions, input bytes/hash, reference bytes/hash/source locations, criterion owner/predicate revision, and case purpose. Keep source readiness distinct from executed outcome. Require nonzero cases and required assertions, unique IDs and a complete justified criterion/reference basis before an eligible qualification result. Unavailable data stays blocked; do not generate answers from production outputs.
2. **Adapt the existing production solve CLI only.** One prepared `RunnerRequest + solve.preview_model` per production case, with explicit request/run identity. Preserve exact input bytes and raw controlled output. Check wrapper `blocked`, CLI exit and payload identity, operation, both validators, runner/model/run/status, mechanics diagnostics and required converged/solved conditions. Do not infer success from exit code alone. Use separate regression entries for existing suite checks and expected-error fixtures.
3. **Evaluate a preallocated required-row ledger.** Each required case/quantity row exists before invoking the process. Resolve each selector exactly once against raw `MechanicsEnvelope.results`, requiring matching entity/load basis, quantity kind, component, frame, location and sign convention, and explicit unit/semantic-contract identity. Check expected and observed values and every arithmetic intermediate are finite. Do not zero-fill, collapse duplicates, discard missing rows, infer dimensions from units, or let an extra unexpected loadcase substitute for the required one. Preserve unrelated extra diagnostics/rows; only an explicit reviewed inventory rule may designate an extra output as outside the comparison scope.
4. **Dispatch an existing governed predicate.** For existing suite regression values use the suite-owned accessors/predicates and their exact constants. For new production-case targets record the applicable existing criterion and dimensioned budget; if there is no adopted basis, report criterion unresolved. Preserve analytic `1e-9` requirements and fixture-specific rules. No blanket scalar formula, threshold, or floor is added by this inventory.
5. **Derive machine/human summaries from the same complete ledger.** Count expected cases/assertions separately from executed/matched/failing/blocked/error/not-run obligations. Interruption leaves outstanding rows present. Required work cannot pass if any required row is missing, duplicated, unsupported, blocked, skipped, nonconverged, nonfinite, unclassified, or mismatched. A diagnostic expected-error regression has its own recorded purpose and cannot cover a physical-solution requirement. The narrow initial artifact can be a script plus inventory-linked JSON/Markdown run evidence under existing `validation/` conventions; retain raw evidence rather than introducing another general report engine.
6. **Bind the actual run, not merely its label.** Capture candidate revision and dirty state, exact executable/artifact SHA-256, invocation/exit/signal, environment/toolchain where material, input/reference/inventory/semantic-contract/predicate hashes, timestamp and artifact locations. Reuse existing canonical-hash/analysis-record/audit-manifest mechanisms where their actual contract applies. Preserve reference acquisition/update as separate evidence. An absent packaged-build witness remains absent; development execution does not become release qualification.

Minimum bounded adapter tests for the eventual implementation: complete good result; deliberately wrong value/sign; missing required case/quantity; duplicate case and duplicate result selector; extra wrong loadcase/frame/unit; finite-input arithmetic overflow; nonnumeric/nonfinite/null; empty required inventory; malformed/truncated output; nonzero exit/no output; expected nonconvergence counted only as diagnostic regression; changed input/reference/build/inventory hash. These are requested future fault-sensitive adapter checks, not tests executed here or new engineering tolerances.
