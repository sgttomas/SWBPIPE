## Highest-risk confirmed paths

1. **SUP-02:** an authored linear guide disappears when the same record carries nonlinear contact. This can yield a solved model materially different from the input visible to the user.
2. **SUP-04:** constant-effort force is injected into every primitive case, so ordinary addition can count it repeatedly, while the general support action is zero.
3. **SUP-08:** general support loads lose all moment components and force signs/components, making complete restraint and equipment action interpretation unavailable. SUP-13 adds a narrower nonlinear contact-attribution error.

SUP-11 is another high-priority correctness concern. SUP-01 is a confirmed availability limit whose practical prevalence still needs sealed reproduction. Missing preload is a serious capability gap even though the current result contract discloses it as metadata.

## Recommendations to reject or qualify

- Do not implement “cap 100” or new tolerances as an unmeasured fix. D-19 ruling (`P/execution/_Coordination/_DECISIONS/D-19_release_convergence_tolerance_policy.md:165–171`) explicitly makes raising a cap/loosening a value a new governance event. Preserve loud non-convergence. A larger cap does not establish a correct contact/friction law.
- Do not freeze a chattering support merely to obtain convergence: that can violate complementarity and produce the wrong active set. Any cycle-control algorithm needs a defined admissibility criterion and independent benchmarks.
- Do not infer preload or constant-force inclusion merely from “weight-bearing”; define reference state, direction and explicit case participation so combinations neither omit nor duplicate the hanger action.
- Do not call manual imported-record selection absent, apply an unverified universal 25% hanger-variation threshold, or treat state subtraction as a complete code-stress method.
- Do not infer missing rotations from absent rotational restraint tokens, claim every duplicate support double-reports, or replace exact skew constraints with arbitrary stiff springs without conditioning/rank evidence.
- Do not change tests/oracles that record an existing contract merely to pass an alternate implementation. Existing tests such as `pp:12932` codify all-case constant effort; a proposed contract correction must include an independently justified expectation and migration/accounting of the changed behavior.
