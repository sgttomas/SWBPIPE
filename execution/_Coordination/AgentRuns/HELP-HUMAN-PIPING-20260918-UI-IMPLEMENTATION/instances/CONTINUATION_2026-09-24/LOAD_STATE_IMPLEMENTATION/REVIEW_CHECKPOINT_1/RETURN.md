## Verified, and how

1. **Build and tests.** In `core/product_physics`, I ran `CARGO_TARGET_DIR=<isolated> cargo +1.97.1 test --locked --offline -j 1 --lib case_state` with cargo and rustc 1.97.1. Result: 18 passed, 0 failed. There were no warnings in `case_state`; all 8 warnings are pre-existing (`test_case_state_review_1.log`).
2. **Physics against my own derivation.** I found no errors.
   - **E, ν and G.** G = E/(2(1+ν)) comes only from the existing `IsotropicENu` (domain E > 0 finite, −1 < ν < 0.5, representable positive G), and is applied to every consumed endpoint and to the interpolated pair. E and ν are interpolated linearly inside a strict bracket, and G is derived afterwards. The test distinguishes the correct 70 GPa from the interpolated-G value of 77.08 GPa.
   - **Selection.** Exact-point and endpoint selection, no extrapolation and no fallback to fixed data all hold. Actual, selected and undated temperatures stay distinct, and an override is required when a known actual T differs from the selected T.
   - **Thermal conversions.** For each definition, ε = [λ(T) − λ(Ti)]/λ(Ti), evaluated as a direct difference: secant, dilation-slope, datum-integral, and expm1 for the logarithmic form. Reversal is a ratio inverse. Split composition, installation below the datum (2/1999 for all three linear forms), multi-segment integrals and the interior secant value (23/16012) all match exact rationals within 1e-12 (`thermal_probes.log`).
   - **Path positivity.** The stationary-point candidates for the quadratic secant and datum forms are correct.
   - **Fit.** ε* = ε_fit + ε_th + ε_fit·ε_th, and the sign is correct: a cut-short member is in tension at +40000 N, the hot state gives −89976 N, and a cut-long member gives −40000 N. ΔL ≤ −L is refused.
3. **Test meaningfulness (mutation).** For thermal, 10 of 13 mutants were killed by the original tests (`thermal_mutations.log`). The killed mutants were: no λ(Ti) division, log treated as linear, reversal by negation, additive fit, flipped fit sign, no path check, α_hot·(T−Ti), naive difference of rounded stretches, datum ignored, and an unchecked dilation datum. The survivors are T1 and T2 (SF1) and T14 (SF2). For material, 4 of 4 mutants were killed (`material_mutations.log`). No expected value is computed by calling the kernel under test. The only kernel-to-kernel comparisons are the tautologies in N2 and the identity checks of already-pinned values.
4. **Fixture.** `review_fixture_recompute.py` is my own script, using only the standard library: fractions, decimal, and π from Machin's formula. It does not import or read the generator or the manager's script.
   - All 324 quantities checked out: each binary64 `value` is correctly rounded from `exact`, and each `decimal` string agrees with `exact` to 80 or more significant digits.
   - All expected values in controls 1, 2, 3 (parallel and serial), 4 (plus the constant-α case), 5, 6 and 9 were re-derived from first principles: partitioned stiffness, E-B stiffness, λ ratios and trapezoid integrals. So were the annular As/I/J/Z values, from OD and wall only.
   - The inputs match VERIFICATION.md. The one exception is the added 20 °C α point in control 4, which is disclosed.
   - The fixture is labeled as invented, and a word-bounded scan found no material-library or code-rule terms.
   - Result: 886 checks, 0 failures (`fixture_recompute.log`). Nine mutations were all detected, including three consistent exact/decimal/value mutations that only an independent derivation can catch (`fixture_mutations.log`).
   - The generator uses only the standard library and git for hashing. The manager's script derives from the fixture's own inputs rather than from VERIFICATION, and uses the fixture's π string. My script covers both of those gaps.
5. **Design boundaries.** All new items are `pub(crate)` inside a private `mod case_state`. There are no serde derives and no public DTO or schema change, and the diff touches no other source or test file. No default temperature or ambient value appears outside tests, and legacy `thermal_expansion_coefficient` is never read. Material identity is the input's ID, with no alias records and no mutation (asserted in a test). No existing test or criterion changed.
