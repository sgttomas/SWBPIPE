### C4 label policy ready for implementation

1. **Identity and eligibility.** Use one typed label identity per supported annotation and deduplicate overlapping context roles. Context consists of primary selection, hovered entity, current row's resolved node and other selected entities, where supported label data/geometry exists. Explicit Hide wins in every mode; it does not acquire a label from selection. Dimmed geometry retains the existing isolation styling and pick policy. Do not invent missing restraint/load plate capabilities or new model data.
2. **Priority.** Attempt context placement before ordinary annotations, in stable order: primary, hover, current-row node, remaining selected annotations. Preserve stable selection order with a deterministic typed-ID tie-break where needed. Resolve the current row through the shell's actual row/focus publication; primary selection is not an interchangeable proxy. Ordinary priority follows the retained adopted design/model relationships and deterministic distance/identity policy.
3. **Nominal Budget.** Let `B = floor(canvas CSS width × canvas CSS height / 3600)`, using the actual drawable CSS area, not DPR-scaled pixels or outer pane size. Place all eligible context candidates first without a count cutoff at B. Let C be the number of context annotations actually placed. Ordinary annotations may fill at most `max(B − C, 0)` remaining slots, after collision checks. Failed placement spends no rendered slot. No ordinary annotation is admitted once context fills or exceeds B. Thus the resulting count is at most B when C ≤ B, and equals C when C > B; the excess is declared context overflow, not a cap failure concealed by diagnostics.
4. **Off.** Ordinary annotations are suppressed; eligible context still receives the same placement attempt. Off may display zero, one or many context annotations. Do not keep a production-only hidden zero-label mode just to satisfy an old instrument assumption.
5. **All.** No nominal count cap; context is attempted first and ordinary annotations follow. All retains the same visibility, containment, non-overlap and picking protections. It never means every requested annotation fits.
6. **Placement wins over the visibility aspiration.** Labels must remain inside the drawing area, never overlap one another, and must not cover geometry's required picking target. Use measured plate dimensions and deterministic bounded placement search. Context overflow lifts the count restriction only; it does not permit overlap or bypass geometry constraints. Every eligible but unplaced annotation remains identifiable with a reason. Do not silently truncate the context input at the old 80-candidate helper or at B.
7. **Truthful reporting.** Expose mode, nominal budget, actual rendered context/ordinary/total counts, context-overflow count `max(C − B, 0)` in Budget, and unplaced annotation identities/counts with causes such as collision/containment/picking. Distinguish ordinary labels suppressed by mode/budget from requested but unplaced context; do not add either to C3's hidden-geometry count. A compact count with accessible inspection of omitted identities is sufficient; no long overlay list is required.
8. **Session and authority.** Budget is the new-project default; mode survives ordinary stage/view transitions and edits. C4 introduces no persisted state: G-17 owns compatible persistence, and All is not promoted into a persisted preference. Label control, pointer and L accelerator share one action route. Mode/layout changes must not mutate model, history or result standing.

The budget arithmetic is an operational reading of “context first; ordinary labels use nominal slots left.” It subtracts successfully displayed context rather than reserving slots for annotations that could not be placed; all context has already received first placement priority. No material owner ambiguity remains for this bounded implementation. Any later conflict found in actual placement or qualification is returned with its specific source and evidence.
