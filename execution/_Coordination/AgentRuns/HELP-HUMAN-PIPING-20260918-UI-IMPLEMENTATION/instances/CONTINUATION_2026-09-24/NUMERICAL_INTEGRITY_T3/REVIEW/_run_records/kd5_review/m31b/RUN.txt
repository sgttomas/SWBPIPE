RV5 M31b attack: exact-arithmetic emulation (standard-library Python 3, Decimal at 80 digits).
Copy the *.py.txt files to a scratch folder as *.py and run there:
  python3 validate_cskew.py              > validate_cskew.stdout.txt
  python3 m31b_attack.py "$(cat specs1.json)" > sweep1.jsonl
  python3 sweep2.py                      > sweep2.stdout.txt   (also writes sweep2.json)
  python3 gen_models.py                  (writes rv5_models.rs: kd5-style ModelData with exact u_int)
m31b_emulation_results.json consolidates sweep1 and sweep2 with each model's exact inputs
(binary64 values as printed by repr: node coordinates, the binary64 arc centre, springs, loads).

Models: one realized bend, node 0 at the origin, translations DOF 0-2 rigid, rotational springs
DOF 3-5, node 1 free with a moment (DOF 9, 10, 11) = (1, 1, 1) N*m unless stated. Section: E 2e11,
G 8e10, A 0.005969026041820614, I 2.700984283923829e-05, J 5.401968567847658e-05; flexibility
factor 1. "shift max" = the centre moved along the chord by the largest fraction of R whose
binary64 geometry the product still admits (|ri - rj| <= 1e-9 max(ri, rj), 1e-9 <= phi <= pi - 1e-9),
found by bisection on the product's own binary64 geometry() arithmetic (b64_formula_chord).
PP-route models: the centre is computed exactly as PP build_curved_bend_macro_elements does
(midpoint minus sagitta times the in-plane normal from y_reference (0, 1, 0)); no designed mismatch.

Quantities (per free nodal row, ratio to 1e-9 * max(|q_i|, S*_kind), S* as formation_check.rs):
  EF_correct = K_act^-1 (f - K_act u), EF_M31b = K_act^-1 (f - K_frm u), actual = |u - u_act|,
  with K_act the check's intended system (H from the actual chord), K_frm the same with H from the
  product's binary64 chord R(cos phi - 1), R sin phi, 0 (== the M31b intended element and, up to
  its own binary64 rounding, the product's element), u = the K_frm solution rounded to binary64.
  Trigger = 2 * EF. The product's own binary64 rounding is not in u here (it is in the Rust run).

validate_cskew: the port reproduces I3's exact u_int of CSKEW_8_5 and CSKEW_30_RADIUS_MISMATCH
to the last digit (three entries differ by 1 ulp), and on CSKEW_30_RADIUS_MISMATCH the chord alone
moves node 1 uz (DOF 8) by 1.838e-16 m: |dEF| = 0.4333 of the criterion on that row (trigger 0.867).
