## Reply ownership and remaining P4 boundary

The proposed non-Serialize IpcResponse wrapper preserves the previously checked Tauri body handoff. Success owns its cloned status/result and serializer buffers through transfer. Busy performs no result clone and uses a separately owned small-control allowance. Known W1 reply-local errors travel through the same guarded control path rather than dropping a guard before ordinary `InvokeError` conversion; the latter allocates a Value in pinned Tauri `ipc/mod.rs:240–245`. This is a local extension of the existing poll response, not a new endpoint, scheduler, retry framework or backend-state machine.

The serializer-failure branch correctly remains conditional: actual partial-buffer destruction, emergency small-buffer availability, error codes/maximum widths, fallible construction and every transfer/Drop path still require P4 and native tests. Freeze the finite W1ReplyError code set before implementation; only the Busy code is a retry warrant. If a bounded emergency control cannot be built, the caller profile is unqualified, not silently covered by a Tauri Err fallback.

Contract §4 truthfully leaves aggregate denied/error concurrency open. A source-proved per-request D and K-admitted-large-reply bound do **not** establish a bound for arbitrary simultaneous denied requests. The full native aggregate still needs the actual live count d, shared state/container ownership and its enforced/profile premise; `R + K*L` cannot silently stand in for `R + K*L + d*D + S` and the other stated phase terms. First-party sequential polling bounds that one retrieval's retained client state, not server-wide concurrency. Tauri post-transfer queues, other jobs, WebView/TS heaps and whole-process RSS remain named exclusions.
