## Cross-plan interface for ROOT to reconcile with I30

I29 supplies proposed memory APIs/ownership cells, not a wire contract. I30 must
supply the precise eligible SourceParts recipe, final row/unit/derived certificate
and receipt/readers, candidate/ordinary mixing and PP publication rollback contract,
and qualified captured caller roster. Required memory inputs are maximum live
row/ID/metadata/receipt populations, owned/borrowed source and result references,
all proposed clone/canonicalization/replay steps, and last-use boundaries.

I29's proposed return to that interface is:
- PreparationPermit → opaque identity-bound PreparedRetainedBatch with checked
  raw/exact populations and owned group preparation.
- ExecutionPermit → current-schedule W1 outcomes plus retained ownership and
  unchanged work charges, under an adopted finite caller/window/profile.
- PublicationDraft → privately certified candidate rows/receipt; ordinary base
  remains owned until a complete commit. Memory refusal is not a failed ordinary solve.
- CompletionPermit → named direct-return or headless-output phase reservation.
  Headless keeps the completion reservation through its existing in-memory
  export path; it does not retain an extra ordinary base after PP commit when
  all completion allocations were bounded upfront. Late export refusal retains
  its existing meaning, separate from W1 memory admission.

These are proposed typestate/call contracts, not existing implementations or
security boundaries. Source review must establish that product calls cannot
accidentally reach new allocations before the corresponding check. Existing
H/VR public retained APIs remain separate validation consumers.
