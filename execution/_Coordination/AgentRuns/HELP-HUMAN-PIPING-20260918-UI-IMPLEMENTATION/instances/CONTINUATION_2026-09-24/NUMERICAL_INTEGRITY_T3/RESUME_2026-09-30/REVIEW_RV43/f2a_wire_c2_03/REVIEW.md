## RV43-C2-F1 — Define the combination nodal-term source form

**Blocking for closed contract/schema freeze; P2. Location:** CONTRACT_DELTA.md:78–82 and :93.

`SourceBinding` has one exact member set, including `nodal_terms`, for both case and combination owners. The nodal-term shape is case-specific: `{constructor_ordinal,source_id,primitive_load_index,dof,value:B}`, with primitive_load_index bound to “the actual case entry” and the array in kernel-canonical order. For a combination there is no single such case entry, and the contract does not state whether this field is the first operand's source metadata, every operand's factored terms, or a newly formed combined array. `owner.terms` binds factors and operand source refs, but does not resolve the meaning of the additional mandatory nodal_terms field or its equality checks.

**Trigger:** an ordinary supported mechanics combination whose operands have the same stiffness/layout but different loads, including the existing cancellation combinations. In source, `CasePrep::combination` keeps the first operand's `PrimitiveSource` (`adaptive.rs:914–953`), separately creates `RetainedLedger::combined` from exact products of every operand term (`ledger.rs:152–177`), and binds K4CMB to ordered factor bits/full operand encodings. It does not construct a new combined PrimitiveSource with finite binary64 load values. The source tests explicitly include the differing-load B1-C/B1-E cases (`combine_tests.rs:153–212`).

**Impact:** two conforming implementations can choose different required nodal-term arrays and source hashes; one may misidentify the first operand's loads as the combination loads, while another might round factor-products/nets into B to satisfy a case-shaped field. Neither choice is supplied by this finite mapping, and the latter would contradict the exact-ledger rule.

**Correction:** specify a discriminated case/combination source form, or explicitly identify which common fields are inherited from the representative first source and which describe the factored combination. For combination load provenance, reuse the ordered factor/operand SourceRefs (and, if needed, source-local term ordinals) without creating rounded combined B terms. State exact hash/equality/count rules and how primitive_load_index resolves per operand. The correction should preserve K4CMB/K4LED bytes and the existing numerical algorithm; it needs no new numerical criterion.

## RV43-C2-F2 — Represent pre-source combination refusals without a fabricated Run source

**Blocking for closed contract/schema freeze; P2. Location:** CONTRACT_DELTA.md:106–108 (with :46–50, :78 and :162).

C2 says a mechanics_combination Call is one Run, and every Run requires `origin.source_ref:U`. A source registry entry exists only after valid source/map construction, while a routing/pre-source decline has no Run. The contract does not give a terminal Call form, or an explicit rule excluding and separately projecting a recorded combination entry that returns before a valid combined source exists.

**Trigger/source:** `RetainedCombination::solve` returns NoOperands, NestedCombination or OperandsDiffer before `CasePrep::combination`, and a ledger-preparation refusal before the combined prep/identity exists (`combine.rs:85–120`). These are not hypothetical extra variants: source tests require empty attempts for invalid combinations and changed station/support declarations (`combine_tests.rs:375–407,535–557`), C2 explicitly maps those reasons, and corrected C1 requires the source-based API to preserve the same checks/order. C2's chosen recorded combination path must therefore define the corresponding evidence outcome.

**Impact:** the literal one-Run Call form cannot describe these returns without inventing a valid combined SourceRef or contradicting the no-Run pre-source rule. Omitting such a call may be a legitimate design, but its boundary, reason custody, meter snapshots and indexing consequences are currently unspecified. This prevents a unique producer/three-reader projection for a declared failure branch.

**Correction:** add a closed pre-source/preparation result to the recorded-call contract, or explicitly put these checks outside the Run/Call domain and define their `retained_unavailable` projection with no source/run/build, the exact typed reason and unchanged meter. Keep group-preparation refusal with an already valid source distinct. Define whether/how the call appears in calls/run_refs/execution_order so arrays remain bijective; do not allocate a fake source/group or label post-work refusal as zero work. Retain the unchanged legacy CombinationOutcome observation and ordinary fallback. No new solve or source-domain expansion is needed.
