## RV19-D4u: preserve protected assertions

The historical D4u patch changes the O9 skip set from candidate to verifier and
deletes two overflow assertions in method_tests. It is prohibited under the
current no-assertion-change fence. The unmodified sd_g5_a_row_the_candidate_cannot_
publish_sets_no_s_star test has overflow assertions at1643–1649, then underflow
assertions at1664–1673. The ordinary D4 fault can fail at the first overflow
assertion; that does not prove the later underflow assertions ran.

Recommended current diagnostic variant: use wrong verifier membership only for
a pair where candidate OR verifier has an Underflow outcome, while retaining
correct candidate membership for the overflow controls. This preserves every
original assertion and permits the original underflow verdict to be the actual
failure. Label this a separately reviewed current underflow-only semantic
variant; retain ordinary D4 and the historical D4u bytes. ROOT must accept the
mapping before execution. Do not silently call it the historical patch, count
the early overflow failure as underflow evidence, or retire the obligation.
If that variant is not accepted, leave D4u open for a permitted additive isolated
underflow discriminator rather than deleting protected checks.
