# Local owner, work and storage audit

This account distinguishes newly introduced local work from retained helper work. It does not turn a LibraryBoundary event into a complete debit. The native meter, each private draft's correction count, local adapter/arithmetic evidence, and later invocation-wide debit remain separate.

## Owning transitions and failure evidence

The production entry prepares its own observer, runs ordinary production, and immediately moves that exact returned envelope into private prepare_owned_case. No production preparation or projection API accepts a replacement envelope. PreparedCase holds the ordinary owner privately; its capture is now borrowed-only outside the module. project_candidate consumes it. Success and refusal wrappers own their envelope, native/capture state and proof evidence; neither exports an owned PreparedCase. A sticky attempt state is charged/set before the first draft and checked before any repeat binding. Tests deliberately reconstruct a test-only repeat and retain the old proof/failure beside the new rejection; counters and envelope bytes do not change.

The owned old/new association vector stores, for each authenticated member id, old source E/G/A/Iy/Iz/J bits, old matched facts D/effective t/A/I/J/Z/c bits, and all five actual preparation outputs. Its checked reserve uses prepared capacity slot 13; fixed copy entries and requested bytes precede its infallible record construction. The vector survives success and every preparation failure after entry. The old I/Z evidence no longer disappears when facts are overwritten. Existing old operational work and preparation Spent owners remain separate.

Both lanes retain their own ResidualWork. The correction getter sums either or both present lanes and returns None only when neither entered. An actual first-lane post-correction ownership refusal retains one correction with no Source lane. A source-seed refusal after a view is produced retains its data-mask capacity. The exact earlier-view allocation/failure boundary is now recorded by the narrowly granted adaptive view-work fields. Actual prescribed/data capacities are assigned immediately after their original allocations and transferred before success/error matching. Controls distinguish failure before allocation (zero capacities), after prescribed allocation (data still zero), and after data allocation (12 and 1 in the actual control), keeping the original error with no correction. Successful masks are not used to infer failed prefixes.

## Fixed helper/return overlap

Compose a conservative local bound by taking the maximum over the actual sequential call stacks: sum each simultaneously live fixed owner/argument/return slot's measured size, plus each live vector/string capacity times its element size. Do not assume move/return elision. The ordinary/native owners remain resident through all stages. K and Source readouts overlap; first descriptor scratch does not overlap lane construction; the verdict allocation persists and is reused.

For each source midpoint, count the borrowed interval, two by-value endpoint arguments, nearest-add context and returned Endpoint, exact-half result, and center destination. Their entered arithmetic/shift/copy events are recorded. For projection, count MemberEnclosures, both recipe results, hull argument/return, WideContext16, sum/midpoint/unit/raw Endpoints, Binary64Outcome and its reserved record/destination. The earlier C0 fixed directed/wide/sum helper schedule still applies where those routines are called; no 32-Endpoint shortcut is asserted. Support formation has one three-f64 array and two sequential actual hypot calls, each entered separately. Hypot's implementation workspace remains an external primitive/caller qualification, while its local calls and actual outputs are retained and certified.

The former support observable Vec collections are fixed six-slot/three-scalar storage; summary validation uses iterators instead of theta/resolution/bound Vec copies. Production no longer builds duplicate formatted proof-work strings; those dumps and test-only residual traces belong to the harness. Harness JSON, oracle clones and trace allocations are explicitly excluded from the production storage account and are retained only as evidence under the existing guard.

The existing coefficient-maximum helper is unchanged. Its concrete additional owners are the boundary Vec, span Vec, three ExactAccumulators, per-span controls, BinaryHeap nodes, best/result and split temporaries. This named input has no distributed loads, so it supplies one span; actual extrema evidence records subdivisions. Its existing 131072 subdivision and depth-48 limits bound the algorithm, but do not expose exact heap allocator capacity or internal arithmetic debit to this caller. Those retained-library/profile quantities, caller ABI spills and allocator overhead are separate explicit qualification obligations. No new numerical programme, host probe or guessed aggregate budget was introduced to fill them.
