# RV67 — minimum completion contract for I51

These are required design contents for the next independently checked proposal,
not selected names, compiled signatures or an implementation grant. Equivalent
closed interfaces are acceptable if their invariants and live ownership are just
as explicit. ROOT retains selection; the existing method stays binding meanwhile.

## 1. Formation and precision

Provide a row-family table covering primary components, prescribed components,
translation/support norms, component stresses, circular maxima and nonquantities.
For each, identify the physical readout(s), arithmetic sequence, rounding points,
raw units and final normalization. In particular, decide the norm projection rule,
not only the phrase “own norm readouts.” A concrete version of the proposed
non-maximum projection is RN1024(lo+hi), exact half, one specified RN1024 raw-unit
conversion, then RN64; other sequences need their own exact description. The
actual final-value certificate makes this sound without assuming the ideal
midpoint itself was correctly rounded. Fixed arithmetic failures refuse.

Keep the maximum's actual binary64 polynomial construction and actual bound
midpoint rule; its dual-physical maximum certificate is additional. Retain +0
rules, exact prescribed values and closed metadata/recipe identities.

Explicitly state the prospective changes to D1's p-formed recovery/magnitude and
binary64 derived-stress production language. Explain the relation of the revised
product values to native q_p/q_2p and stop entries; a direct final error proof is
not an observed p/2p agreement result. If direct certification is to replace a
product formation/process requirement, identify that replacement for ROOT to
select rather than claiming the old process was preserved.

Keep native selected p and P=2p truthful and unchanged. The certificate arithmetic
precision and product projection precision are separate provenance fields/facts,
not substitutions for receipt p. p512 floor selection depends on actual native
p=512 alone, uses that new owner's actual evidence and the existing force/moment
floor placement, and is followed by complete final-scale/class recomputation.
Actual new-K G5a evidence, operational source bits and protected final predicates
must agree with the final frozen candidate. Explain any method/replay/reader
wording impacted by this process change before public activation. No older
identity or evidence is silently reinterpreted.

## 2. Preparation and ownership seams

Specify a narrow section-preparation operation with only normalized D/effective-t
inputs, a fixed algorithm/version, an owned Spent return on every exit, and a
closed successful result. Successful data includes bound input bits and A/I/J/Z/c
bits with positive finite conversion/primitive checks; unequal rounded endpoints
are a distinct refusal. Geometry rounding authority can remain in FK, with
private result constructors and read-only bit getters across retained_api.
No endpoints, arbitrary rationals or source-agnostic radius constructor need cross
the crate. This scalar result alone is not a provenance credential.

Define PP's PreparedCase constructor from its validated capture, actual member
mapping, selected material and actual preparation result. It owns or explicitly
borrows one new PrimitiveSource and the matching facts/operational records.
It checks D/effective-t input bits, material E/G selection/case/basis identity,
node/member/station/support/individual-ledger maps, and exact new property bits.
Old built validation compares old capture with old build; new source is compared
with preparation. Do not remove old validation or make old facts authenticate a
new source. Compute operational L/ka/kt by the established binary64 sequence from
this new source. Preserve source encoding and a preparation/version association
for deterministic replay. Explicitly place these objects under the selected
RecordedInvocation/run/RetainedSolve identity checks once the new solve exists.

## 3. Two lanes, projection and final checking

Use exactly a closed internal AdmittedK/AnnularSource selection, not a callback
or arbitrary matrix/constitutive API. Describe one owner-bound product proof
draft constructed by RecordedInvocation after verifying run/solve/source/facts
identity. It owns both lane Spent returns and the native enclosure vectors needed
for later recipe checks. AdmittedK forms exact coefficient products and zero
coefficient differences; source recovery uses source coefficients throughout.
Both use the same owner's verified P=2p cache, actual scale vector, data mask and
bound. Missing/no-data cases retain the reviewed refusal/zero/uniqueness limits.
At most one correction per loaded lane is permitted; every correction is followed
by a fresh independently evaluated residual.

The same proof draft must serve projection *and* final certification. Do not call
today's residual-producing certify_product_case again after a separate projection
pass. Define how closed row descriptors are authenticated before projection,
how projected finite values are read, and how the final certificate is obtained
without a caller-supplied interval/value-radius pair. Endpoints can remain private
inside FK. The PP maximum builder only needs identified projected endpoint actions
and actual section data, not general numerical authority.

Choose whether lane view/data, alpha and epsilon are consumed/dropped after
recovery or retained. The current ResidualSpent only exposes a borrow; a compact
row-only result needs an explicit private consuming seam. Retain both work records
on every outcome, including success of K followed by failure of source. Keep the
original numerical cause plus accounting-fault state with the established
precedence. Do not overwrite first-lane work with the second lane or count a
zero-Delta pass as free.

## 4. Frozen candidate and observables

Choose and specify one concrete candidate representation. A small frozen overlay
is compatible with the proposed bound: borrow original row identities/metadata
and actual ancillary observations, own at most Q_final replacement f64 values
and typed maximum evidence/summary data, and expose closed row/evidence/headline
access to bind_rows, final_case, G5a and observable validation. All these consumers
must see the same candidate. Existing functions that take MechanicsEnvelope
require explicit bounded adaptation; they cannot silently keep reading the old
ordinary envelope.

Before freeze, regenerate all coefficient maxima using candidate endpoint actions
and the new section. Bind full result/entity/unit/location/interval/coefficient
scope; build complete maximum coverage and aliases from that same row set. Check
the native/source norm accuracy and published-component support guard separately.
For the private supported shape, mode is mandatory, parity follows its actual
producing presence, and a modulus-basis record appears exactly when selected
material capture requires it. Unsupported combination/pressure/user-review kinds
are not silently assigned NonQuantity or InputDerived. Prescribed components
follow the exact source map; current private imposed-motion exclusions remain.
Keep actual captured mode/parity/material observation semantics and metadata;
new mechanical proof does not retrospectively describe an ordinary observation
as a retained comparison.

Freeze prevents values, order, metadata, evidence and aliases changing while the
borrowed final rows/certificate are live. Document their lifetimes and the rule
invalidating certification after any mutation. A successful final transaction
consumes the certified draft and transfers the exact checked values/evidence into
publication. Preallocate/check everything that could fail before mutating the
ordinary fallback; do not rely on a second whole-envelope clone. On any earlier
failure, drop only candidate state and preserve the ordinary envelope and all
spent work. State how certification remains bound across the move and later
receipt/hash finalization. A lifetime annotation alone is not owner identity.

## 5. Local accounting and private implementation fence

A design-complete first private component should name its exact write set and
acceptance evidence. Plausible files are the listed FK product_certificate,
source_residual, final_case, origins and retained_api seams; PP retained_product
and its narrow observer/maximum adapters; and their bounded existing test modules.
Any refactor of ordinary maximum producers must show unchanged ordinary behavior
and be explicitly within the component. This is a required prospective fence,
not authorization of that list by this reviewer.

Keep the private observer/captured-entry scope, the exact same named request,
straight W1a supported laws and both modes. No public entry constructs/activates
the new producer merely because a private candidate passes. No native solver
schedule/factorization change, generic numerical engine, fixture recognizer,
neighbor search, exact-profile change, new library data, fallback/typed change,
receipt/schema/reader activation, new diagnostic/method selection, domain
retirement or tolerance/budget amendment belongs to this private component.
Exact-block-selected invocations retain no W1 preparation/numeric/draft work and
byte-identical publication; ordinary routing-observer storage is still counted.

List checked dimensions/layouts and live capacities for preparation, one new
source/facts/operational set, both residual lanes, retained enclosure vectors,
row descriptors, Q_final values, maximum/summary/metadata records, fallback and
later transfer/serialization. Include failed allocations and partial prefixes;
record successful capacity before subsequent fallible work. Count initialization,
conversions, comparisons, map visits, lane corrections/recovery and projection/
final checks. Current diagnostic certify_product_case does not debit the numerical
invocation meter: the new design must say which Spent fields are charged now and
how their association survives, rather than imply future public budget custody
already exists. No unpriced work is made free.

The 19-entry geometry schedule is a local operation count only. Keep the proposed
32 Endpoint scratch target unselected until a named layout covers caller/callee
copies, conversion temporaries and scalar/sum scratch. Seven f64 values omit maps,
work records, allocator layout and provenance. Preserve 20B/60B limits and current
failure precedence; full resource/RSS/caller qualification stays open.

Required private evidence: actual new preparation/source identity, selected p and
P, no stale ordinary facts/op fields, both lane widths/work and at-most-two
corrections, all 98/99 rows and exact final raw/SI/class/scale/predicate records,
actual maxima/support/headline evidence, new-K G5a, ordinary fallback bytes and
negative ownership/partial-failure controls. Later public F2a still requires
receipts/readers, both-entry and protected references, exact-block coexistence,
pressure refusal/no-pressure publication, resources and native Current witness.
