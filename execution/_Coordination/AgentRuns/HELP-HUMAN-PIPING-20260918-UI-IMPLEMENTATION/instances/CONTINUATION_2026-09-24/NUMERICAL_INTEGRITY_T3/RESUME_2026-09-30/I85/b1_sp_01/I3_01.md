## 3. SF-1: N-16 record by record (brief item 2; RR ruling 1)

**The finding.** RETURN §3.3 said "no difference" between the batch and the one-case Runs. That compared only (terminal, record count, selected precision). Record by record, **the second Run of every two-Run batch differs from its one-case Run in exactly three flags:**

| Record | Field | In the batch | Alone |
|---|---|---|---|
| p128 | `shared_built_here` | false | true |
| p256 | `shared_built_here` | false | true |
| p256 | `verification_shared_built_here` | false | true |

Every other field of every record is equal (`AttemptRecord`'s `PartialEq`), and so are the terminal facts. The first Run's records are equal to its one-case Run's, with no exception.

**The cause** is C2 §4's group-build sharing. D1.5 gives one stiffness, so one group. The first Run builds s128, s256 and v256; every later Run reuses them, so it does not build them "here". RR ruling 1 holds that these flags are N-16 outcomes.

**Where it holds** (`G/tests/b1_sp_head.lines`, `B1_SP_N16_RECORDS`), in both modes:

| Batch | First Run (position 0) | Second Run (position 1) |
|---|---|---|
| W-C2, A = {A, C} | A (request 0), 2 records, no flag | C (request 2), 4 records, the three flags |
| (C, B, A), A = {C, A} | C (request 0), 4 records, no flag | A (request 2), 2 records, the three flags |
| (A, A2) | A (request 0), 2 records, no flag | A2 (request 1), 2 records, the three flags |

**The test.** `n16_batch_against_one_case` (PP `retained_facade_tests.rs`) runs one `CaseBatchCall` over the prepared cases and each case's one-case Run, then for each Run:
- asserts the terminal facts equal;

- compares every record. A difference in the two flags is noted, patched on a copy, and the whole record is then compared with `==`;
- asserts the noted flags exactly: none at position 0, and exactly the three rows above at every later position.

It is called by the W-C2 test (replacing its old N-16 block) and by both SF-2 inputs.
