# Single-case requested/moving ownership composition

This is a proposed, conditional source composition for ROOT's generic captured ordinary single-case milestone. It is not full F2a C0, an enacted memory allowance or a qualified numeric byte estimate. The existing passing numerical producer is the basis; no alternative numerical search is proposed. The applicable frontier is the accepted private ordinary straight/source family, one actual case, no combinations/components, both modes, and actual complete ordinary/observation custody. Excluded routes keep their existing ordinary behavior; their full-F2a extensions remain mandatory before main/public qualification.

## 1. Identity, metrics and qualification premises

Let an allocation token be (actual construction event, site, copy generation). A move changes its owner edge, an Arc clone adds an edge, and a deep clone adds a distinct token. Equal bytes or digests do not establish sharing. At phase/event e, A(e) is the union of live tokens reachable from the actual invocation/caller roots and local temporaries; Old(e) is old backing still live during a moving reserve/shrink/transfer and not already in that union.

    E_req = max_e Σ[a in A(e)] weight(a)
    E_mov = max_e (Σ[a in A(e)] weight(a) + Σ[o in Old(e)] weight(o))
    E_stack = max_e sum of simultaneous source frames, arguments and return slots

The adopted M check must test both requested and moving expressions before the affected allocation. No M exists today; 4,026,531,840 B is only the recorded technical comparison target. Stack, allocator overhead, RSS, concurrent invocations and arbitrary downstream copies are separate claims. A base already larger than M declines W1 but is not made unpublishable and is not claimed to fit M.

Use P1/P3's site-specific V(site,T,k)=stride(T)*Cap(site,T,k), child-vector sums C, Arc/Box request functions, tree/deque/sort and moving laws. Every stride/alignment, constructor/collect/clone/shrink mode and toolchain/feature premise must be bound. Existing I51 local measurements are witnesses for their actual build only. Native width schedules include every reachable precision/failure path; observed p128 is not an admission premise. Checked/sticky work source replaces the historical global no-wrap programme; it does not supply byte/container/stack profiles.

Define P_final as the actual complete final product row count; its upper adds actual ancillary mode/parity/material presence, at most three. Withheld/unsupported coverage cannot be filled merely to attain that upper. Actual row order and count are checked before finalization.

A completed case has at most m successful preparation records (or an entered prefix ending in one refusal), nine preparation conversion outcomes per entered successful member, m old operational records only after the complete old prelude, and a new-evaluation prefix bounded by m. Actual capacities/outcomes are retained on failures; historical capacity slots are evidence, not additional live buffers. These maxima do not manufacture records on skipped branches.

## 2. Admission placement — early ordinary overlap is included

This ordinary-span profile is an explicit unqualified prerequisite until its actual source sites/container laws are bound. If absent, no allocating W1 observer is installed; ordinary execution proceeds once through its existing no-observer route.

**G-B, immediately before the old-source late capture.** Only after the single-case actual source_selected=false and positive observation custody settle exact-block arbitration may this gate authorize SourceParts/old-source capture. It consumes/replaces the capture reservation with a bound on the actual still-live frame:

              ∪ P1_old_source(e) ∪ OldFacts/Operational(e) ∪ O_finish(e)
              ∪ RefusalReserve(e) ∪ CallerCarry(e)]_k

R_late includes the BuiltModel/BasisStiffness, model/materials, boundary, LoadApplication, force/ledger/working/report/row owners still live at that exact callsite. O_finish covers the ensuing LoadCaseSolve transfer, final case/result maps, id qualification, cloned rows/metadata, preview evidence, diagnostics and MechanicsEnvelope construction. A missing bound skips old-source capture; it never reruns or blocks the ordinary solve. Observation storage can have an admitted prefix in a later exact bypass, but no old/new W1 source, native/proof attempt or W1 public diagnostic is allowed after exact selection. Exact output bytes and the legacy ledger remain unchanged.

**G-C, after the actual complete ordinary owner is returned.** Only here may R_complete replace R_late. PreparationPermit covers old source and new SourceParts/constructor together, section helpers, typed C3 prefix capture, source/map/encoding/operational ownership and every failed prefix. Missing profile/M/width/count or allocation refusal returns the owned ordinary base. No completed ordinary owner is fabricated for an earlier terminal; first-terminal recovery/suffix continuation is outside this bounded publishing frontier and remains a full-F2a obligation.

These are successive reservations of the same actual invocation, not three additive memory charges. Reducing a reservation requires actual owner Drop/transfer. Releasing memory never refunds either work ledger. Old SourceRecoveryBudget and W1 InvocationMeter remain separate.

## 4. Typed C3 capture and counter identity

Reserve the complete bounded event storage before each helper/evaluator stage: at most m prepared-member entries, 9m conversion entries, two lane terminal entries and at most P_final final-row conversions as an upper, refined by the exclusions above. A typed entered slot stores old operands before calling preparation; immediately consume the returned result/work into that slot without an intervening fallible step. A new OperationalSpent is stored immediately at its return. This preserves the F1 unequal helper/new prefixes, old errors and the old_coverage prelude/swap distinction. One start capability exists per actual case/attempt.

Native Run work remains the native meter's actual output. C3 proof and local operation counts are snapshots, not extra copies of native charges. For the single-case frontier the actual ProductCapture owns its cumulative adapter/capacity series. ProductAttempt.adapter is one immutable terminal snapshot, never a sequence of stage snapshots. On private success: finish all private gates, fix and check/charge the exact actual commit move plan, then freeze the adapter before any receipt construction/validation/encoding. Admit and charge snapshot storage/copy before its closed infallible final capture. On terminal private refusal: retain entered work and the precharge failure, if any, then freeze that actual terminal prefix. Do not relabel capacity accumulation as peak live bytes. Successful completion work is already merged into proof; separate ProductValuesFailure has its own retained work. Later receipt/validator/encoder/hash/staging and late-failure costs belong to a separate admitted PublicationWork owner. They cannot mutate the C3 snapshot or claim inclusion in it. The receipt serializer reads immutable evidence, so no receipt/hash-cost cycle exists. C3 Ready denotes private proof completion, not public selection: late publication failure retains the frozen Ready attempt privately, separate publication failure and unchanged ordinary fallback. Precharged commit moves are recorded as charged but unexecuted on that branch. Only final success executes them, without fallible allocation or further adapter mutation. Wider multi-case account ownership is not silently supplied by this single-case design.

## 5. Serialization and hashing contract

The current source_receipt hash route is not a bounded free primitive: json! clones payload structure, serde_json::to_string allocates text, checked_parse builds another Value plus duplicate-key HashSets, canonicalization allocates another String and per-object UTF-16-sorted key vectors; each parent key vector remains live during recursive child rendering. Taking only the maximum single object would undercount. Number/string formatting also allocates. Headless invokes related helpers repeatedly. The profile must count these literal owners if the current path is used.

The primary proposal retains and fully accounts this existing clone/parse/render path. There is no demonstrated contract, failure-path or qualified-fit limitation requiring a new canonical sink, so canonical_json source changes and bounded.rs are outside the minimal fence. The profile binds the existing parser/validator/renderer, duplicate-key HashSets and their key clones, nested ancestor-key vectors, sort temporaries, escaped-string and number strings (including digits/exponent/rendered temporaries), output old/new growth and bounded traversal stack. It must cover every reached failure prefix and concurrent owner. A logical serialized length alone is not its heap or stack bound. If qualification later exposes a concrete unbounded premise or fit failure, return that exact witness and the smallest correction; a new sink is only a separately reviewed possible optimization, not an automatic prerequisite.
Use the selected closed C1/C2/C3 grammar to derive length. Text(b)≤6b+2, SB/B=18 including quotes, H=66, U≤16 decimal bytes, bool≤5, null=4. For objects add exact fixed-key lengths, colons, commas and braces; for arrays add element bounds plus commas/brackets. Take the maximum over actual allowed error/result branches. Bound original Text payloads from actual resident length or the source field's static literal plus bounded dynamic operands before it can be produced. Unknown Debug/Display growth is not a profile. Native encodings retain P1's exact K4SRC/K4STF/K4LED formulas and checked written widths.

The selected definition bytes/hash can be embedded as fixed data. Any dynamically parsed table/cache is separately owned and charged at its real first initialization and later residence; static spelling does not make a heap singleton free. Snapshot capture, hash byte count and typed schema encoding failure all preserve the same ordinary transaction.
