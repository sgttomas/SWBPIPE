It does not expose a precommit public receipt transaction, qualified memory permit, full C3 typed capture or caller reservation. Those are proposed changes below, not already implemented facts. The public path must run the ordinary solver once; it cannot call the existing prepare_observed wrapper after another ordinary solve.

## Counter and evidence identity

One native InvocationMeter spans actual work; 20B/60B remain stop thresholds with honest overshoot. Reuse integrated checked/sticky WorkTotal and stage status, not the superseded global static no-wrap programme. Native Run totals are serialized once. C3 work is not assigned an invented LME price. ProductAttempt.adapter has exactly one terminal immutable capture from the actual ProductCapture account. Success freezes after private gates and checked precharge of the exact commit move plan, before receipt/validator/encoder work; terminal refusal freezes its entered prefix. The freeze operation and its storage are themselves admitted and charged. Later publication work has a separate owner; it is never retroactively inserted into this snapshot. Precharged but unexecuted commit moves remain identified privately on late publication refusal. The single-case frontier permits the existing capture owner without a multi-case reset/fabrication. Wider invocation ownership is a mandatory extension, not assumed solved by this design.

F1 prelude state and old/new vector transition are explicit: captured_prefix before validated old inventory, complete after that prelude; old results can be errors. Each helper's inputs/result/work/conversion prefix is retained at return before subsequent copy failure; each new evaluator result is retained before the later preparations.push check. Do not infer entered work from successful preparations/associations length. Registered preparation/source/receipt hashes have their separate acyclic scopes.

## Concrete qualification gaps to close in the composition

1. Bootstrap stack/depth and actual resident Value/container census, including large spare capacities, cannot be supplied by J alone. Bind the real captured parser/canonicalizer and ordinary/caller shapes to a finite traversal profile before allocating census storage.
2. P1/P3 are reviewed symbolic owner expressions; final site-specific Vec/String/Arc/Box/tree/sort/moving and helper-frame coefficients still require a source/build profile. Local I51 sizeof measurements are observations, not universal capacity laws.
3. Typed C3 capture and public serialization are missing. The proposed receipt encoder must account and reserve every array/string/error-prefix and the current source_receipt json!/to_string/checked-parse/canonicalize chain, including nested key vectors and moving String growth. No replacement canonical sink is necessary on present evidence.
4. Headless owns additional request/payload/runner/mechanics/export copies and canonicalization; direct transfer does not cover them. The exact completion expression will identify each actual site.
5. Native uses accepted corrected U_J + caller overlay only at actual overlap: resident R_J remains in U_J until actual last-owner Drop, never added twice. Context multiplicity/tails and attributable task-map backing remain unqualified under I53/RV70; one logical start does not prove one actual worker. Permits bind actual invocations/jobs.

The preparation-only ordinary operand / mixed-combination mismatch and exact-profile producer are mandatory later full-F2a capabilities. C3 does not currently supply those routes. They are not expanded in this checkpoint and cannot be hidden by extra solves, unmarked preparation or a new availability exception.

## Explicit caller barrier and publication freeze

Keep the existing `run_linear_static_preview_value_with_mode` entry and its existing wrappers ordinary/W1-disabled. Native direct and worker callers at apps/desktop/src-tauri/src/lib.rs:1562 and :1694–1695 therefore cannot inherit DirectPp admission. Add the separately named proposed PP `run_linear_static_preview_value_with_retained_direct` entry, which can obtain only a source-qualified DirectPp permit, and a closed context-taking `run_linear_static_preview_value_with_retained_headless` entry used only by a new explicit headless retained entry. Existing headless and typed entries also remain W1-disabled. There is no Default caller, Value-to-DirectPp inference, or automatic upgrade. These are proposed API names, not reserved public policy identifiers. Native source changes are unnecessary for this barrier and remain outside the fence.

Headless can call its new PP entry only with its actual source-reviewed completion context; a label or externally supplied byte total does not qualify it. Shared internal ordinary execution remains single-pass. A source-call inventory/control must fail if either existing native caller reaches either new retained entry or if any shared legacy wrapper mints a retained permit.

The exact commit move plan (actual row and staged metadata slots, including the receipt slot transfer) is fixed and precharged before the single adapter freeze. Its execution is deferred until receipt/hash/validation success. Receipt creation, reader maps, canonical encoding, hashes, publication diagnostics and late refusal evidence belong to separately admitted PublicationWork. A C3 Ready attempt may therefore remain privately Ready while public selection fails; preserve that frozen attempt, the separate publication failure and unchanged ordinary owner. Do not rewrite C3 stages or claim its adapter snapshot captured later hash work.
