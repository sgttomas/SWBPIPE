# I65 U4 G6: the identifier-class audit

**Why.** RR "RV87 on S-2 in G5 part 2: NOT CONFIRMED; a class-wide identifier audit goes into G6". This is the third round of underpriced identifier copies, so this audit fixes the **class**, not the sites.

**Scope.** Every identifier-bearing copy on the D1 call graph with positive multiplicity in the T08 text run (the part-2 run at `1e323058f3`). A copy is a `clone`, `to_string`, `to_owned`, `into`, `String::from` or `push_str` of an identifier, or a `format!`/`write!` placeholder that carries one. Identifiers include result, diagnostic, case, member, support, node, load and source ids, references, names, keys and labels.

**Outside TAV, priced by other families (RV87 N-1).** The lexicon's `TEXT_NAMES` name filter classes some identifier copies as data clones or non-literal `.into()`, so they are not TAV sites and not in this table: for example `qualified.clone()`, `ids[&row.id].clone()`, `pipe.from`/`pipe.to.clone()`, `input.behavior.clone()`, `entity.into()` and `case.into()` (`PP/lib.rs:2779`, `:5561`, `:5564`, `:7050`, `:7117`, `:7127`; `source_receipt/rows.rs:318`; `source_receipt.rs:815`). Their bytes land in owners that other families price: row text in O (Text(row), with 4 × 1,024-B refs) or T25, and diagnostic refs in Text(diag), at 152 B per ref.

**G6 repair (RV87 SF-1 to SF-3; RETURN.md, Addendum 2).** The table now covers every identifier-bearing candidate **whatever rule would price it**, and TEXT fails on a stale site key. That added 48 entries (§2a), including the node-DOF label (SF-1) and the adapter's `copy(s)` (SF-2). The 25 `suffix = stable_suffix(<id>)` rows are relabelled IN128 (RV87 N-2), and after RV87's confirmation the last two at `retained_product.rs:2332`/`:2351`, with `:2351`'s `station_id_location(loc)` as COMP (RV87 G6r N-2; labels only, the bytes are unchanged; RETURN.md, Addendum 3).

**Result.** 795 (site, expression) entries over 641 sites (G6: 747 over 599). Each is priced by its **source**, never by its spelling. No run row is lowered, and TEXT is complete. The in-build maximum stays under 0.9 M: 0.8929 M dense after the repair (QUALIFICATION.md §3).

## 1. Method

1. **Candidates come from the run's own site table,** not from a name rule. At G6, a site was a candidate when either:
   - its lexicon receiver, `push_str` argument or `format!` placeholder was priced by an identifier class rule (`ident`, `ident_debug`, `result_id`, `composite_id`, `refs_vec`); or
   - its text names an id, ref, name or key field. This catches copies a rule priced under another class.
   
   That gave 745 entries; the enforcement in step 4 found 2 more `push_str` arguments, for 747.

   **G6 repair (RV87 SF-3): the candidate set is by type, and the run computes it.** `text_budget.py` (`_run_records_g6r/`) makes every expression at a positive-multiplicity site a candidate when any of these holds, **whatever rule then prices it** (identifier, integer, f64, static, a site override or a lexicon class):
   - its text names an id, ids, ref, refs, name, key, **label**, **suffix** or **identity** (`ID_TOKEN`; any receiver or call, so `integrity_dof_label(..)` and `schema_ref()` are candidates);
   - it is a bare parameter of the enclosing function typed `&str`, `String`, `&String`, `impl Into<String>`, `impl AsRef<str>` or `Cow<str>` (a helper that copies whatever text its callers pass, so `copy(s)` is a candidate whatever `s` is called);
   - the first argument rule that matches it is an identifier class or `refs_vec`.
   
   Excluded: `{:e}` and `{:x}` placeholders (numbers), literal copies and `diag_literal`/`from_literal` rows. The repair's run found 48 candidates outside the G6 table; each was read at its site and added (§2a), for 795.
2. **Binding resolution** (`_run_records/id_audit/id_resolve.py`). For each candidate, the copied expression's base and its nearest binding in the enclosing function: a fn parameter, a `for` pattern with what it iterates, a `let`, a closure parameter, or an `if let`.
   - For parameters, `id_callers.py` lists every call site's argument in the snapshot (`id_callers.txt`).
   - So the source is read from the binding and the callers.
3. **Pricing** (`id_rules.py` provenance rules, `MANUAL` site resolutions, `id_table.py`). Each entry gets a source class and its bound:

|---|---|---|---|---|

   - **Never lower.** Each entry is priced at max(its previous bytes, its source bound). Debug (`{:?}`) placeholders keep the run's Debug law, 2 + 6 × bound.
   - **Repair: site overrides.** Where a `site_size`/`site_aggregate` override prices a `format!` site, the expression's generic class never priced it, so its entry is the source bound and the site keeps its override as a floor (`size = max(override, audited evaluation)`): `lib.rs:13834` (150), `source_receipt/source.rs:27` (188) and `:51` (129) keep their override bytes. At a `lex_site_size` site the entry is at least the site's class. Its "priced before" column reads 0 for those three.
4. **Enforcement in the run** (`_run_records/text_budget.py`, `text_args.g4.json` → `id_audit`).
   - The audit table is consulted first, per (site, expression).
   - An identifier-class rule hit at a positive-multiplicity site that is **not** in the table is reported as `id-unaudited`, which makes the run incomplete.
   - The first G6 run was incomplete on exactly 2 sites, both `push_str` arguments that the candidate scan had not covered: `retained_product.rs:3267` and `:691`. Both were audited and added, and the run is now complete.

   **G6 repair (RV87 SF-2, SF-3; `_run_records_g6r/text_budget.py`):**
   - **Every candidate** of step 1 (by type) at a positive-multiplicity site must be in the table, whichever rule would price it, or the run reports `id-unaudited` and is incomplete. This covers placeholders at sites a `site_size`/`site_aggregate` override prices (their audited evaluation then applies when larger) and lexicon rows a `lex_site_size` class prices (the audit entry applies when larger).
   - **Stale keys fail.** A key of `site_size`, `lex_site_size`, `site_total`, `site_zero`, `site_from`, `site_aggregate` or `id_audit` that matches no inventory or lexicon row at this basis is reported `stale-key`; an audit entry that names no expression at its site is `stale-audit-entry`. Either makes the run incomplete.
   - **Controls** (`_run_records_g6r/controls/audit_controls_g6r.out.json`, `audit_controls_g6r.py`): each one change to a copy of `text_args.g4.json`, the whole run at D = 14,734. The unmodified copy is complete; each of the eight changes makes it incomplete with exactly its own finding:

   - **Residual.** The candidate predicate is syntactic. A local alias bound from an identifier under a name with no token above, outside a text parameter, is not a candidate (for example `let x = &row.id; format!("{x}")`); the G6 binding scan and RV87's by-type probe found no such copy at this basis. A site key that has drifted onto another row on the same line is not detected (the check is presence per line). **Carried as a re-qualification obligation** (RV87 G6r N-1; QUALIFICATION.md §11).
   - **Keys ignore comments** (RV87 G6r N-3). A `//` line comment inside a placeholder's text is stripped from its audit key (`audit_key`, `id_table.py`), so editing a comment no longer fails the run. It changed one key, `lib.rs:1149`'s; no byte moved.
