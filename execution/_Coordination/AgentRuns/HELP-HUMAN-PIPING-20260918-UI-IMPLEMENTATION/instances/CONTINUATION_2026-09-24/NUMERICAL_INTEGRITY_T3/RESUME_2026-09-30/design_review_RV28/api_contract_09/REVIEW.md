## Context and information ownership

The old Counts/Sizes pair cannot describe arbitrary retained Case/model text,
the whole-family parse peak or actual launch bytes. The proposed enriched
capture explicitly obtains those premises instead of inferring them from
structural counts.

Its lifetime shape is coherent: Case/Model/input/invocation carry lifetime 'a;
source and Counts are separate temporary borrows. The returned context owns
checked scalars/fixed arrays and therefore can survive the existing source drop.
V398 has the necessary live objects; V399 need not be delayed.
The compiler-level lifetime/API check is still future implementation evidence.

The inspected source exposes borrowed member/spring/directional/load/support
slices and body_count without creating their child vectors. Counts already
contains free_dofs, pattern/profile counts, blocks, quantities and encoding
length. Thus avoiding a new free_dofs/layout/encoding/graph call is both possible
and necessary to avoid unaccounted construction. Source-ID lengths can be
accumulated over existing borrowed strings. The generic VR adapter's u=0 and
zero prescribed values follow its own source_parts, not H/no-spring analogy;
actual s/d and every load term remain required.

Counts provenance must remain tied to the same captured Model/source/counting
operation. Basic n/f consistency alone is not proof that an arbitrary supplied
h or block count came from it. Private fact construction and the later
CONTEXT-TRANSLATION review must preserve that binding, as the contract requires;
no new graph replay is warranted just to describe an already computed result.

Described loaders are the correct ownership point: existing raw text, Value
and typed result coexist there. Case alone cannot recover discarded whitespace,
ignored fields, escaped source bytes or earlier family cases.
A fixed-size aggregate/ten-family summary design can represent the needed
source uppers without retaining all raw data or cloning/reparsing models.
The proposal does **not** claim a zero-cost implementation: any added
descriptor/hash/traversal storage or changed collection/drop edge must be
accounted and reviewed. Loader facts must bind the actual input/selection;
a matching family label alone is not provenance.

The narrow cases.rs/Args/test-call edits remain ungranted until explicitly
included in implementation scope. No stale estimate loop, partial subtotal,
caller-provided byte allowance or missing-cell zero is permitted.

## Independent five-field derivation

Let all caller-only alternatives and retained join addends use the corrected
owner ledger and overlay. For fixed nonnegative premises:

    Full = max(C_j, A_s+K_all, A_i+O_all)
    Selected128 = max(C_j, A_s+K_128, A_i+O_128).

The common C_j set explicitly retains the whole prefix and late caller
alternatives even if some branches are unreachable after a successful128
selection. That is conservative named padding, not a prediction of selection.
The returned O terms are stationary requested-byte uppers; only the currently
growing caller or kernel phase gets its active-old increment.

The proposed diagnostic fields have distinct meanings:

    model = M + P_pub
    fixed = B0 + C_cut + E_lane + LIST78 + T_ctrl + P_pub
    decide = max_v complete moving R7 transient(v), v=256,512,1024,
             excluding Kpad, current Report and caller.

Model retains the old standalone-Model-plus-publication meaning. Fixed is a
comparison-interface baseline under declared Base padding, **not** a claim
that all those owners remain alive during the whole process. It is not added
again to Full/Selected128. Decide is a named transient, not the admission
decision or an incomplete replacement for the full certificate/schedule union.

The strict ordering follows algebraically, without adding1 or forcing totals:

1. P_pub cancels in fixed-model, leaving
   B0+(C_cut-M)+E_lane+LIST78+T_ctrl>0 under C_cut>=M and B0>0.
2. The comparison addend contains at least
   C_cut+E_lane+LIST78+T_ctrl+P_pub. With
   O_128>=B0+S128+U128 and S128+U128>0, that comparison join exceeds fixed.
   Selected128, a maximum containing it, also exceeds fixed.
3. If the full source-site roster/phase alternatives contain the shortened
   roster with nonnegative additional owners, then K_all>=K_128 and
   O_all>=O_128. Monotonicity of addition and max with the identical C_j set
   proves Selected128<=Full.

These are **conditional owner-subset premises**, not an already evaluated193
proof. In particular O_128 must actually be instantiated with the inherited
named Base/Shared/Solved padding and selected finish/certificate/error-prefix
coverage; it cannot be a narrower outcome size while the proof assumes more.
Full/short rosters retain their minimum backing allocations. If an
instantiation violates a premise, expose the defect/missing fact; do not enlarge
a total solely to repair test order or set an impossible conditional path to0.

## Six remaining cells are real release prerequisites

The contract correctly identifies:

1. **KERNEL-193:** actual s/d/load/ID/source construction and full/short solve/
   return/Base/R7 terms using the existing generic equations.
2. **CALLER-FAMILY10:** each actual family's raw/typed prefix, escape/shape

3. **CALLER-193:** all row/control/Exact/diagnostic/record/floor/RCM/sparse

   springs, multiple bodies and partial returned-error construction.
4. **REACHED-TYPES:** the untouched-node spring set is
   BTreeSet<(u32,usize,usize)> in scale.rs:70–88. Neither the pair-key set nor
   RF-LARGE's empty-spring premise supplies that type's request. Prove emptiness
   on the relevant fixed inputs or supply the exact missing fact if reached.
   Directional parity retains its early returned-String branch. This review
   asserts neither universal reach nor emptiness and commissions no probe.
5. **RESULT-5-CHECK:** evaluate all193 tuples and the subset inequalities,
   compare overlapping12 and external12 under matching exact/upper policies,
   and preserve checked widths and one-active-grow placement.
6. **CONTEXT-TRANSLATION:** actual fixed/borrowed plumbing, any added allocations,
   canonical-normal binding and separately authorized call-site migration.

B<=N and b<=f are valid population uppers, not recovered exact graph counts.
They may replace unknown metadata only in explicitly tagged policies and
expressions proved monotone in those quantities. They cannot be substituted
inside an exact identity as though equality held, used to reconstruct W1 h,
or used as SD's numeric skyline. A static upper-policy result can differ from
a later exact-count result; equality requires the same policy, otherwise
validate dominance. The proposal states this limitation correctly.

Reference profile/fact IDs must remain compatible across inputs, kernel and
caller composition. Current Sizes observations cannot silently overwrite a
historical reference fact. The selected external final-build/reliance gate,
ordinary CLI/CI, all193 assertions, wider213 source-domain/refusal coverage and
measurement/admission requirements remain intact.
