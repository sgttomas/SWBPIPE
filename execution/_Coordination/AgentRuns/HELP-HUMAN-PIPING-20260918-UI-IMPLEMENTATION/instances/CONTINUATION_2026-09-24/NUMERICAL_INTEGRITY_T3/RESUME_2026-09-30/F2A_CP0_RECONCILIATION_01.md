Before selecting bounded derivation work, resolve these cross-plan questions:

   be silently labelled pre-existing or placed outside every admission/accounting
   boundary. Preserve old terminal ordering/bytes, exact-source budget behavior,
   no-attempt coexistence and the new method's work/memory scope explicitly.
2. **Native caller coverage.** I29 names direct-PP and headless windows; I30 requires
   native direct/job W1 witnesses. Native src-tauri/src/lib.rs:1557–1564 creates a
   request and calls serde_json::to_value on the returned MechanicsEnvelope; job

   alias native to a PP-only window or imply whole-process RSS coverage. Identify
   the exact additional caller reservation/proof or an explicit supported scope
   that still satisfies F2a's native obligations. Webview/unrelated state and
   arbitrary later consumers remain separately named exclusions, not hidden terms.
3. **Publication coordinates and recipes.** Preserve the selected design_a1
   addendum: absolute binding is centered on n in SI, raw y/U stays provenance,
   display intervals convert outward (or compensate normalization offset), and
   relative raw values require the separate H_U predicate. A round trip is not
   zero publication/normalization error. Check each proposed recipe against its
   real product operands and rounding; no re-formed rounded formula is its oracle.
   Open recipe/arithmetic proofs remain open until independent derivation.
4. **Attempts, combinations and accounting.** A candidate/verification projection
   must conserve role/reuse/failed/own/shared work and actual case/invocation

   Assess whether the accepted D1/D2 contract admits the projection as proposed.
   Mixed ordinary/retained combinations need source/custody/cache and availability

   New facade arithmetic needs an explicit bounded resource/accounting contract;
   existing LME prices are not invented for new operations.
5. **Custody and native unsafe inputs.** Legacy typed calls remain ordinary unless
   a separate actual-custody API is selected. S5-R's captured digest-unavailable
   fallback is an accepted rule needing implementation; headless raw export
   unavailability is already distinguished. Native registration/AnalysisRun
   currently prevents unbound raw display. Do not pretend a PP fix resolves it,
   forge hashes or label unregistered data Current. Identify the smallest concrete
   owning scope/representation choice, and whether it blocks F2a or is a separately
   carried T3 obligation under the accepted design.
6. **Proof scope and next grants.** Reconcile the actual source/caller rosters,
   proposed API/ownership changes, shared pure kernel algebra relocation and the
