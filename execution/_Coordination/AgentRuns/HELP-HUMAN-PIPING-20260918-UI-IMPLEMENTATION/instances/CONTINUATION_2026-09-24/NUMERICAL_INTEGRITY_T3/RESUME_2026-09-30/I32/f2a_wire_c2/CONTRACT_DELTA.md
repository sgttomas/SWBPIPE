## 1. Wire vocabulary and bounded evidence

All objects below are closed. `U` is a nonnegative safe integer; source indices additionally fit the target u32/usize width before conversion. `I32` is an exact JSON integer in the signed i32 range. `B` is 16 lowercase hex bits of a finite binary64; nonnegative numeric evidence uses canonical +0. `H` is lowercase SHA256 hex. `C` is one of UX,UY,UZ,RX,RY,RZ. `Dof={node:U,component:C}` uses the explicit node map. `Kind` is translation/rotation/force/moment. `Text` is the **exact owned UTF-8 payload** of a typed source field, never Display/Debug rendering or a parsed diagnostic. Its byte length must fit the admitted field and aggregate UTF-8 counts before copying/formatting; no new numeric cap is chosen here. Readers do not interpret free text as a trigger or proof.

`OwnerRef={kind:"case"|"combination",index:U}` addresses the authored-order receipt case/combination array; resolve it to that entry's full basis_ref and require agreement with source owner ids. `DiagnosticRef` is a nonempty full diagnostic id, unique in the actual envelope. `RunRef` is a global U assigned by the actual recorded-call execution sequence as specified in §4, not a case array index.

Null is permitted only where listed. Empty vectors mean actual empty evidence, not missing capture. No JSON float carries a counter. Nonfinite typed error values cannot be encoded as B; the whole W1 receipt declines with receipt_encoding and preserved ordinary diagnostics, rather than zeroing/truncating that payload. That path is not a new source-domain rejection.

`Reason={space,tag,...payload}` has exactly the fields below for its discriminator. Variant names are stable proposed snake_case translations, not a catch-all. Diagnostic explanatory text stays outside Reason. Field arrays use actual counted lengths and finite input/copy bounds. Unexpected new native variants require an explicit map update; they cannot silently become `other`.

## 3. Source registries and concrete maps

C2 replaces duplicated per-selected source_binding with a body-level `sources[]` and references. A **case** source is registered after PrimitiveSource::new and map validation succeed, **regardless of final selected/unavailable outcome**; a **combination** source is registered only after the existing operand checks and CasePrep::combination succeed, as specified below. `SourceRef` is its array index. There is no public reference to an absent private registry. Combination pre-source refusal instead uses the explicit Call result in §4; it does not masquerade as this case SourceError branch.

`body.material_bases[]` contains `{index:U,selector,materials:[Material],case_indices:[U]}` in first-use case order. Selector is `{kind:"base"}`, `{kind:"named",id:Text}`, or `{kind:"temperature",kelvin:B}`. It is derived from actual modulus_basis_ref / normalized modulus_basis_temperature, not a caller label. Material is `{input_index:U,id:Text,elastic_modulus:B,shear_modulus:B,shear_origin,selection}`. Include only materials used by admitted members, retaining their order and input_index in the actual chosen normalized material array (request-level overrides versus model materials); do not invent G for an unused material. Selection is `{kind:"base"}`, `{kind:"named_point",point_id:Text}`, or `{kind:"interpolated",lower_point_id:Text,upper_point_id:Text,target_kelvin:B}` bound to the actual resolved pipeline. shear_origin is `{kind:"explicit_g"}` on preview or `{kind:"derived_e_nu",poisson_ratio:B,constitutive_basis:"homogeneous_isotropic_E_nu_v1"}` on exact mode: pressure_material.rs deliberately derives G from the selected common E/nu pair and ignores redundant authored G. Record that actual result, with its exact point/interpolation provenance; never substitute base G. A basis sharing a selector does not excuse changed E/G bits. 0.4 member-pair inputs are outside this F2a contract.

`SourceBinding` is a **closed union discriminated by owner.kind**, not a common case-shaped load object:

- **CaseSource:** exact members `{index,owner,material_basis_ref,kernel_source_sha256,stiffness_sha256,id_maps,body_membership,layout,stations,supports,constraints,nodal_terms,section_terms}`, with `owner={kind:"case",case_index,case_id}`. The map table below specifies this branch.

Each operand resolves to a **CaseSource** for the stated case; repeated cases, factors and source refs remain repeated. representative_source_ref is exactly operands[0].source_ref. This branch has **no nodal_terms or constraints value array** and no material/map copies that could be confused with combined load data.

The representative first CaseSource supplies the immutable node/member/spring/support id maps, material/operational section descriptors, body membership, layout, station declarations and support groups used by CasePrep::with. Resolve these through representative_source_ref; compare every operand's full stiffness bytes, layout, stations and supports as the existing API does. The constrained **DOF set** comes from that common stiffness; the representative's constraint **values** are not the combination's prescriptions. Product common model/map/material/section association checks remain those already required by C1/B1, without turning different load inventories into OperandsDiffer.

Combination load provenance is exactly the ordered expansion of references `(operand_index, term_index)` to each operand CaseSource.nodal_terms in its canonical source order. These provenance sequences are derivable and **not serialized as binary64 products/nets**. No combined PrimitiveSource is invented; factors multiplying to overflow/underflow in binary64 are never first formed in binary64 for the ledger.

kernel_source_sha256 is raw SHA256 of the existing K4SRC bytes for CaseSource and existing K4CMB bytes for CombinationSource. K4CMB retains ordered factor bits and complete operand source encodings exactly; ledger_sha256 in CombinationSource is raw SHA256 of its separately prepared K4LED bytes and must equal selection.ledger_sha256 whenever selected. Source identity remains C1 H(`retained_precision_source_mp_v2`, exact union object **without its own index**), including owner.kind, representative_source_ref and each ordered operand's source_ref **and** source_identity_sha256. A different case owner with identical K4SRC bytes is still a different product association. One actual invocation meter joins calls; no reset/refund.

C1's attempted retained mechanics combination entries gain `call_ref:U`. `retained_selected` requires result=runs, non-null run/source_ref, its own selected source/hash/ledger and exact row coverage. For `retained_unavailable` caused by pre_source_refusal, `run:null`, `source_ref:null`, and `reason={code:"combination_unresolved",phase:"preparation",cause:Call.result.reason}`; this explicitly adds the four typed pre-source CombinationReason causes to §2's preparation wrapper, rather than mislabelling them as SourceError or post-work kernel failure. It has no own source_identity_sha256 or selected payload. Its operand provenance comes from requested_operands, not a fabricated operand_cases/source binding, and its effective cache_inputs/imports are empty because no cache merge occurred. For a later unavailable run, source_ref and run remain mandatory and resolve normally. Ordinary/base_withheld combination entries have no W1 call_ref, Run or new source. Existing diagnostics and the original ordinary fallback/availability rules are unchanged; this representation never authorizes silent row withholding.

`Group={id,call,first_source_ref,source_refs:[U],stiffness_sha256,preparation:{kind:"ready"}|{kind:"refused",reason:Refusal}}`. Case-batch groups are call-local, assigned at first full-stiffness-byte equality, preserving current linear search order. Groups from separate calls remain separate even with identical hashes. The producer compares **full K4STF bytes**, the reader can verify source/maps/record consistency, and implementation evidence warrants actual equality/cache use. Digest equality alone cannot create a group or authenticate a producer. Repeated source refs in different owner cases remain distinct provenance owners.

`Build={id,group,slot,origin:{call,run,physical_record,phase:shared|verification_shared},state:success|nonbudget_failure|budget_failure,reason:null|Stop,work:U,stages:Stages}`. A build id is allocated exactly when obtain/obtain_verify actually attempts a missing slot, not on source equality, case entry or use. Slot is s128/s256/s512/s1024/v256/v512/v1024. A success or nonbudget_failure is cached; budget_failure is never a resident slot. Actual build metadata must be captured where Spent and built=true exist, because failed/stopped records do not otherwise prove whether a failure was cacheable. No new prices or counter semantics.

`SlotOrigin={slot,build:U}` arrays are in fixed slot order and contain only resident slots. A physical record gains `shared_build_ref:null|U` and `verification_shared_build_ref:null|U`: null iff that phase did not request a build/cache; a zero-cost requested slot still has an origin. For built=true, the build origin points to this exact run/record/phase; for false, it points to the actual older resident build in that group's before-state. Work/stages/state match the build record. A non-budget failed slot can be consumed by multiple unavailable runs; every one counts the full case charge and zero invocation shared increment. A budget failed slot can recur as a **new** build id on a later case. Ordinary/preparation zero inherited LME is not zero cost.

Within a batch, update the live group's slot inventory at each actual successful/nonbudget-failed build. A selected solve snapshots this inventory at its finish; `selected_snapshot` is tied to that run, not to the batch's eventual final cache. Unresolved/refused runs retain origin and cache-after evidence even if no RetainedSolve survives; this preserves unavailable-build associations. These descriptive inventories are not actual factor clones.

For a combination Call with result=runs, `Group` additionally has `imports:[{operand_index,selected_run,slot,build}]`. operand_index addresses that Call's requested_operands and the identical CombinationSource.operands position. Prepared ordinary operands import none. For each slot take the first occupied selected-operand finish snapshot in authored term order, exactly GroupCache::merged; preserve its original build id/group. The new combination group's own newly built slots use its new group id. Imported builds can be reused only after the existing stiffness/layout/stations/support checks; their origin remains the actual earlier group, not rewritten as built here. `cache_before` is the chosen import set. New combination cache-after is private to this combination; it never backfills operand snapshots or later combinations' imports. A reader checks all references point backward except a current run's newly built slot, and that no non-import cross-group reuse exists. C1 cache_inputs is now a **derived compatibility view** of these checked selected operand snapshots/build refs, not a second independently writable ledger; no duplicate cache_inputs payload is serialized. For pre_source_refusal its derived view is empty and there is no Group/import inventory. Individual Build stages reconcile with the physical record's aggregate shared_stages as solve-shared **plus** verification-shared, never as two additional work charges.

This closes the structural association hole for unavailable runs. It does not make serialized provenance self-authenticating, establish upstream no-wrap, or authorize an unbounded trace. G5 checks this graph plus C1's exact partition only after the admitted producer/source/build warrant. Replay and mutation controls verify actual implementation use.

## 6. Chosen minimal terminal-evidence API

Select the **additive execution-result path**, not adding an attempts field to legacy CaseOutcome::Refused. Consumer inspection finds complete `{refusal,geometry}` patterns in VR records.rs:79 and FK factor_tests.rs:248/references_tests.rs:257. H attempts_of intentionally returns [] for Refused; VR current records likewise do. A direct field addition therefore changes unrelated consumers and risks rewriting historical observations.

Proposed internal/public-in-purpose shapes (not compiled code):

```
ExecutionOutcome = Selected(Box<RetainedSolve>)
                 | Unresolved { reason, attempts, geometry }
                 | Refused { refusal, attempts, geometry }
RecordedCase { outcome:ExecutionOutcome, origins:RunOrigins }
solve_cases_recorded(sources, case_limit, meter, admitted_origin_context)
    -> Vec<RecordedCase>
```

One private schedule core returns ExecutionOutcome and moves attempts through every finish_terminal branch. Existing solve_cases/solve_case call that same numerical core and immediately erase the additional refusal attempts **before appending each legacy outcome**; they return the unchanged CaseOutcome type and produce the unchanged H/VR records. The recorded entry retains those owned attempts and origins for F2a. No double schedule, cloning refused attempts, report retention or new solve. Nonrecorded mode must not allocate origin inventories; only the fixed branch/owned-vector move is new. Admission reserves all recorded-mode inventory capacity upfront.

The source-combination recorded entry returns the closed additive `RecordedCombination = PreSourceRefusal { stage, reason, requested_operands, meter_before, meter_after } | WithRun { source_ref, outcome:ExecutionOutcome, origins:RunOrigins }`. PreSourceRefusal is produced at the actual operand-validation/combined-ledger return before a valid combined prep exists; it moves the typed reason without constructing source/group/Run evidence. WithRun begins only after valid combined prep/source registration and retains later group/preparation or schedule outcomes. Its meter snapshots are represented by the containing Call/Run, as above. This uses the same checks and schedule core; existing RetainedCombination::solve projects PreSourceRefusal to its existing Unresolved{reason,attempts:[]} and erases additional post-work refusal evidence exactly as before. C1's PreparedCaseSource/CombinationOperand API extends this same implementation. Preserve old numerical reason/order/meter and H/VR observation bytes. Empty attempts alone do not select the PreSourceRefusal variant: group preparation, exhaustion and some later stops also have no attempts and require their actual phase/source association.

RunOrigins is filled at actual group creation/cache obtain/finish seams. It is not constructed by a caller claiming a matching digest. Public F2a context issues call/run ids, but private constructor checks source owner and actual local group/slot objects before stamping origins. Cross-call imports are possible only through checked retained operand snapshots, not arbitrary external build ids. No counter changes are authorized.
