K6 D: how the packet and the D tables are reproduced from committed records alone.

1. Combine the three slots' records into one folder, as the runner wrote them in one records folder:
   - copy every file of _run_records/b1/records/, then _run_records/b2/records/, then _run_records/b3/records/
     (later copies replace earlier ones: B2's baseline_T3b/T5 and B3's baseline_T6 are the runs' own tier baselines);
   - records.jsonl = b1/records/records.jsonl + b2/records/records_b2.jsonl + b3/records/records_b3.jsonl, in that order
     (166 lines, sha256 fcc89445c0221df068aae87c029a77356971477e8df225e32da4179c166c47d7);
   - drop records_b2.jsonl and records_b3.jsonl from the folder.
   The combined records.jsonl is byte-identical to the working records folder the runner wrote during B.
2. python3 H/runner/k6_runner.py --packet --records <combined>  >  k6_packet.json
   sha256 b5419aee28d2736b84fe3f0a36d7e2850a21a1c59634a21e0580e69e632eb27f, identical to the working-folder packet and to
   H/observations/k6/k6_packet.json.
3. python3 d_tables.py.txt <H/runner> <combined> H/observations/k6/counts.jsonl <out>  writes tables/ here;
   python3 gen_return_tables.py.txt <out>/d_tables.json H/observations/k6/counts.jsonl _run_records/c/mutation_table.json
   return_tables.txt  writes the tables RETURN embeds; sparse_and_timing.py.txt writes sparse_and_timing.txt.
Every table here was generated from the combined committed records (step 1).
