# Scoped implementation plan

The new public module will parse original numeric tokens once to finite binary64, retain numeric lexemes by JSON Pointer for explicit schema-owned exact-integer admission, and render all admitted numbers through the existing ECMAScript formatter. Safe integer variants remain usable by downstream DTOs; every new-profile hash renders their binary64 values. No name-based count inference or generic schema language is added.

A standalone `openpipestress_jcs_binary64` CLI keeps the old binary and its complete acceptance unchanged. It accepts only protocol1.0.0 plus the selected binary64 profile, echoes both, checks envelope duplicates and bounded input, and fails the entire batch on rejection. Python gets explicit new text and programmatic-snapshot entrypoints and executable discovery. Runtime never builds or retries under another profile. Unsafe untyped Python integers require an explicit real conversion or the raw scientific text route; bool cannot satisfy the separate exact-integer helper.

New-profile-only implementation resource limits: 8MiB per document, nesting depth128, 262144 value nodes,4096bytes per numeric token,16MiB cumulative preallocation JSON Pointer construction; CLI64MiB envelope and4096 batchitems. These are admission/resource limits, not a qualified solver range. They do not change old limits. The parser rejects noncharacters, decoded duplicate names, negativezero, overflow and nonzero lexical underflow. Literal positivezero with extreme exponent remains zero if syntax and token limits permit.

Meaningful checks combine all RFC8785 finite rendering vectors (negativezero retained only as historical algorithm control), adversarial JSON syntax/Unicode, midpoint/adjacent decimal conversion, deterministic random finite binary64 comparison to stock Node, Python raw/snapshot/typed-count admission, CLI profile/envelope negatives and unchanged historical regression hashes. Native/WASM exports, real solver invocation, custody receipts and result/quantity adoption remain successors.
