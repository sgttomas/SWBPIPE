The reviewed numeric boundary parses original tokens directly to binary64;
generic large integral-valued reals never use the old exact i64/u64 renderer.
Original numeric lexemes remain available to explicit JSON-Pointer count/index
checks. Integer tokens are admitted only within the safe range and supplied
field bounds; decimal/exponent spellings and negative zero do not become exact
counts after rounding. Programmatic unsafe integers need an explicit real-domain
conversion. Python bool/subclass/coercing objects are not accepted as integers.

The text parser rejects strict-JSON syntax violations, decoded duplicate keys,
lone surrogates, noncharacters, negative zero, overflow and nonzero underflow to
zero. Representable nonzero subnormals remain supported. It preserves string
content and uses the existing Rust ECMAScript numeric renderer and UTF-16 key
order. Raw text and programmatic snapshots deliberately make different custody
claims; canonical equality is not original text identity.

ordered unique item IDs and whole-batch refusal. The Python adapter invokes
only the explicitly selected executable; it has no runtime build, PATH search,
retry to another profile or Python canonical-byte fallback. The build helper's
default still chooses the historical checked executable. Call-site search found
only the new standalone authority, CLI, adapter and tests using the new APIs;
no existing product/native/WASM/solver consumer was activated.

reconstructed and matched to their recorded base hashes. Historical CLI/lock/test
