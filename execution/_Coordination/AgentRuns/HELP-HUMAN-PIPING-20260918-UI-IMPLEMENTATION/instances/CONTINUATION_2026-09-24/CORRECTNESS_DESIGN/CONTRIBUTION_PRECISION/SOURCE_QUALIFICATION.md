## Independent analytical/prototype warrant

The independent TASK uses exact Fraction oracles, a per-operation p-bit rounding model and a genuine two-word arithmetic prototype. It preserves code, inputs and raw output without importing production. This distinguishes full multiprecision solving from promoting a rounded matrix and independently checks why retaining global high-precision values through action recovery is necessary. It covers named references, a multi-span chain, an oblique source-factor analogue, an ordinary-scale small-motion case and extreme precision escalation. Exact tested operations/range and errors are in `INDEPENDENT_REFUTATION.md` and `_run_records/precision_refutation/`.

This arithmetic prototype is not an MPFR deployment test, a complete 3D product-element implementation, native-path evidence or a performance measurement. Its correctly rounded p-bit model has its stated exponent/range behavior; an actual backend's overflow, underflow, exception and conversion behavior must be checked. The source-factor analogue shows that increasing arithmetic precision after independently rounding every global element coefficient can preserve the wrong model. A new solver must preserve supported primitive/constraint relationships as well as sums.

The choice is adaptive multiprecision because a fixed significand can meet N05/N06 yet fail a more ill-conditioned small-rotation case. That is a reason to expose a precision/range limit and escalate generically, not a reason to promise unlimited accuracy or to add a case-specific exception. Relative-coordinate diagonalization is retained as an independent physical oracle and a potentially useful general formulation improvement. A production implementation would need graph/constraint/compatibility design before that route could replace arbitrary coordinates generically.
