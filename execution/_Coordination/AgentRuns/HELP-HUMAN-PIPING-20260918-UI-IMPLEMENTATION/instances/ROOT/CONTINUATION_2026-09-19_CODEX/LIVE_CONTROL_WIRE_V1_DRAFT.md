## Carrier and invocation

The first implementation is development-only opt-in, for this Mac, using a private Unix socket. Keep normal startup usable with the bridge disabled or unavailable. No TCP listener or implicit app discovery. Other platforms return an explicit unsupported-host outcome until separately implemented; keep existing platform builds compiling.

Proposed CLI: `swbpipe-control --attachment <descriptor-path> <inspect|preview|submit|status>`, reading one JSON params object from stdin and emitting one JSON result to stdout. `help` and `describe` work without a running app. Errors go to the same structured stdout envelope, with concise optional human guidance on stderr; use a nonzero exit code for an error. Never print an attachment capability. No account/model authentication, configuration change or agent loop lives in this binary.

A descriptor contains the application protocol version, app_instance_id, socket path and random local capability. Create the parent directory with owner-only permissions and descriptor with owner-only file permissions using exclusive creation. Bound path length for macOS Unix sockets; choose a short randomized private directory, not an overlong default temp path. Reject unsafe existing filesystem objects, malformed or oversized descriptors. Clean up only the endpoint owned by that process. Preserve other running apps/rows/preferences.

The CLI opens one socket per request, sends one bounded newline-delimited JSON envelope and waits for one response. This is a Piping application protocol, not MCP or a claim of MCP qualification. Each request includes protocol_version=1, a unique request_id, explicit app_instance_id, capability, method and params. Each response includes protocol_version, request_id, app_instance_id and either result or error. Limit frames, concurrent in-flight requests and timeouts; starting defaults may be1MiB/frame,16in-flight and30seconds. These are new transport admission limits, not changes to a product/performance criterion. Describe them and report actionable limit errors; never silently truncate operations or model content.

The native bridge checks authorization and explicit identity before dispatch, and forwards domain params opaquely to the one registered frontend controller. It does not implement a second domain validator/model. The registration binds the actual main webview, app instance and fresh controller session; ready/reply/unregister commands verify that binding. A stale registration cannot answer a newer request. Frontend readiness is published only after its listener and controller are installed. Unmount clears readiness and settles pending requests explicitly.

## Domain requests

One explicit app inspection may discover that app's current workspace handle. All model-sensitive calls then supply that handle; neither a previous request nor connection continuity chooses the workspace.

- `inspect`: `{ scope: "workspace" }` returns an explicit workspace handle, project identity, current selection's copied identities, supported primitive description and readiness. `{ workspace, scope: "nodes", node_ids: [...] }` returns the named node snapshots, source length unit and one coherent host-issued basis. A small explicit node-count limit is reported as an error rather than truncation. Inspection never mutates selection/model/history.
- `preview`: `{ workspace, basis, changes: [...] }`. Each proposed change is `{ target: { object_type: "Node", ref: "<copied-id>" }, field_path: "position.x", before: "<source-value>", after: "<requested-value>", unit: "<project-length-unit>", dimension: "length" }`. The controller creates the existing modify/set_field EditorOperationIntent/OperationBatch, with trusted agent attribution, invocation-scoped IDs and unchanged engine checks. This narrow projection avoids asking a caller to fabricate validation/audit fields. Return the immutable preview reference, engine diagnostics/diff and validation outcome. Invalid batches have no submittable preview.
- `submit`: `{ workspace, preview_ref, idempotency_key }`. Resolve an existing canonical key/preview association before fresh-basis validation. Otherwise require the exact still-current basis and publish the frozen operation batch to the existing review queue. Return the real ticket only after its committed-render acknowledgement. No direct Apply method exists.
- `status`: `{ workspace, ticket }` returns the retained authoritative outcome and any commit receipt. The explicit workspace here may be a prior workspace generation for an existing ticket: authenticated same-controller history lookup precedes current-workspace admission checks. This distinction also applies to same-key submit recovery after a project change. It never admits a new old-workspace mutation.

Workspace handles and bases are opaque application references externally, with inspectable non-secret identity fields for useful diagnostics. Internally they bind app instance, fresh controller/workspace identity, project generation and ID, published model revision and canonical hash. A remount or restart creates a new controller/app identity as applicable. Numeric counters alone never establish global identity. Never return a new model with a previous hash; await coherent hashing or return not-ready.

Preview stores exact canonical operations and basis, not a rebase instruction. Changes to selection do not retarget it. Unknown methods/fields or unsupported domain primitives are explicit errors. Preserve decimal/source-unit semantics through the existing builder/engine rather than converting through display-unit preferences. Node labels, other fields and new operation kinds remain outside this first projection.

## Outcomes and retention

External states distinguish queued, committed, rejected, withdrawn, expired and outcome_unknown. Rejection includes a stable reason (validation, stale basis, conflicting key, unavailable controller or busy owner) and useful next action. A transient readiness/transport error does not claim that a previous submit never happened. Retrying an uncertain submit uses its original key and preview, not a fresh key.

A commit receipt binds the original ticket and operations, truthful agent origin and observed review actor, previous/next revision/hash, workspace identity and actual published model/history/result transition. Record the actual user acceptance route. Controlled automation is recorded as test-driver evidence and cannot satisfy the separately required real human-prompted witness.

Retain key/payload/ticket/outcome associations for the running controller session, including project replacement. If a bounded registry fills, refuse new work with capacity guidance rather than evicting a promised recovery record. Expiring unsubmitted previews may be added only with an explicit documented lifetime and expired response; no silent renewal. Restart/controller remount invalidates old handles and requires outcome reconciliation. No new persistent field is introduced.

Disconnect/timeout triggers a best-effort cancellation notification correlated to the original registered controller/request. Only the controller decides whether cancellation preceded queue publication. A confirmed pre-publication cancellation leaves no ticket. Once publication is observed, disconnect cannot withdraw or undo; the ticket is recovered by the original submit key. A transport timeout alone returns outcome uncertainty, not a fabricated cancellation success. UI Clear remains the withdrawal route.

## Native binary and testing ownership

The native TASK owns new live_control.rs, narrow lib registration/commands, the separate Rust CLI binary and only needed Cargo/lock changes/tests. Preserve explicit default-run and desktop bundle selection when adding the second binary; existing packaged self-test behavior must stay reachable. The shell writer owns the domain projection, controller registry, committed-render observation and frontend bridge, after B4.1 handback. If the bridge service needs to be authored earlier, it stays with that writer; do not duplicate it in the native lane.

Both writers use the same fixture envelopes for correlation, identity, error, cancellation and reconnect. Native tests use a controlled handler; controller tests use a controlled carrier. These component tests do not qualify the real connection. Integrate and exercise actual native single and batch journeys, invalid later operation, lost reply followed by Apply/retry, Undo and stale rejection. The final human-approved loop requires the real Codex/CLI/App witness described in the activation proposal.

Developer guidance must show describe/help and a complete invented request/result exchange for each method, including locating the descriptor without exposing its capability. No private endpoint extraction, database mutation or file-input solver substitutes for this connection. CLI and human operation semantics remain those of the existing shared engine/controller.
