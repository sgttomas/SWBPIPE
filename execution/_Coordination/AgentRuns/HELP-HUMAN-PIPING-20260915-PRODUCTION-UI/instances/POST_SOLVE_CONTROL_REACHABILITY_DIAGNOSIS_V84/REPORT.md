## Source-based interpretation

The matrix at `apps/desktop/e2e/ui-foundation.spec.ts:780–804` performs `scrollIntoViewIfNeeded`, focus, a focused assertion and `expectCenterUnobscured`, then reads the target and body rectangle and requires exact vertical containment. The center helper at `e2e/ui-foundation-workflows.ts:548–577` only reads geometry and actual `elementFromPoint` ownership; it does not reposition the control. Neither failed trace records a wheel action. The current test therefore rejects one auto-scroll/focus placement without testing an ordinary wheel route to an interior placement.

The product deliberately exposes that route. `styles.css:752–756,3484–3490` makes `.workspace-dock-body` a bounded, padded `overflow:auto` scroll container inside the dock. `SolvePanel.tsx:62–86` supplies ordinary mode and Run buttons in content flow, disabled only while running. Their markup contains no wheel override or sticky positioning. The current evidence shows usable body space and a focused, center-owned control near an edge; it does not show an irreducible clip, an obscuring overlay, a focus trap or an inability to scroll that control further inward.

The V81 product change is independently understandable: `App.tsx:3602–3606,3748–3755` supplies the concise Solve proof summary while retaining the exact original `value` in Details. The R1 test-only patch changes the asynchronous export availability query to the existing default `findByTestId`; it does not change this geometry path. Neither explains away the sampled clip.
