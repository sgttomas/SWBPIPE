## Standing direction

Steer (this run): STANDING DIRECTION — development pressure
The goal is a working software application meeting the acceptance criteria the instruments record; every iteration is measured by how much closer it gets. This iteration's deliverable is product work: code, working features, executing cases, closed engineering gaps. Governance is a fence around the work, not the work — apply ruled decisions as-is, don't revisit them, and produce the minimum coordination artifacts your instruments require. If you find yourself planning, re-deriving, or writing records instead of building, stop and build. A return whose bulk is run-records and plans rather than product progress is a failed iteration even if every gate passes. Decisions that need the owner: park them in one list at the end, don't let them stall the work. An iteration whose shape the owner has explicitly directed (a recording tranche, a specific fix) is measured against that direction, not this default.
Applied to Step 0 (node selection). Select the highest-value open engineering target the instruments already authorize. Then, up to N=5 nodes per iteration, take any further target that is also already selectable at Step 0 and either (a) has a write scope disjoint from every other node and shares no gate surface with it — build these in parallel — or (b) is named by the instruments as a dependant of a selected node (DAG edge, deliverable Remaining item, chained TM row or decision) — build it after its predecessor. When more than one selectable target satisfies (a), taking them in parallel is preferred to leaving them, up to the cap. Each node is bounded by one WORKING\_ITEMS per package. Record the work graph before dispatch. For each node, name at selection where its checks will run — in-session, CI, or host-capability — and if none is available, the node is not selectable; park it with the reason. Selection is a decision, not a deliverable: state the nodes in one line each and go build. Anything discovered while building is not a node — amend the current node in place if it belongs to it, otherwise register it and stop. A single-node iteration is a valid result; do not manufacture a second. If Step 0 concludes that no authorized engineering work exists and only decisions remain, return that as a short parked-decisions list — do not manufacture a planning or records iteration to fill the session.
Applied to failures. A failed check or a failed integrated review is not a terminal state for a node: repair the enumerated findings and re-run the checks, then obtain a fresh 100%-diff read-only review with a refreshed hash inventory; repeat until the node passes. There is no limit on repair cycles. Every failed review and its hash inventory is preserved immutably in the run's AgentRuns package; a node lands only in its passing state. Failed nodes hold only their declared dependants; independent nodes keep moving. The only reasons to stop with a node unpassed are forced termination (session limit, owner stop) or a finding that needs an owner ruling or touches a hard fence — in those cases land the nodes that passed, record the failed node's state and its remaining repair matrix, park the ruling if one is needed, and stop; partial landing is a valid result.
Applied to closeout. The iteration is one tranche: one branch, one PR, one receipt. If the previous iteration's PR is not yet merged, branch this tranche from its head and open this PR with that branch declared as the PR's base — one PR per iteration, stacked and merged in order, never a single PR grown across iterations; name the base branch and the dependency in the PR description and the receipt. If the predecessor merges before this PR opens, open against main as normal. Do not stack more than three PRs deep: if three prior PRs are already open unmerged, park the iteration with that as the reason. Nodes are commits in dependency order, each landing only after its own checks pass. A node whose checks run on an external proof surface (CI, host execution) may land as several adjacent commits — the proof loop's attempts — provided the node's final state passes and the receipt points at the proving run. Review runs over the integrated diff. Writes to shared surfaces (receipts, registers, completion logs, shared coordination roots) happen once, at fan-in, not per node. Agent 0 owns integration decisions; CHANGE commits. The receipt is written after the fact and points at the nodes and their evidence — it does not narrate them. If main advances mid-PR, request owner authorization for a non-rewriting sync merge — do not sync silently.
