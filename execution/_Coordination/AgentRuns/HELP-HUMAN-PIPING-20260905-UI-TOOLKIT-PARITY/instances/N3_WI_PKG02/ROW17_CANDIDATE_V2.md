The canonical model supports section references but live desktop PreviewModel is a different wire model. Merely adding a ref to preview JSON is currently ignored by product_physics serde.

Bounded proposal: optional string section_ref on preview pipe, resolved in common product_physics::run_linear_static_preview_with_mode before normalization, so native/headless/Wasm use the same semantics. Referenced Section must exist uniquely, be section_type pipe, and supply explicit valid outside_diameter and wall_thickness QuantityValues. For this bounded binding, those are the only section-owned physical properties. Other scalar section properties cause unsupported-binding diagnostics unless implementation deliberately maps them; do not silently ignore. Existing per-span mill_tolerance, material_density, contents_density, insulation_thickness and insulation_density retain explicit local meaning and are not replaced. Section type rigid/custom/TBD cannot be assigned as pipe mechanics.
PKG16 assign_section payload explicitly chooses pipe_ref + section_ref; operation validates before/after and materializes the bound OD/wall into inline section for existing displays and exporters. Section OD/wall edit rematerializes all referring pipes atomically and includes them in preview/affected-object diff. Direct bound OD/wall edits on Pipe fail with edit-shared-section-or-detach guidance. Clear/detach operation must explicitly be requested; it freezes current resolved OD/wall as local data and removes reference, preserving supplemental values. No implicit detach on scalar edit. Reference removal/delete checks include every bound pipe. Provenance remains on shared Section; operation trace records binding, never fabricates source provenance.
Physics re-resolves authoritative Section on every solve; stale inline OD/wall caches cannot control solver. To maintain non-solver consumers, persist/operations must materialize consistently and detect or repair caches through explicit normalization at load/preview boundary; cache correction must not silently modify stored bytes. If dependent exports cannot consume live ref safely, reject stale cache with explicit diagnostic instead of reporting stale geometry. This is integration work with required native/Wasm/headless fixtures, not a UI-only setter.
Alternative copy-on-assignment is useful only if labeled snapshot copy and not claimed row17 live-reference coverage. Full canonical/preview schema convergence is unnecessary for this tranche.
Tests: shared edit propagates two pipes; nonreferencing pipe unaffected; supplemental values preserved; direct bound edit blocked; explicit detach thereafter independent; duplicate/missing/type/property failures atomic; stale cache fails or deterministically resolves at declared read boundary; solver result changes after shared OD/wall edit; native/Wasm parity and export consistency.

## V2 accepted refutation repairs / exact wire contract
Optional PreviewPipe.section_ref: string. PreviewModel.sections default empty; each record carries id, name, section_type, properties (quantity map), provenance. The existing pipe.section remains required for backward compatibility and materialized readouts. Bound OD/wall are authoritative only from the exact referenced Section; supplemental pipe fields remain local. At operation/load/shared-consumer boundary stale inline OD/wall is rejected explicitly before display/export/use (no silent stored-payload correction). Product physics independently resolves shared Section at entry before normalization and must reject stale cache too, so every solve caller fails consistently rather than producing a value from contradictory geometry. PKG16 assignment and shared edit materialize matching inline values atomically; detach validates/resolves shared values, writes them and removes ref explicitly. Resolve/validate each referencing pipe's OD/wall with local mill_tolerance; any failure blocks entire shared operation. Unbound inline spans unchanged. Section provenance is retained as source metadata; detach operation provenance must reference source Section, not invent imported source. Schema extension is preview representation only; canonical schema already expresses section_ref, no canonical migration required.
