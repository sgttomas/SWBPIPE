# Phase A v2 amendment — parent accepted direction and durable association

Parent HELP_HUMAN accepts the bounded global free/rigid/diagonal-spring composition as implementation direction. Review and net-new source release remain pending. No solver changes are authorized or needed. N2 rich-support contract and the future atomic-batch contract are explicit predecessors.

## Persistence proposal (implementation request, not live schema truth)

Each generated support carries a preserved optional `boundary_association` object:

```json
{"boundary_id":"boundary:equipment-1:nozzle-a","kind":"equipment_nozzle","equipment_reference":"user equipment reference","nozzle_reference":"user nozzle reference","coordinate_system":"global"}
```

For an equipment-only boundary use kind `equipment`, a required equipment_reference and omit nozzle_reference. For kind `equipment_nozzle`, both references are required. These are nonempty user-supplied descriptive/source references, not model entity IDs claiming an equipment collection exists. The stable boundary_id groups all support records generated by the atomic command. Identical association values are copied to each member record and survive operation apply, save/load, import/export of the native model format and subsequent ordinary support edits. They are shown in the model inspector alongside member support IDs. Deleting a member deletes that support; retained members keep association and are not falsely reported as a complete original template. Model schema/adapter preservation must be proven; do not rely solely on mutable labels or provenance text as association storage. Native model persistence is not PCF export.

PKG16 owns schema and resolver decisions about exact canonical storage nesting; `boundary_association` is the proposed external interface to accept or amend before UI source starts. The essential contract is durable boundary_id, kind, equipment/nozzle references and explicit global basis surviving mutation/persistence. Rich-support canonical nesting is owned by N2; this amendment does not pick a second spring-field representation. PKG07 depends on that accepted result before implementation.

Strictly reject unknown kind or coordinate_system, blank required references and incompatible data on the generated records. Require uniqueness of generated support IDs and a new boundary_id for creation; never append silently to an existing group. Ordinary support edits must preserve the association. Member deletion and ordinary individual editing remain supported with truthful group member inventory; this first slice does not promise aggregate edit/reconstitution or automatic reconciliation against original per-DOF template.

Nozzle association is metadata describing which user-declared equipment boundary these ordinary supports represent. It is not equipment geometry, local shell compliance, allowable load evaluation or a new solver family. Global-only rigid/diagonal-spring semantics and user-supplied stiffness remain unchanged.

Acceptance adds: roundtrip association for every batch member through validation/apply/serialization/reload, preservation under member edit, truthful member deletion, missing/invalid association rejection, and agent/human payload parity. These are implementation checks pending source release, not tests already passed.

Closure: contract pending independent refutation, then exact UI/operation request returned to parent; implementation held until parent releases net-new phase after N2 rich support and atomic-batch prerequisites.
