# Batch provenance persistence — owning-scope disposition V1

Status: RECOMMEND bounded renderer wiring to existing persistence contract; read-only source disposition, no source changes. This is a minimum provenance-preservation measure, not closure of the complete SOW-070 durable accepted-operation audit requirement.

- DEL-16-03 ScopeOfWork.md CLM-004 lists those audit subjects; CLM-005 contains historical current-slice in-memory audit/storage-TBD statements and CLM-002 expressly calibrates historical future/TBD wording. Empty _STATUS Remaining is not proof that any new batch path preserves history.
- docs/architecture/persistence_contract.md is labelled draft; it describes the established local SQLite/JCS envelope and preservation of provenance/reproducibility. Its human-review records require hash-bound semantics if later added. It is not authority to invent an accepted batch/group schema.
- Actual native src-tauri/src/lib.rs LocalProjectEnvelope/SaveLocalProjectRequest use editor_intents:Value; normalized_editor_intents (line1110) returns arrays unchanged. upsert_project (lines876–929) serializes that complete JSON in the same SQLite transaction as the model; load (line1048) parses exact JSON. save_local_project (line2167 onward) forwards it. - Renderer types.ts EditorOperationIntent has proposed-only operation_status, author_type, full source metadata, target, before/after/change/source_note, rationale and professional/audit flags. Singles currently remove applied intents from the pending queue.

## Exact minimum interface recommendation

1. Continue existing SaveLocalProjectRequest shape `{..., model, editor_intents: EditorOperationIntent[], ...}`. No native schema/migration/envelope additions are necessary.
2. On successful explicit batch apply, **inside the same generation/hash-guarded publication transaction in renderer state**, retain a deep copy of the exact submitted `entry.batch.operations` in an existing-intent-compatible provenance collection. Preserve member ordering, operation_id/change_id, author_type, complete source fields, rationale, target, before/after, source_note and all original flags. Do not fabricate assumptions or source identity verification. Do not derive persisted intents from allowlisted simulation rows because those intentionally omit original provenance.
3. On Save, editor_intents must include both pending single intents and these retained member records. Exact duplicate records may be coalesced; conflicting content with the same identity must never silently overwrite provenance. Prefer detecting collisions before commit or preserve both records with an explicit ambiguity diagnostic. Do not change original IDs or add batch keys to the schema. Failed, validation-only, or stale/discarded apply responses append no **applied provenance**. Pending drafts may remain session-only if explicitly disclosed.
4. Keep UI queue membership separate from the persisted review-context collection. Existing Remove/Clear queue controls must not accidentally erase retained operation provenance. On reload, originals remain proposed/untrusted records, and durable acceptance/group membership is unknown: show them as saved review context, require explicit selection/requeue plus fresh validation before any application, and do not auto-replay or infer prior acceptance. Existing controls/messages that call every editor_intent pending need adjustment for that truthful interpretation. This may require treating all restored editor_intents as review context because the existing durable shape cannot distinguish saved pending from already-applied members.
5. Keep batch grouping, timestamps/receipts, undo checkpoint and acceptance status explicitly session-only. Suggested disclosure: “Member intents and their source/rationale are saved as review context. Batch grouping and application receipts are retained only for this session; reopening does not restore an acceptance record.” Saved model remains the current authoritative model payload. Undo/redo may leave retained provenance as attempted/session history; never label every saved record currently applied, especially after undo.

## Acceptance checks for the bounded wiring

Apply an offline agent-authored batch, Save, reopen through native storage, and compare each retained original member including full source/author/rationale/before/after and flags. Include unknown-but-preserved model fields in the model roundtrip. Verify a failed/stale/preview batch adds no applied provenance, Save writes the physical model and intended provenance together, and reload creates no receipt/auto-application. Verify clearing a pending queue cannot silently drop retained members. Confirm model undo/reload never manufactures accepted history from these proposed records.

## Remaining scope boundary

This prevents complete loss of newly applied batch provenance without inventing a durable acceptance container. It does **not** satisfy all durable accepted/rejected history, assumptions, timestamp/hash-bound decision and group reconstruction requirements of SOW-070/DEL-16-03. Parent should retain that bounded limitation in existing project issue/handoff surfaces. No second issue plan or new governance ruling is proposed here. No live runtime binding or D58 release.
