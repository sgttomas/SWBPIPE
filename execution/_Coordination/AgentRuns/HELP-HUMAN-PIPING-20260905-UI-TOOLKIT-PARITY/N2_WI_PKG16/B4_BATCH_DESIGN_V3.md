## V2 refutation repair proposal
Successful and failed individual outcomes never serialize directly. Each returned step is an explicit allowlist simulation projection: index, operation_id, change_id, target_object_type/ref, change_kind, schema/reference/unit/before validation states, diff_preview_status, diff_preview, diagnostics, simulation_status (validated_on_temporary_state or blocked). No per-step mode/apply status, acceptance, applied_model, applied_model_backend_hash, professional_boundary or audit_boundary copied from engine outcomes. No nested intermediate hashes. The top-level batch alone declares applied state/receipt after every step succeeds; validate or rollback always declares no model/no acceptance. Submitted operations are retained separately as untrusted submitted metadata, not engine outcome claims.
Shared preflight must explicitly enforce operation_status proposed, author_type user|agent, professional_boundary human_review_required true and all software claim booleans false, audit mutation_route structured_operations_only/direct false/requires_user_acceptance true/mutates_accepted_model_state false. Existing single applier does not enforce all these; preflight is required before batch simulation and offline import. Missing/invalid mandatory controls block. Agent source.source_ref nonempty and rationale nonempty required; source/rationale never overwritten to user author. Input validation fields never promoted into output findings.

## V3 source and renderer commit guard
An agent operation requires a complete EditorOperationSource object containing nonempty string source_ref, source_channel and source_role; malformed/partial sources reject. User operations may omit source, but any supplied source must obey the same complete contract. Only declared source fields accepted.
Outcome always echoes initial_model_hash in complete canonical hash-evidence shape and initial_backend_hash; it never substitutes final hash for initial request identity. Renderer (N1 owner) captures its monotonically increasing model-generation token and authoritative model hash immediately before async validation/apply request. Before committing any successful response, it requires unchanged generation AND recomputed current model hash equal to response/request initial model hash. Every load/new project/undo/redo/edit increments generation. A mismatch discards the response with explicit stale-result diagnostic, creates no checkpoint and never overwrites current model. Successful batch creates exactly one checkpoint. These guards are required even though core checked initial hash, because core executes a supplied immutable snapshot and cannot inspect subsequent renderer state.
