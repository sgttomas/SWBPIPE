# Bounded repair program and decision queue

## Activation gate and contract

This is a proposal derived from accepted baseline manager packets. No production repair is authorized by this file itself. The user authorized the full audit/repair program; Agent0 activates specific package briefs only after complete baseline independent review PASS and Agent0 acceptance. The additive I1 service-failure/precision evidence is accepted and included before S1 freeze.

Every activated repair must identify its source findings, owning deliverable/SOW, exact source write set, baseline fixtures, independent expectation, implementation/review agents, acceptance tests, and compatibility fence. `REQUIREMENT_BINDINGS.csv` provides frozen SOW paths/hashes/objectives; manager briefs must load the live paired context/status/memory before writing. Existing IN_PROGRESS/empty Remaining does not imply acceptance or permit lifecycle promotion.

Use one PKG04 WORKING_ITEMS manager for numerical/support repairs, one PKG05 manager for load/recovery/algebra integration, and PKG09 for independent reference/regression strengthening as needed. Package boundaries remain explicit; a single authorized product adapter owner coordinates all writes to shared product code. Disjoint kernel work may proceed concurrently. All core/product source changes require a fresh read-only TASK software-code-review over100% frozen diff, independently of the implementer.
