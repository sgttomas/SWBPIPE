## Operation contract for the new interaction

Keep Tauri 2 + React/TypeScript/Vite + Three.js. No kernel/library replacement. Select/hover/camera/preview/snapping/draft inputs remain transient. Typed endpoint IDs, entered coordinates/units, local reference vector, material, section and provenance are visible before mutation. An explicit existing-node snap selects that exact EntityRef; it never merges nearby nodes, auto-welds intersections or changes topology. Pointer projection is an editable draft on a visibly selected construction plane; typed X/Y/Z values remain the precise authority. The first cut need only existing-node snap and typed coordinates; automatic grid snapping, inferred bends and constraints are excluded.

Route new endpoint + straight segment as ordered create_node then connect_pipe_run members in one existing atomic batch. If connecting two existing nodes, emit only connect_pipe_run. Where section assignment is chosen, include assign_section only under its existing resolver contract; no inline dimension mutation of a bound section. A displayed preview is not a model entity. Zero length, duplicate/reserved identity, missing material/section data, invalid units/frame or stale basis produces a field-linked/shared-engine error and publishes nothing. ID reservation includes pending intents/batches across surfaces.

Inline human Add (creation) / Apply (revision) is an explicit final human action on the displayed draft/diff. It freezes original model/hash/revision and exact intent, validates with the same Rust service, exposes any warning/diff requiring review, and applies only that unchanged validated intent after the human action. If validation changes the proposed diff or needs new input, hold for an explicit new Apply; no auto-fix or hidden batch member. A single deliberate action may validate and apply an unchanged disclosed simple draft; no separate navigation to a global queue is required. Model changes/cancel/replacement invalidate in-flight callbacks; repeated clicks cannot duplicate commits. A failed batch cannot publish its earlier members. Successful segment creation produces one undo checkpoint for all its members. Undo/redo remains session-scoped, including after reopen only for new edits in that session; no durable acceptance/history claim. Offline/agent proposals retain their explicit review workflow and D58 remains held.
