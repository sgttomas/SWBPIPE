## Concrete draft layout and deltas

All three candidate files use JSON Schema 2020-12. A common proposed wrapper contains `schema_version=0.1.0-draft`, `record_kind`, accountable `contract_owner`, nonempty `source_refs`, nonempty `provenance_refs`, `professional_boundary` and `payload`. References use `object_type/ref` for this draft only. The wrapper is deliberately a **new, unaccepted wire delta**; current Python `to_dict()` results have no such wrapper. Its version is a review identifier, not a public version compatibility commitment. The comparison wrapper's `contract_owner=DEL-14-05` identifies the contract owner; payload `producer_owner` identifies DEL-14-03 or DEL-14-04.

Validation payload preserves the current `diagnostics[]` fields (`code`, `class`, `severity`, `message`, `remediation`, `affected_references`, `source_references`) and `has_blocking_findings`. It does not invent class taxonomy or owner engineering rules. Transform payload preserves `analytical_model`, `diagnostics`, `traceability_links`, and `has_blocking_findings`; `analytical_model.model_role` is explicitly `analytical_solver_model`. It does not assert that a partially derived/blocked model is solver-ready. Nested analytical records and trace links still require their accepted model/trace contracts and semantic checks; the draft's object slots are intentionally not a claim of full model validation.

Comparison payload has `comparison_review`, `producer_owner`, and `producer_payload`. `comparison_review` reuses an exact local copy of the existing DEL-14-05 `ComparisonReview` definitions: two participants, mappings, unmatched records, tolerance references, assumptions, diagnostics, hashes, export contract, provenance and professional boundary. `producer_payload` retains each producer's present field names (state refs/entity changes versus run context/result and settings deltas); it does not normalize or overwrite source output. Copied definitions remain constrained by their hashed original source. This wrapper/join and its publication shape are **unaccepted design deltas**, not present runtime behavior. Reuse of an input/review contract supplies a vocabulary, not automatic evidence that a producer satisfied it.

These drafts intentionally do not select CSV columns, report layouts, tolerance values/formulas, hash canonicalization, persisted record migration, version compatibility windows, diagnostic-class reconciliation, or new runtime endpoints. No numerical default appears in a draft. Current DEL-08-04 accepted 0.1/0.2 dispatch and raw-row preservation continue unchanged; comparison mapping must eventually target an explicitly selected supported version and preserve its distinctions between received assertions and verified derivative evidence.

## Required semantic checks beyond JSON shape

| Hook | Required positive/negative evidence before a production conformance claim |
|---|---|
| IF-001 Identity | Bind source refs and hashes to actual supplied model/state/run records; detect stale or mismatched source; no invented digest or source status. Same inputs/settings yield deterministic canonical output under the separately accepted hash basis. |
| IF-002 Findings | `has_blocking_findings` equals presence of blocking diagnostics; missing data remains visible. Validation's `source_references` and affected references survive export; adapters cannot silently coerce unknown diagnostic classes into success. |
| IF-003 Transform | Source model remains byte/semantic-unchanged; each emitted, omitted and assumed analytical record has source trace or an explicit finding. Validate nested model and trace contracts; unsupported/nonfinite/wrong-dimension data remains blocked. Scalar-path pairs follow existing trace-link constraints; no claim of full runtime trace production. |
| IF-004 Comparison | Review participants bind exactly to producer left/right states/runs; map every matched/unmatched result, reject duplicate/ambiguous mappings, preserve settings/metadata and unsupported categories. DEL-14-03 structural comparison adds no unit conversion; DEL-14-04 normalization requires valid explicit units/dimensions and governed tolerance references. No tolerance inferred from a section-property oracle. |
| IF-005 Export | Producer → interface → DEL-08-04 → consumer round trip preserves identities, hashes and their declared byte bases, source rows, units/dimensions, mapping/unmatched evidence, diagnostics, assumptions and limitations. Distinguish source-preservation evidence from semantic qualification. CSV/report projections disclose every omitted field. |
| IF-006 Privacy and authority | Export only the explicitly permitted data; provenance references do not grant access or redistribution. No protected/private payload copied by default. Software produces no professional acceptance, compliance or certification. |
| IF-007 Compatibility | Reject unsupported schema versions explicitly. Accepting a future version requires a documented compatibility/migration disposition; this preparation creates none. Invalid shape fixtures and changed semantic binding must actually fail. |

Structural validation of these drafts is useful preparation evidence only. It cannot close PDU-011 output conformance, PDU-023 runtime trace production, PDU-047 suitability, protected tolerance selection, or existing human-review dispositions. Publication of authoritative schemas and wiring to producers/consumers remains a bounded implementation activity after exact contract acceptance. The source-owner assessment and GUI map are separate files in this directory.
