## Reproduction and backcheck

Run from any directory:

```sh
python3 <this-folder>/apply_check.py --check
```

The script reconstructs each postimage from its sealed preimage and exact
non-overlapping source-span operations, verifies before/after body and file
hashes, compares the actual STATUS file, and verifies unchanged lifecycle.
`--apply` performs the same replay idempotently and refuses unknown preimages;
`--check-spans` permits later unrelated additions but still requires every
repaired span and original lifecycle to remain present. The default strict
check is the R5 completion check; later integrated R6 accounting is parent-owned.

Validation result: PASS for 64 exact reconstructed postimages, 158 operations,
29 Remaining result rows, unchanged lifecycle values, and existence of all
concrete project-relative evidence paths cited by the repaired Remaining text.
No product suite or new engineering validation is asserted. The default check
fails on postimage drift, preimage/body-hash mismatch or lifecycle change;
`prepare.py` refuses to overwrite an existing manifest.

`REMAINING_RESULTS.csv` distinguishes the factual repairs that retain review
or intake-reliance holds. `operations.csv` mirrors the JSON operations without
