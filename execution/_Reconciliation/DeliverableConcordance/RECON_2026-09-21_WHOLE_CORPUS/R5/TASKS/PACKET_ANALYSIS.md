## Four-lens and adversarial result

Ontology: reference libraries, running application services, interfaces, evidence and lifecycle are distinct objects (DEC-009/010/020 and F7); coverage ownership is not implementation ownership (DEC-094/103). Epistemology: merged PR intent plus accepted briefs are authority-bearing context expressly recognized by Direction1/DEC-012; bare code is evidence; record absence is not event absence; tests are not engineering validation (profile §4). Praxeology: use stable claim keys, one current authority pointer and named evidence; avoid copied revision/status/test snapshots (Rev2 §3.1; R18 owner adoption). Axiology: preserve transparent engineering objects, explicit missing information, private-data controls, truthful attribution and human professional responsibility (DIRECTIVE §§2–5; CONTRACT DATA-2/UNIT-1/AUTH-1).

Refutation attempted: a permissive catch-up could erase new-scope or invariant breaches, treat previews as production, transform a draft header into de-adoption, or manufacture historical approval. The recommendations therefore retain explicit product gaps, issued/lifecycle paths, engineering and IP evidence holds, and truthful dates. Alternative maximal rewrite-to-code was rejected because it would codify contingent mechanisms and erase tested interface obligations. Alternative send-every-packet-back-to-owner was rejected because it ignores DEC-012's sealed-brief route, existing specific decisions and DEC-087 reasoned discretion.
