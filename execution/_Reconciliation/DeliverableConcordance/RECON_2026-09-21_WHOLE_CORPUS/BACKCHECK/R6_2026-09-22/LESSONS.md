# Calibration and implementation-planning lessons

This is the R6 handoff of the owner's two feedback perspectives, checked against
this run. It is an agent synthesis, not a reusable workflow or a new governed
criterion. The owner requested preservation of these lessons at R6; workflow
authoring remains a separate undertaking.

## Reconciliation practice

- Resolve claim granularity before packet choices. Most stale revision pins,
  current declarations and test-count snapshots are evidence metadata. Their
  removal is often justified without another product decision. Inspect every
  physical block: A9's 213 source units were not 213 deletable paragraphs, and
  one declaration contained DEC-077/DEC-092 requirements that had to survive.
- Ask about off-code events at activation: manual reviews, signing,
  notarization, release and field observations. No located artifact means
  unknown evidence, not proof that an event never occurred. Record both the
  observation and its result artifact, with actual candidate identity.
- Read the primary permission before imposing a new gate. A3's CP-10 packet
  omitted DEC-012's sealed-brief route; D-72's final supplement had already
  settled an item that discovery still called unruled. Earlier human intent
  must neither disappear behind a register convention nor be broadened by
  incidental code.
- Name recurring questions early and record one run-wide reading. F7 subject,
  unit-safety tier, CONTEXT obligations and parity claims should be calibrated
  across representative packages before scaling. Preserve worker variance and
  independently backcheck high-error or materially changed subjects.
- Route the reverse pass to every proposed owner before assigning scope. A
  proposed owner never asked to assess a capability is not an owner that
  declined it. The original 44 routing-gap capabilities and their limitations
  remain accountable; this record-only tranche does not invent new ownership.
- Hash minted subclaim bodies when they are created. Historical `.sNN` keys
  without original body spans require explicit parent-envelope binding here;
  no reconstruction is presented as original independent evidence.
- Sequence decision IDs before dependent handoffs, or reserve ID ranges.
  Bind each source claim once and count physical edits, source units,
  capabilities and handoff items separately. Every coverage checker must reject
  missing and duplicate populations; this R6 runs both negative controls.
- Preserve resumability: immutable prior artifacts, explicit source hashes,
  native launch/return attribution, scoped write ownership and current handoff
  pointers. Written briefs and actually executing children remain distinct.
- Scope instructions do not enforce host containment. Record actual native
  mechanism and prompt-level restrictions; independently inspect the final
  changed path set and exclude ignored/build state from evidence.

## Implementation planning

- Write claims at §3.1's decision/interface/named-verification level. Keep
  mechanisms, exact versions, transient counts and build details in bound
  evidence. Schema-required revision pins are deliberate exceptions until the
  representation contract changes through its own path.
- Keep deliverables in production planning. A substitute work graph or done
  declaration must have an explicit accepted relationship to claims; it must
  not become an unregistered competing authority. Piping C9's owner-steered
  graph remains current; Remaining is reconciled as a record, not revived as
  the sole work selector.
- Every capability needs a keyed owner or an explicit evidence relation
  before merge. A PR should name which claim it serves and which existing hold
  or decision it settles. This is a future planning recommendation, not a PR
  template amendment in this tranche.
- Apply rulings to their carriers when made; otherwise list each unapplied
  carrier and its residual. A settled decision missing a carrier is repair
  work, not a reason to ask the owner to decide again.
- Use one registered decomposition source basis and preserve each evidence
  artifact's evaluated revision. Do not mechanically refresh approval hashes
  when prose changes.
- Bind verification to stable claim keys **and** evaluated bytes/revision,
  scope and validity conditions. Wording-only repair need not invalidate an
  unrelated test result, but claim keys alone cannot authorize future bytes or
  replace SHA-bound human acceptance.
- Retire or label superseded code when the chosen path changes. Reference,
  contract, compatibility and product-runtime code have different epistemic
  roles; retained Python evidence is neither a production waiver nor a reason
  to port every isolated helper.
- Move scope and deliverables when responsibility moves, and size slices to
  what can be completed. Partial implementations, ownership gaps and release
  gates remain visible instead of being hidden by a blanket done label.
- Reconcile at milestone boundaries and identify touched claims in ordinary
  changes. A small current check is cheaper than reconstructing months of
  interleaved direction, code and stale snapshots.
